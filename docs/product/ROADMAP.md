# 交付路线图

路线图按受控迭代组织。一轮可以跨越多个工作会话，但只有在实现、验证、档案更新和提交全部完成后才结束。

进度快照（2026-08-12）：第 0–205 轮已完成。第 203 轮把产品方向重构为 **iLens：AI 驱动的长期个人健身数据库与行动闭环**；第 204 轮发布 `ilens-muscle-model-v1`，第 205 轮让 9 个 starter 和 owner 自定义动作以严格 mapped/unmapped 关系消费该词表，并把自定义 revision、owner 边界、便携导出和训练选择时快照连成首个历史闭环。当前仍没有肌群聚合、状态、人体图、关系编辑 UI 或专家内容审阅。下一轮只实现 Body Metric Registry v2。

## iLens 迁移原则

1. `dataModel.md` 是目标模型，`funcTable.md` 是当前到目标的迁移矩阵，`IMPLEMENTED_PRD.md` 仍是实际上线能力的唯一产品清单。
2. 不做整仓重写。每轮只交付一个可独立测试、可回滚、可归档的纵向切片，并保持当前训练、营养和隐私流程可用。
3. 先统一事实语言，再做首页人体图、训练分析和 AI 编排；界面不得提前制造后端不存在的“肌群状态”“体测报告”或“PR”。
4. Evidence 采用共享信封和领域内精确外键，不先创建容纳任意 JSON 的万能证据表。AI 输出先是候选或计划草案，必须通过确定性 Schema 与安全校验。
5. 新增领域必须同步覆盖 owner、来源、发生/记录时间、revision、Unknown/完整度、确认、导出、纠正与删除。
6. iLens 作为产品方向和界面名称逐步迁移；仓库名、包名和部署标识暂不批量重命名，避免把品牌修改混入数据迁移。

## 目标领域与当前迁移类型

| 领域                        | 当前判断              | 本阶段策略                                                      |
| --------------------------- | --------------------- | --------------------------------------------------------------- |
| Profile / Goal              | 已有可靠基础          | 扩展字段、来源和多目标生命周期，不替换现有引导历史              |
| Body Metrics                | 九个指标可用          | 建立版本化指标注册表，再扩展身体组成和节段指标                  |
| Body Assessment             | 不存在                | 新建检测事件、私有报告、提取候选、本人确认和指标关联            |
| Body State                  | 全身恢复可用          | 保留当前确定性估计，后续增加统一状态快照                        |
| Muscle Model / Muscle State | 词表与动作关联已完成  | 保持历史版本；以后独立设计聚合权重、本人状态与人体图            |
| Training                    | 事实层成熟            | 直接复用；重组执行体验并补 planned/ad-hoc 语义                  |
| Performance                 | 只有动作统计          | 新建可复算的最佳组、e1RM 和 PR 投影，固定算法版本               |
| Nutrition                   | 事实层成熟            | 直接复用；后续接入计划目标和完整度                              |
| Plan                        | 只有单周聚合          | 新建 Plan v2 长期生命周期，旧周计划保持兼容读取                 |
| Evidence                    | 领域内较强、跨域不齐  | 每个新域同步对齐，不单独发明中心化事实库                        |
| Personal Model              | 内核与三个 claim 可用 | 保留并暂停横向扩张，待 Body/Performance/Plan 证据成熟后逐项接入 |

完整代码证据、页面映射和首个验收见仓库根目录 `funcTable.md`。

## 依赖主链

```text
Muscle Model → Exercise-Muscle → Muscle State / Training Analysis / Human SVG
Body Metric Registry → Body Assessment + Evidence → Body Profile / AI Report Import
Training Facts → Performance → Training Analysis → Plan v2
Profile + Goal + Body State + Performance + Nutrition → Plan v2
Confirmed facts + exact revisions → Personal Model → AI closed loop
```
