# 产品简报

## 产品主张

iLens 是一个 AI 驱动的长期个人健身数据库与行动闭环，当前垂直聚焦健身房力量训练。它把资料、身体指标与体测、身体/肌群状态、训练、力量表现、饮食、计划、证据和长期认识放在同一条可追溯时间线上，让用户从“记录了什么”继续走到“今天做什么、结果如何、下一步怎样调整”。

现有 MyFitness / 衡迹代码库是 iLens 的迁移起点，不做整仓重写。系统只把本人确认事实、设备/机构事实和可复算派生值按明确来源组织起来；AI 负责提取候选、解释和计划草案，不替用户定义自己，不把短期波动固化为标签，也不让生成文本成为事实来源。

## 初始受众

正在健身房进行或准备开始系统力量训练的成年人。他们希望增肌、减脂、提升力量或建立稳定习惯，需要一种比电子表格更快捷、比聊天回复更可追责，并能长期保留身体与表现变化的数据工具。

MVP 明确排除未成年人，以及针对妊娠、进食障碍、糖尿病、肾脏疾病、心脏疾病或其他需要个体化医疗照护情形的治疗性计划。

## 核心用户任务

1. 无需解读多个仪表板，就能看清今天最重要的事情。
2. 对常见重复操作，能在 30 秒内记录一次训练、餐食、身体指标或恢复信号。
3. 理解每周变化，而不过度回应单次测量。
4. 获得一份尊重可用时间、器械、经验、偏好、疲劳和疼痛信号的现实计划。
5. 能够纠正 AI 错误，并始终掌控每一项已存储事实。
6. 无需联系支持人员即可导出或删除个人数据。
7. 理解系统为什么形成某项关于自己的认识，并能确认、标记为暂时情况、不同意或表示不确定。
8. 从体测报告中提取候选数据，逐项确认后进入自己的长期身体档案。
9. 查看动作最佳表现、e1RM 与 PR 的依据，并明确区分估算值和实测事实。

## 信息架构

| 区域       | 用户问题                             | 目标内容                                     |
| ---------- | ------------------------------------ | -------------------------------------------- |
| 首页       | 今天最重要的行动和待确认事项是什么？ | 今日训练、饮食、恢复、身体人体图和待确认候选 |
| 训练       | 怎样完成、复盘并规划力量训练？       | 训练执行、计划中心、训练分析、动作表现与 PR  |
| 身体档案   | 我的身体组成和状态如何变化？         | 身体指标、体测事件、趋势、私有照片与报告导入 |
| 饮食       | 吃了什么，与目标相差多少？           | 餐食事实、营养汇总、目录、照片候选和计划目标 |
| iLens 认识 | 系统目前如何理解我，依据是什么？     | 有证据支持的个人模型、每周回顾、校准与修订   |
| 我的       | 我能控制哪些资料、权限和数据？       | 个人资料、目标、单位、同意、导出与删除       |

这是目标信息架构，不代表全部已实现；当前页面和能力清单以《已实现产品需求文档》为准。

## MVP 功能范围

### 基础与个人资料

- 支持微信/手机号的身份边界；后端集成前使用本地演示身份。
- 身高、体重、年龄段、目标、经验、可训练天数、单次时长、器械、饮食偏好、单位制和时区。
- 对健康风险回答提供明确警告和安全退出路径。

### 记录

- 身体：体重、腰围、可选的设备报告体脂估算、静息心率。
- 训练：动作、组数、次数、负重、时长、距离、RPE、完成情况、疼痛与疲劳反馈。
- 营养：食物、份量、能量和宏量营养素；收藏与最近项目。
- 恢复：睡眠时长/质量、酸痛、精力、压力和可选备注。
- 每条记录包含来源、单位、发生时间、时区、估算数据的置信信息及修订历史。
- 第一阶段建立统一肌群词表及动作的主/次肌群关系，并从已完成力量训练确定性派生最佳组、e1RM 与 PR；e1RM 始终显示为估算。
- 体测报告导入只提出候选指标，本人逐项确认后才写入身体记录；原始报告按私有媒体和明确保留规则处置。

### 洞察与规划

- 在适当场景使用移动平均线展示七日、三十日和九十日趋势。
- 先从计算指标生成每周摘要，再生成叙述文本。
- 提供包含理由、替代方案、版本和用户修改的结构化周计划。
- AI 响应必须有清晰标记，且绝不作为医疗建议处理。

### 个人认知镜子

- 用稳定类型区分本人确认的目标、约束和偏好，与系统从记录中观察到的基线、行为、状态和模式；假设始终明确标注为待验证。
- 每项认知都能回到精确证据、观察窗口、当前修订、支持与反对证据及已知限制。
- 每周只呈现少量高价值认知卡片，允许用户确认、标记为暂时情况、不同意或表示不确定。
- 用户反馈与新证据形成不可变修订，不静默改写原始记录、既有历史或用户确认事实。
- 在 Body、Performance 与 Plan v2 的事实基础稳定后，再把新证据逐项接入 Weekly Review → User Feedback → Model Revision；Contextual Decision、Outcome 和更广泛 AI 推理继续后置。

### 图像辅助

- 食物识别提出候选项、份量范围、不确定性和可能缺失的配料；最终记录由用户确认。
- 进度照片只用于姿势对齐和视觉比较，不诊断姿势障碍，也不推断精确体脂率。
- 移除 EXIF；仅供分析的图像默认删除；保留进度照片需要单独同意。

## 首个版本明确排除项

- 社交动态、排行榜、直播课程、市场、教练匹配、保险用途、医疗记录、疾病诊断、治疗声明、未成年人，以及与所有可穿戴设备生态自动集成。

## 成功模型

北极星指标：每位周活跃用户完成的可追溯认知闭环数，即查看一项有证据的个人认识后完成校准、行动或结果反馈。

辅助指标：

- 从新手引导到首条记录的完成率。
- 每周至少有一条有意义记录的天数。
- 周计划的接受、修改、跳过和完成率。
- 个人模型条目的证据查看率、用户校准率、争议率和修订后复核率。
- 每周认知回顾从展示到反馈或行动的完成率。
- 七日与三十日留存率。
- 按功能和用户群体划分的 AI 纠正率与拒绝率。
- 安全规则触发、误报和未处理事件。
- 图像分析延迟，以及每条已确认营养记录的成本。

数字目标将在原型测试和首批 100 名用户基线形成后设定，不会在缺少证据时臆造基准。

## 商业模式假设

- 免费版：手工记录、核心趋势和基础每周回顾。
- 专业订阅：自适应计划、更丰富的 AI 解释、照片辅助、长期对比和高级导出。
- 不使用健康数据投放定向广告，也不出售用户健康数据。

该假设不属于首个工程里程碑；留存与信任才是第一道门禁。
