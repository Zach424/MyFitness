# 衡迹已实现产品需求文档

状态：内部 Alpha 现状基线

基线日期：2026-08-10

适用客户端：微信小程序与响应式 H5；管理端为独立支持工具

## 1. 文档目的

本文只描述仓库在基线日期已经实现且有代码、契约、迁移或测试证据的产品行为，不把路线图、待办或设计设想写成现有能力。页面文案与交互以 `apps/client`、`apps/admin` 为准，服务端边界以 `packages/contracts`、`apps/api` 和数据库迁移为准；接口与表结构的逐项细节分别见《接口参考文档》和《数据库设计文档》。

当前产品定位是“隐私优先的健身记录与计划工具”，帮助成年用户把身体与恢复、训练、餐食和计划放到一条可追溯证据链中。系统提供趋势整理和安全约束下的计划，但不提供疾病诊断、治疗方案、精确体脂推断或自动生效的 AI 处方。

### 2.1 当前明确不包含

- 未成年人使用路径。
- 医疗诊断、治疗性饮食、疾病管理或孕产期个性化处方。
- 社交动态、排行榜、教练撮合、直播课程、商城与广告画像。
- 原生 Apple Health、Health Connect 或穿戴设备自动同步。
- 照片人体测量、姿态诊断、精确体脂率或“好坏体态”判断。
- AI 自动修改计划、自动确认事实、自动写入餐食或自动提高训练量。
- 用户端离线写入队列；网络结果不确定时不会在后台自动重放请求。

## 3. 用户、权限与信任边界

### 3.1 普通用户

目标用户是已满 18 周岁的健身初学者或重新开始规律训练的人。用户拥有自己账户下的资料、健康记录、训练、餐食、计划、AI 输出和照片；所有普通业务接口按当前会话用户强制隔离。

### 3.2 管理员

管理员与普通用户使用不同身份表和会话。支持人员只能按精确账户标识、工单和原因进行查询，返回聚合证据而不是健康内容；审计读取和支持查询分别受最小角色控制。管理端不能代用户修改记录、查看照片内容或生成计划。

### 3.3 系统与 AI

- 确定性服务负责单位换算、汇总、计划结构、安全门禁和结果校验。
- AI 只能处理明确授权的最小上下文，并且输出必须标记来源、模型、提示版本和验证器版本。
- AI 估计与用户确认事实必须在界面、响应和数据库中保持可区分。
- 用户撤回 AI 或照片授权后，新的相关处理停止；已保留内容按对应授权与保留策略处置。

## 5. 全局交互规则

### 5.1 权威读取状态

所有包含敏感写入的主要页面遵循同一读取模型：

| 状态               | 页面行为                                   | 写入权限                             |
| ------------------ | ------------------------------------------ | ------------------------------------ |
| 首次加载           | 显示读取中，不预设“没有数据”               | 全部关闭                             |
| 首次失败           | 显示网络、服务拒绝、服务暂不可用或未知错误 | 全部关闭；提供手动重试               |
| 已就绪             | 展示服务端确认的当前清单或明确空状态       | 按业务规则开放                       |
| 刷新中且有旧快照   | 旧内容只读保留并标记正在复核               | 保存、修改、历史、删除和模型调用冻结 |
| 刷新失败且有旧快照 | 保留旧快照并明确其已过期                   | 继续冻结，直到手动重试成功           |

因此，“空状态”只能来自成功响应，不能由超时、断网或 5xx 推断。

### 5.2 分页与快照

- 当前列表使用稳定游标分页，默认只加载首批，再由“加载更多”获取后续页。
- 刷新会从第一页重新建立权威快照，不把旧页与新页盲目拼接。
- 后续页失败时已加载页仍可阅读，但不会把失败解释成列表结束。
- 版本历史独立分页；历史读取失败不覆盖当前实体，也不显示伪空历史。

### 5.3 新建请求与幂等恢复

- 新建身体记录、训练、餐次、自定义动作、自定义食物、照片预约、计划生成和 AI 解释使用幂等键。
- 对明确可安全重试的新建操作，网络中断或 408、425、429、500、502、503、504 会保留输入和原幂等键。
- 若服务端明确返回字段错误、权限错误或业务拒绝，该次请求终止；用户修正后产生新的明确提交。
- 对修改、归档、上传、确认、删除、计划决定、关联和 AI 调用，响应丢失后不会直接重放，而是先通过精确读取或原请求查询接口核对权威结果。

### 5.4 乐观并发与版本冲突

- 可更正实体带正整数 `revision`；修改提交携带 `expectedRevision`，删除携带 `x-expected-revision`。
- 409 表示基线已变化或幂等键被不同内容复用。客户端保留用户输入，读取当前实体并逐项比较。
- 若当前服务端内容与原提交完全一致，页面可以确认上次操作已成功；若仅版本没变，则说明没有成功证据；若内容不同，则更新比较基线并要求用户再次确认。
- 系统不会悄悄覆盖其他设备或页面产生的新版本。

### 5.5 本地草稿

- 身体记录、训练和餐次草稿按当前账户和 Schema 隔离，默认保留 24 小时，单份上限 96 KiB。
- 页面提示用户“恢复”或“放弃”，不会自动把旧草稿当作当前事实。
- 更正草稿记录目标实体和基础版本；恢复前必须精确读取目标，若目标已删除或版本过期则安全放弃更正意图。
- 保存、明确取消、退出登录或账户删除会清理对应草稿。

### 5.6 时间与时区

- 记录同时保存带偏移的发生时间和 IANA 时区，展示可还原本地自然日。
- 输入必须是有效日期时间；拒绝未来时间。
- 夏令时跳空时刻会被拒绝；重复时刻需要用户选择明确偏移，不由客户端猜测。
- Dashboard、历史日历和洞察以请求时区计算自然日，7/30/90 日窗口身份固定且有序。

### 5.7 破坏性操作

- 删除记录、训练、餐次、目录定义和照片都需要显式确认对话框。
- 对话框默认把键盘焦点放在取消或安全操作，支持 Escape；失败后焦点回到安全按钮。
- 记录类删除是从当前列表软删除，修订历史保留；私有照片删除进入持久化对象删除任务，列表消失本身不等于物理字节已经清除。

### 5.8 无障碍与响应式

- 关键按钮有可读 `aria-label`，选择器使用 `aria-pressed`、`aria-selected` 或 `aria-checked`。
- 状态消息使用 `role=status`，错误与安全警告使用 `role=alert`，弹层使用 `role=dialog` 与 `aria-modal`。
- 按钮支持键盘 Enter/Space；焦点在弹层打开、失败和关闭后有可预测去向。
- 页面覆盖 320×844 移动视口、放大文本与减少动态效果。当前证据主要来自 Chromium H5 自动化，不等于真实读屏器和真机验收已完成。

## 6. 身份与登录

### 6.1 H5 OIDC 登录

1. 页面进入时先检查本地会话；已有有效会话则进入今天页。
2. 点击登录后读取公开 OIDC 配置，使用 Web Crypto 生成 `state`、`nonce` 和 PKCE 验证材料，并把短期交易状态放入 `sessionStorage`。
3. 浏览器跳转到身份提供方。回调页先校验 `state`、授权码和本地交易，再清除 URL 中的回调参数，防止刷新重复交换。
4. 服务端验证授权码、PKCE、nonce、签发方和预配置身份，返回衡迹自己的不透明会话令牌。
5. 新用户进入建档，既有用户进入今天页。

边界与异常：

- 浏览器不支持必要加密能力时禁止发起登录。
- 用户取消、提供方返回错误、交易状态缺失、state 不一致、授权码已消费、配置不可用和网络失败分别显示明确错误。
- 回调交换不会自动重放；用户必须重新开始一笔新的授权交易。
- 会话令牌不进入 URL；服务端仅保存令牌哈希。

### 6.2 微信与开发身份

- 微信小程序把一次性登录码交给服务端，服务端换取稳定身份并返回会话及 `isNewUser`。
- 本地开发入口接受受限格式的演示 subject；生产环境应返回不可用。
- 当前产品简报中的手机号身份尚未形成用户端完整交互，不应宣称已交付。

## 7. 新手建档与个人资料

### 7.1 三步流程

第一步“资料”：显示名称、年龄段、用于计算的生理性别、身高、单位制、时区和已成年确认。

第二步“目标与节奏”：选择减脂、增肌、体能或习惯目标；选择经验、每周可训练日、单次时长、器械和饮食偏好。

第三步“安全与同意”：选择风险标记，确认条款、隐私和健康数据处理授权。

交互细节：

- 进入页先读取现有资料；在成功读到资料或明确 404 未建档前，不显示可保存的权威底稿。
- 已建档时表单基于当前 `revision`；未建档时显示起始草稿，并明确其尚不是已确认事实。
- 顶部显示 3 步进度，可返回上一步；每一步通过字段校验后才可继续。
- 保存中禁用重复提交；成功后显示新版本和资格状态。
- 若资料被其他位置更新，页面冻结保存并提供“载入当前底稿”操作；该操作会明确放弃未提交差异。

### 7.2 字段与边界

- 成年确认必须为真；年龄段为 18–24、25–34、35–44、45–54、55–64 或 65+。
- 可训练日为 1–7 天，单次时长 15–180 分钟；时区必须是有效 IANA 名称。
- 风险包括急性伤病/术后、胸部不适、晕厥、孕产期等安全信号。
- 任一高风险标记不会生成诊断，但会把个性化计划资格设为阻断，提示先获得医生或合格专业人员许可。
- 资料修改产生新 revision，计划会检查资料版本与当前安全资格。

### 7.3 异常恢复

- 保存响应不确定时保留表单和原提交摘要，先重新读取资料。
- 若读取到内容完全一致则确认成功；若仍是旧版本则允许用户重新明确提交；若出现其他新版本则要求重新载入。
- 409 不自动重试 PUT。

## 8. 今天 Dashboard

### 8.1 页面组成

- 顶部显示当前本地日期与问候。
- “准备度”展示 `unknown` 或经过确定性规则计算的分数、置信度、一致性和标签；只有确认来源参与。
- “今天证据”按发生时间列出身体/恢复、训练和餐次的已确认事实。
- “近期形状”固定提供 7、30、90 天窗口，展示活跃日、记录数、训练数、餐次数等。
- “本周计划”展示计划状态、版本和下一动作。
- 快速入口分别进入身体与恢复、训练和餐食记录。

### 8.2 读取与刷新

- 每次显示页面时原子读取 Dashboard 与计划列表；两者未同时成功前不拼出半新半旧状态。
- 首次失败不显示零准备度、零活动或“尚无计划”。
- 有旧快照时刷新失败继续显示旧数据并标记为过期，提供手动重试。
- 卡片跳转只携带必要实体键或指标，不把健康内容放进 URL。

### 8.3 边界

- 缺少恢复证据显示 Unknown，而不是 0 分或低状态。
- 今天证据不能晚于响应 `generatedAt`。
- `today.date` 必须与 `generatedAt` 在请求时区的本地日期一致。
- 趋势不作医学解释，也不根据单次测量自动调整计划。

## 9. 历史日历

- 固定显示截至参考日的连续 28 个本地自然日。
- 每天只标记当前健康记录、训练和餐次数量；删除后标记会重新计算。
- 选择日期后显示该日是否有记录。成功读取后的空白明确表示“没有保存记录”，不表示没有活动或摄入。
- 从某日进入补录时只传递日期与时区，用户仍需选择精确发生时间。
- 刷新失败时保留旧 28 天快照，但冻结日期切换和补录入口，避免在过期范围上写入。

异常：连续日期、起止日期或计数一致性不满足共享契约时，客户端拒绝把响应当作权威日历。

## 10. 身体与恢复记录

### 10.1 支持指标

| 分组 | 指标                                 | 允许单位或评分             |
| ---- | ------------------------------------ | -------------------------- |
| 身体 | 体重、腰围、体脂估算、静息心率       | kg/lb、cm/in、percent、bpm |
| 恢复 | 睡眠时长、睡眠质量、酸痛、精力、压力 | minute/hour 或 1–5 分      |

### 10.2 新建

1. 在“身体指标/恢复感受”标签切换分组。
2. 选择指标；评分型指标点选 1–5，数值型输入数字并选择允许单位。
3. 输入本地发生日期、时间和时区，系统解析为带偏移时间。
4. 来源默认为手动，状态为已确认；可带置信度的 AI 估计必须仍然标记为候选或估计来源。
5. 点击“保存记录”，成功后清空草稿并刷新清单。

校验与边界：数值必须有限、指标和单位组合合法、时间有效且不在未来。服务端同时保存展示值/单位和标准值/单位，避免后续单位制改变改写历史输入。

### 10.3 更正、历史与删除

- 点击“修改”把当前快照复制到编辑器，并显示基线 Rn；保存会创建 Rn+1，原版进入修订历史。
- “历史”弹层按时间倒序展示 created/updated/deleted 行为及当时快照，可继续分页。
- “删除”要求确认并携带当前 revision。成功后从日常清单移除，修订记录保留。
- 修改或删除结果不确定时先精确 GET；404 可作为已不在当前清单的证据，但不等于历史被抹除。

### 10.4 长期观察

- 从指标卡进入单指标观察页，可切换指标和 7/30/90 天范围。
- 展示确认记录数、记录日数、最小值、最大值、平均值和最多 180 个明细点。
- 统计使用标准单位；明细仍显示原展示单位、来源和版本。
- 无记录时统计值保持 `null`，不显示 0；页面不判断“达标”“改善”或疾病风险。

## 11. 训练记录与动作目录

### 11.1 训练编辑器

1. 输入训练标题、开始/结束时间和时区。
2. 搜索内置或“我的动作”目录并加入训练；动作定义在加入时复制为快照。
3. 每个动作按记录方式显示字段：次数+负重、时长，或时长+距离。
4. 每组可选热身/正式/放松，填写次数、负重、时长、距离、RPE，并明确勾选是否完成。
5. 填写疲劳 1–5、疼痛 0–10 和备注。
6. 页面预览完成组、总组、训练量、距离和活动时长；点击保存。

边界：1–30 个动作，每动作 1–50 组；位置唯一；负重、距离和时长需满足契约范围；结束时间不得早于开始时间。训练状态由完成事实派生：全部组勾选为 completed，否则 partial，客户端输入的旧 `status` 不作为权威。

疼痛较高时显示安全警告；该警告不构成诊断，也不会生成继续训练建议。

### 11.2 列表、复用与更正

- 列表显示标题、时间、全部完成/部分完成、汇总和动作。
- “复制”只复制结构到新草稿，并取消完成事实；用户必须按本次实际情况重新勾选。
- 修改产生新 revision，删除软删除，历史保存完整嵌套快照。
- 读取快照过期时保存、复制、修改、历史、删除和动作目录写入全部冻结。

### 11.3 自定义动作目录

- 字段：名称、最多 8 个别名、力量/心肺/灵活性分类、记录方式、1–6 种器械、器械说明。
- 名称在当前用户活动目录中规范化唯一；键只允许小写字母、数字和下划线。
- 新建使用幂等键；纠正使用 expectedRevision；“停用”把定义移出未来选择。
- 纠正或停用不改写训练草稿和历史训练中已复制的动作快照。
- 每条定义有独立修订历史；结果不确定时先读取当前定义，不自动重复归档或 PUT。

### 11.4 单动作观察

- 按稳定 `exerciseKey` 区分动作，不因显示名称相同而合并。
- 可切换动作、指标和 7/30/90 天窗口，显示训练次数、完成组、次数、标准公斤训练量、活动分钟和距离。
- 只统计已完成组；最多暴露 180 个训练点并返回 `hasMore`。
- 页面只呈现历史趋势，不评价动作质量，也不自动建议加量。

## 12. 餐食记录、食物目录与收藏

### 12.1 餐食编辑器

1. 选择早餐、午餐、晚餐或加餐，填写餐次标题和发生时间。
2. 在“内置/我的/收藏”等来源中搜索食物并加入。
3. 每个食物在加入时复制名称、分类、每 100g 营养和参考来源。
4. 输入实际份量；系统换算成克并预览能量、蛋白质、碳水、脂肪和有证据时的纤维总量。
5. 可添加备注，确认后保存餐次。

边界：一餐 1–30 项，位置唯一；份量必须为正且单位属于 g、ml、piece、serving；营养参考必须在契约范围。缺少纤维参考时总纤维保持未知，不把未知当 0。

### 12.2 收藏、复制、更正与删除

- 收藏保存的是食物完整快照和默认份量；取消收藏按食物键删除。
- 收藏 PUT/DELETE 响应不确定时重新读取收藏清单，确认完整快照是否存在，不按按钮本地状态猜测。
- “复制餐次”复制食物和份量到新草稿，用户必须按实际食用内容调整。
- 更正、历史、删除与训练记录采用同一 revision、精确读取和软删除规则。

### 12.3 自建食物目录

- 字段：名称、别名、分类、每 100g 能量/蛋白质/碳水/脂肪/可选纤维、参考文字、默认份量。
- 营养值由用户确认，仅是参考数据，不代表实验室检测，也不会自动生成摄入建议。
- 纠正只影响未来选择；已保存餐食和收藏继续保留选择时快照。
- 归档移出未来目录，历史餐食、收藏和定义修订记录不变。
- 餐食照片候选只匹配受控演示目录，不自动信任用户自建条目。

### 12.4 每日营养观察

- 固定返回连续 90 个本地自然日，并可查看 7/30/90 天窗口。
- 可切换能量、蛋白质、碳水、脂肪和纤维；显示有记录日、无记录日、餐次数、项目数和“仅已记录日均值”。
- 空白日表示没有保存餐次，不表示零摄入。
- 窗口汇总必须由已接受的 90 日序列逐字段重算；页面不设目标、不判定达标、不评价食物好坏。

## 13. 餐食照片校样台

### 13.1 独立工作流

1. 从餐食编辑器进入校样台；当前餐食草稿内容不会发送到照片页。
2. 用户阅读 24 小时保留和删除规则，明确勾选单次分析授权。
3. 点击选择照片，客户端先预约临时候选，再上传 JPEG、PNG 或静态 WebP。
4. 服务端重编码、剥离 EXIF、校验尺寸和字节数，并调用配置的候选生成器。
5. 成功时显示私有签名预览、候选名称、置信说明和克重输入；用户逐项选择，最多确认 5 项，每项 5–2000g 整数。
6. 点击确认后服务端关闭候选并启动照片删除；页面只把受控目录键与确认克重通过内存事件带回尚未保存的餐食草稿。
7. 用户仍需在餐食页核对营养参考并点击“保存餐次”。

### 13.2 状态与边界

- 候选状态区分预约、处理中、可审阅、失败、已确认、过期/删除中；不可审阅状态禁止重复上传原媒体。
- 没有可用候选时显示“返回手动记录”，不会生成猜测餐食。
- 候选可能漏掉调料或画外食物，页面明确要求手动补充。
- 照片、候选和确认项不进入 URL，也不进入通用餐食草稿持久化。
- 预览必须使用短期签名令牌；对象存储键不返回普通客户端。

### 13.3 异常恢复

- 预约失败可在同一幂等语义下核对；上传、确认和删除响应丢失时先读取私有候选清单。
- 若已出现可审阅结果，页面不重复上传；若仍未确认，不把候选带回餐食；若候选已消失，只能说明它不再可审阅，不能单凭 404 声称对象字节已物理删除。

## 14. 进度照片

### 14.1 拍摄与保留

1. 选择正面、侧面或背面，页面显示对应参考框。
2. 选择“24 小时内自动删除”或“保留用于长期对比”。
3. 明确勾选本次净化与拍摄条件机器检查授权；长期保留还必须单独勾选保留授权。
4. 预约后选择或拍摄图片并上传；前后端共同剥离 EXIF，服务端保存净化版本。
5. 返回画幅/方向、分辨率、亮度和对比度检查，整体状态为“可对位”或“建议调整”。

### 14.2 浏览与对比

- 私有清单显示视角、拍摄时间、保留模式、机器检查和删除状态。
- 同一视角至少两张长期保留照片时可使用透明度滑块叠片对比。
- 机器结果始终标记为拍摄条件估计；不识别身体部位、不判断姿态、不推断体脂。
- 撤回“分析”授权会清除机器检查结果，但明确长期保留的净化照片仍归用户所有；撤回“保留”授权会删除相应照片。

### 14.3 删除与异常

- 删除对话框明确照片和检查结果均将删除且不可撤销。
- 上传或删除响应丢失时先读取私有清单；发现照片存在可确认上传成功，发现照片不存在只确认其离开当前清单，物理删除仍依赖持久任务证据。
- 未使用预约和分析型照片按过期时间进入清理；失败任务可进入重试或死信状态。

## 15. 洞察与教练视图

### 15.1 Dashboard 证据账本

响应同时包含 observedWindow、confirmedRecovery、recoveryEstimate 和可选 planExperience。各部分的 `asOf` 必须与 Dashboard `generatedAt` 对齐，来源只允许 manual/device/imported 的确认事实；AI 输出不能冒充恢复事实。

### 15.2 教练页

- 教练页复用同一次 Dashboard + 计划原子快照，不在卡片间发起独立、可能漂移的二次读取。
- 卡片解释近期记录、恢复和计划状态，并提供跳转到计划、记录、历史或采用后回看的入口。
- 页面不生成新的健康结论；没有证据时显示 Unknown。
- 只有存在计划时才提供 AI 解释档案入口。

### 15.3 动作与健康纵向点

- 动作与健康来源窗口行只允许唯一的 7、30、90 日身份；输入可乱序，缺失身份继续明确回退为空窗口，重复或未知身份失败关闭而不静默选择或丢弃。
- 动作与健康洞察最多返回最新 180 个点，`hasMore` 表示查询还取得了第 181 个合格点。
- 生产查询和纯构造边界都把合格输入限制为最多 181 点；超过上界不静默截断。`hasMore: true` 只有在公开前缀恰好 180 点时合法，`false + 180 点` 不会被误写成“已证明完整”。
- 点按 `occurredAt` 非递增；相同时刻允许，因为公开响应不含创建时刻，不能向用户声称完整数据库次序。
- 参考时刻和全部原始点时刻必须有效且有限；无效值在排序与未来过滤前失败，不能静默变成“没有记录”。
- 动作点的 `workoutId`、健康点的 `recordId` 在各自序列中唯一；重复身份视为证据错误，不静默去重或重复绘制。
- 动作顶层身份必须逐字段等于最新公开点；健康顶层规范单位必须等于首点，且全部合格健康点使用同一规范单位。空序列时对应摘要为 `null`。
- 健康单位一致性在排除未来点后、截断前验证，未发生证据不改变当前摘要，隐藏第 181 个合格点仍不能混入不同量纲。
- `localDate` 使用当前响应时区派生；健康记录自身的 `recordTimezone` 只保留来源上下文，不替代响应时区。
- 点序列只展示已确认事实和来源凭据，不把时间顺序解释成改善、异常、技术质量或医疗结论。

## 16. 周计划

### 16.1 生成

- 用户选择周一作为 `weekStart`，点击“生成初稿”。
- 服务端读取当前建档、可训练日、器械、经验、目标、近 7 天 Dashboard 证据和恢复投影，使用 `deterministic-v1` 生成 7 天结构。
- 每天包含可用性、可选训练；训练仅为力量、心肺或恢复，强度只有 easy/moderate，时长 10–90 分钟。
- 每个活动提供 1–6 个替代项，计划还含 3–4 个营养关注和可审计生成理由。
- 风险资格阻断时不生成；恢复证据不足时采用保守安排，而不是虚构准备度。

### 16.2 审阅、替代、采用与跳过

- 7 天折页使用 tab 语义；每一天显示有无计划训练及是否关联实际训练。
- 用户可以为活动选择替代项。存在未保存替代时主按钮显示数量；保存决定为 `modified` 并产生新 revision。
- “采用这份计划”记录 `accepted`；“本周暂不采用”记录 `skipped`。计划不会自动生效。
- 非 modified 决定不得携带替代选择；同一活动最多选择一次。
- 决定历史按 revision 展示 generated/accepted/modified/skipped 和备注。

### 16.3 新鲜度状态

| 状态                | 含义                                   | 允许操作                                 |
| ------------------- | -------------------------------------- | ---------------------------------------- |
| current             | 资料、安全资格和影响计划的证据指纹一致 | 采用、替代、AI 解释、跳过                |
| evidence_changed    | 恢复新增、过期或跨阈值使计划证据变化   | 冻结采用/替代/AI；建议重新生成；仍可跳过 |
| profile_changed     | 建档 revision 已变化                   | 冻结并建议重新生成                       |
| eligibility_blocked | 当前风险状态阻断                       | 只读；回到资料检查；仍可跳过             |
| onboarding_required | 当前没有完整建档                       | 只读；先完成资料                         |

重新生成同一周会在现有计划聚合上产生新 revision，不创建相互竞争的当前计划。

### 16.4 关联实际训练

- 计划采用且新鲜度为 current 后，用户可为某个计划日选择自己已保存的实际训练。
- 关联同时锁定计划 revision 和训练 revision，且每个计划日和每个训练最多有一个活动关联。
- 解除关联保留关闭时间和原因；计划或训练历史不会被改写。
- 旧计划版本的关联不会自动迁移到新 revision，页面明确标记版本差异。

### 16.5 结果不确定恢复

- 生成、决定、关联、解除都不会在响应丢失后直接重发。
- 页面读取当前周计划与关联：精确匹配则确认成功；已有竞争版本则载入当前权威状态；无证据则终止旧意图并要求重新确认。

## 17. 采用后回看与本人反思

- 只能读取某个已采用计划的精确 revision。
- 观察窗口从采用时刻起恰好 7 天；未结束时为 open，结束时为 closed。
- 展示当时规划证据、用户采用的替代、明确关联且未撤销的训练，以及窗口内当前存在的确认恢复记录。
- 记录已被删除或关联已解除时进入 withdrawnEvidence 计数，不继续作为当前跟进证据。
- 有任一确认跟进证据时为 Observed，否则为 Unknown；Unknown 不等于计划无效。
- 页面明确“不推断因果、评分或自动调计划”。

本人反思：

- 选项为“比预期轻松”“大致合适”“不适合我”“暂时不确定”。
- 点击即按 expectedRevision 保存，来源固定为 `user_confirmed`；可再次修改或删除。
- 本人反思与系统证据分栏显示，当前不反馈给计划算法或 AI 自动适配。

## 18. AI 计划解释

### 18.1 生成条件

- 必须有当前且新鲜的计划 revision。
- 用户逐次勾选 `ai_plan_explanation` 授权；授权版本固定记录。
- 请求只发送计划精简摘要、近况计数、恢复投影和理由，不发送姓名、用户编号或未选择动作。

### 18.2 输出与展示

- 输出含标题、概览、2–4 个依据高亮和下一步，每个高亮绑定 1–3 个允许的证据键。
- 响应记录 source、provider、model、promptVersion、validatorVersion、failureCode 和创建时间。
- 输出通过严格结构和安全验证后才展示；服务不可用、超时、拒绝、无效输出或安全失败会使用确定性 fallback，并明确标记原因。
- 固定安全说明指出它只解释既有计划，不是诊断或处方，且没有修改计划。

### 18.3 异常与档案

- 同一请求有幂等键。响应丢失后通过“原请求状态”读取 pending 或 completed，禁止补发新的模型调用。
- pending 到期后由运维协调器转为确定性 fallback。
- 档案页只读列出最多 20 条已完成运行，区分当前计划版本、同版本但资料已漂移、以及历史版本；展开不会重新调用模型。
- 撤回授权停止新的解释并清理待处理任务；历史处置按隐私策略执行。

## 19. 数据与隐私

### 19.1 数据清单

- 页面先恢复本机可能存在的销户回执，再读取账户清单。
- 展示账户创建时间、可导出总数、活动照片数、8 类数据库存及 7 类授权状态。
- 清单首次失败不显示“零数据”；旧快照失败时导出、撤权和永久删除全部冻结。

### 19.2 数据导出

- 点击“下载我的数据”即时生成 `myfitness-portable-export-v4` JSON。
- 包含账户、身份、资料、目标、授权事件、健康记录与修订、目录、训练、餐食、收藏、计划、AI 运行、照片分析和进度照元数据。
- 不包含会话令牌、令牌哈希、内部安全哈希或对象存储密钥。
- 客户端在落盘前校验精确 Schema 和 50 MiB 上限；H5 使用 Blob 下载，微信端使用临时文件能力。
- 新读取世代会使旧导出副作用失效，避免把过期响应落盘。

### 19.3 授权历史与撤回

- 必需授权 terms/privacy/health_data 随账户服务存在，不在当前页提供单独撤回。
- AI 解释、餐食照片分析、进度照分析和进度照保留可以逐项撤回。
- 撤回前显示具体影响并二次确认；成功返回撤回时间和清理数量。
- 响应丢失时重新读取授权清单。若已显示 revoked，可确认状态但不虚构本次清理数量。
- 独立授权历史页按游标展示每次同意的版本、接受和撤回时间。

### 19.4 退出登录

- 退出移除当前会话和三类未完成草稿。
- 销户状态查询回执独立保存，不会混入草稿，也不会因普通退出而被误删。

### 19.5 永久删除账户

1. 用户选择已经下载导出或明确“不导出”。
2. 勾选理解永久不可撤销。
3. 精确输入“删除我的衡迹账户”。
4. 客户端先创建 15 分钟有效的删除意图，得到一次性 intent token。
5. 随后提交 intentId、确认短语、导出选择和永久性确认；服务立即关闭账户访问、吊销会话并返回独立回执密钥。
6. 页面轮询 queued/running/completed/dead_letter，分别显示主库、媒体、身份提供方和备份恢复日志状态。

边界与异常：

- intent 过期、令牌不匹配、短语错误或清单非权威时拒绝删除。
- 删除响应丢失后可凭回执密钥恢复最小状态，不需要重新登录，也不会暴露健康内容。
- 本机可保存回执密钥；用户可明确“从本机移除”。移除后产品不能代为恢复该秘密。
- dead_letter 时账户仍保持关闭，运维可依回执恢复任务；不能把它显示为已完成。
- 完成条件要求主库、媒体、提供方策略和恢复日志均达到定义状态。

## 20. 管理支持工具

### 20.1 管理员登录

- 管理员身份必须预配置，可使用 OIDC 交换；本地开发环境有单独开发会话。
- 管理会话与用户会话完全分离；BFF 使用 HttpOnly Cookie 保存管理令牌。
- 当前角色只有 `support_reader` 和 `audit_reader`。

### 20.2 精确用户查询

- 支持人员必须输入精确账户 ID、工单号和查询原因。
- 返回账户状态、身份提供方、建档是否存在、各类证据计数、活动会话数、照片数、最近活动和可撤回授权状态。
- 不返回具体健康数值、训练内容、餐食内容、AI 文本或照片。
- 不存在账户也产生审计事件。

### 20.3 审计

- 审计事件只追加，数据库触发器拒绝 UPDATE 和 DELETE。
- 记录操作员、动作、结果、目标类型、哈希目标引用、请求 ID、受限 details 和发生时间。
- 审计页只读游标分页；无对应角色返回 403。

## 21. 运维可见能力

- `/v1/health/live` 只证明进程存活；`/v1/health` 检查数据库、对象存储等就绪依赖。
- 内部指标使用 Prometheus 文本，不携带用户标识。
- 持久数据任务接口展示聚合队列状态并执行一次有界 drain。
- AI 运维接口展示聚合运行状态并对过期 pending 解释执行一次有界协调。
- 所有内部接口需要 `x-operations-token`，不使用普通用户 Bearer。

## 22. 全局异常状态矩阵

| 场景                   | 用户可见行为                         | 系统禁止行为                    |
| ---------------------- | ------------------------------------ | ------------------------------- |
| 401 会话无效           | 提示重新登录并清理无效会话           | 不继续用旧令牌写入              |
| 403/422 资格或授权阻断 | 展示具体前置条件                     | 不绕过风险、授权或角色检查      |
| 404 当前实体不存在     | 精确读取场景可结束旧更正/删除意图    | 不把普通列表失败当 404 空数据   |
| 409 版本冲突           | 保留输入，读取当前 revision 并比较   | 不自动覆盖、不盲重试 PUT/DELETE |
| 408/425/429/5xx        | 标记结果可能未知，提供核对或安全重试 | 不对不可重放操作重复提交        |
| 响应结构不合法         | 拒绝更新当前权威快照                 | 不展示部分或错误推导数据        |
| 图片不支持或超限       | 保留页面并要求重新选择               | 不保存原始不合规媒体            |
| AI 无效或不可用        | 显示确定性降级和 failureCode         | 不展示未验证模型原文            |
| 删除任务死信           | 显示需运维处理并保留回执             | 不宣称已完成，不恢复账户访问    |

## 23. 当前质量证据与尚未关闭的发布边界

基线状态记录了 461 个单元测试、66 个集成测试和 95 个 H5 浏览器场景；构建预算、依赖审计、文档语言与迁移清单均有自动门禁。浏览器覆盖包含首次失败、旧快照刷新、并发冲突、草稿恢复、焦点与破坏性对话框等关键状态。

仍需注意：

- 当前是内部 Alpha，不应把本地通过等同于真实生产环境的身份、对象存储、备份恢复和告警演练。
- 微信真机、真实 OIDC 提供方、真实屏幕阅读器和大规模数据量仍需发布前验证。
- 原生健康平台和设备自动同步尚未实现。
- AI 生产提供方成本、延迟和安全误判率需要在真实流量下建立基线。
- 项目风险登记册中的开放风险仍优先于本 PRD 的功能完整描述；“已实现”不代表风险已关闭。
