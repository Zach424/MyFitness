# ADR-0108：历史日历只接受连续参考本地日期序列

日期：2026-08-10

状态：已接受

## 背景

跨领域历史日历公开截至请求参考时刻的 28 个本地日期，并展示当前已确认健康记录、当前未删除训练和餐食的计数。PostgreSQL 已使用 `generate_series` 精确生成参考本地日及此前 27 日，同时以参考时刻排除未来事实。

公开 `buildHistoryCalendar` 此前直接映射任意输入行，再从首尾复制 `startDate` 与 `endDate`。共享 Schema 只要求数组长度为 28、范围标签等于数组两端且日期严格升序。因此，仍为 28 行的间断、未来、重复后重排或整体偏移输入可能被测试夹具、替代适配器或未来模块抽取发布为有效日历，并把错误日期带入历史查看与回填入口。

自动排序、去重或补日会隐藏权威来源故障。空白日只有在数据库明确生成该日期且计数为零时，才能表达“该日本地范围内没有当前可见记录”；构造器不得发明空白日来掩盖缺失输入。

## 决策

- `buildHistoryCalendar` 以 `at` 在 `timezone` 中的本地日为末日，用现有 UTC 日历自然日算术生成连续 28 日预期序列。输入长度或任一 `local_date` 不精确匹配时，在映射计数和复制范围前抛出内部一致性错误。
- 合格输入继续由现有单日映射派生 `hasRecords` 和三类计数；范围标签只从已接受序列两端取得，不新增排序、去重、补行或零事实。
- `historyCalendarSchema` 独立解析 `generatedAt + timezone` 并重建同一日期序列，只报告首个日期错位的精确路径，同时要求 `startDate` 与 `endDate` 等于预期范围两端。无效响应由控制器现有 Schema 解析失败关闭。
- 保持现有 SQL、端点、查询参数、客户端、90 日回填门禁、持久化和“不评分/不判断依从性”语义不变。

## 影响

同一 28 行输入只有在参考日推进到其末日时才合法；较早参考日、错序、重复、缺日、未来末日或整体偏移都不能再伪装成有效历史范围。数据库正常响应的结构和用户界面不变。

UTC 日历算术只移动已经解析出的 `YYYY-MM-DD`，不把本地日写死成固定毫秒长度。末日本地日仍由 IANA 时区格式化得到，因此 DST 变化不会破坏自然日连续性。

本决策不证明真实浏览器或微信设备的时区数据库一致，也不提供行为评分、连续打卡、依从性或双时态历史。R-029 继续开放；真实平台验证仍是封闭测试门禁。
