# ADR-0096：私有照片采用用途分离路由与异步公共块

日期：2026-08-10

状态：已接受

## 背景

照片识餐工作台原先作为组件被进度照片页面静态导入，再由 `kind=food` 查询参数决定显示哪个用途。业务数据、同意和 API 边界虽然已经分离，但构建器仍把两套页面实现装入同一个延迟路由块。第 101 轮开始时，H5 最大异步块已达到 205,756 字节，只比 206,000 字节预算少 244 字节；WeApp 最大页面也只比 56,100 字节预算少 403 字节。

直接把照片识餐注册成独立页面可以恢复单页边界，但 Taro/webpack 会把大量相同的异步依赖复制到两个及更多页面块。第一次最小拆分使 H5 总量从 2,838,465 字节增至 3,006,449 字节，超过 2,842,000 字节预算。另一方面，应用启动只需要探测当前时区，却从完整发生时间解析模块导入该函数，使解析、DST 和格式化逻辑进入入口块。

## 决策

- 将 `pages/food-photo-workflow/index` 注册为照片识餐专用延迟页面；`pages/progress-photos/index` 只渲染进度照片流程，不再读取用途查询参数或静态导入食物照片页面。
- 饮食页只导航到专用照片识餐页面，并继续用本次导航拥有的 `EventChannel` 返回已确认目录键和整数克数。直接访问仍不能确认候选，照片、预览路径、同意和未确认内容仍不进入 URL 或持久草稿。
- H5 增加低优先级 `client-async-shared` 缓存组，只抽取至少被两个异步块使用的第三方运行时、共享组件和工具。`occurrence-field` 保留更高优先级的专用缓存组，避免通用规则覆盖已有领域边界。
- 将 `detectedTimeZone` 移入轻量独立模块，并从原发生时间模块重新导出以保持调用兼容。应用启动改为直接导入轻量模块，完整发生时间解析只随需要它的延迟页面加载。
- 自定义导航样式继续由应用级配置统一声明，删除七个重复页面级声明，并用源代码回归锁定单一权威位置。
- 不改变照片 API、数据库、对象存储、同意、保留、删除、读取权限、工作台确认语义或 WeApp 分包策略。

## 影响

食物照片与进度照片现在具有可独立测量、独立注册和独立演进的页面边界。H5 总量由拆分后的 3,006,449 字节降至 1,193,322 字节，入口为 315,096 字节，最大异步公共块为 200,006 字节；WeApp 总量为 1,094,282 字节，vendor 为 19,338 字节，最大页面为 55,672 字节。两端都通过现有预算，但 H5 入口仍超过 webpack 的通用建议警告，R-009 因此保持中等级，并继续要求真机与代表性浏览器证据。

异步公共块会在多个延迟页面首次进入时复用，因此未来新增页面时必须继续运行完整双端构建和 `myfitness-client-quality/v1`，不能只观察单个页面脚本。共享块只解决交付重复，不授予跨用途数据或权限共享。

## 验证

- 私有照片路由源代码回归 2/2 通过，完整 Vitest 86 个文件、440/440 项通过。
- H5 与 WeApp 生产构建通过；质量校验记录 1,193,322/315,096/200,006 与 1,094,282/19,338/55,672 字节。
- WeApp `app.json` 同时注册两个路由，食物照片与进度照片页面脚本分别存在且为 20,867/26,332 字节。
- 两条真实 Chromium 回归通过：照片识餐初始读取中断保持未知，进度照片刷新被拒绝后保留已接受私有清单。
