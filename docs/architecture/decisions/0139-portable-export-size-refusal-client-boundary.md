# ADR-0139：便携导出超限拒绝的客户端解释边界

日期：2026-08-11

状态：已采纳

## 背景

第 144 轮让同步便携导出在超过共享 50 MiB 上限时返回严格 413 `portable_export_too_large`。然而 Taro 下载适配器仍把除 401 外的所有非 2xx 状态折叠成“数据导出生成失败”。用户无法区分确定性的规模资格拒绝和暂时服务故障，重复点击也不会改变超限结果。

下载响应正文会落在 H5 Blob 或 WeApp 临时文件中。为了展示 413，客户端可以读取并解析服务端错误体，但这会扩大敏感文件处理分支，并可能把代理错误页、后端自由文本或恶意响应带入 UI。当前产品只需要一个保守且跨平台一致的解释，不需要依赖错误正文证明更细状态。

## 决策

1. 下载适配器只使用 HTTP 状态码识别同步规模拒绝。状态 413 映射为固定产品文案：“当前数据副本超过 50 MiB 同步下载上限，未下载或保存。当前版本无法生成该副本。”
2. 文案中的 50 MiB 从共享 `maximumPrivacyExportBytes` 计算，不复制第二份数值；单元测试锁定当前显示结果。
3. 客户端不读取、解析、记录、持久化或展示 413 响应正文；服务端 `message` 即使包含不同或恶意文本，也不具备 UI 权威。
4. 413 路径立即释放 H5 临时 Blob，绝不触发 H5 下载锚点、WeApp `saveFile` 或后台重试。现有一次自动重试仍只允许 401 会话刷新。
5. 413 不改变 `exportChoice`。账号删除准备继续显示“尚未选择”，只有完成验证并实际触发下载/保存的结果才可标记 `downloaded`；用户仍可独立主动选择 `skip`。
6. 其他非 2xx 状态继续使用通用产品文案，不展示后端自由文本。未来异步归档真正可用前，不承诺不存在的操作入口。
7. 浏览器测试必须用含恶意自由文本的 413 响应证明固定文案、自由文本不可见、零下载、选择未推进，随后同一页面仍能完成既有无效产物拒绝与合法下载。
8. 本轮不增加 UI 卡片、状态码明细、错误体 Schema 解析、自动轮询、自动重试、归档任务或真实 WeApp 文件系统操作。

## 影响

- 用户可以判断当前版本无法同步生成该副本，不会把确定性上限误解为暂时网络故障。
- H5 与 WeApp 不需要依赖错误临时文件的可读性，跨平台行为更一致。
- 服务端稳定错误码仍保留给 API 调用方和未来归档客户端；当前 Taro UI 选择更窄的状态码信任边界。
- 浏览器对刻意的 413 请求会记录一条预期网络控制台错误；测试单独计数该条并继续拒绝其他未知浏览器错误。
- 固定产品文案增加少量客户端包体，必须重新构建双端并继续受 R-009 预算保护。

## 备选方案

### 读取并严格解析 413 JSON

暂不采用。可以获得错误码与最大字节数，但需要在 H5/WeApp 非成功下载路径上读取临时文件；状态码已经足以给出保守解释，新增文件保管表面没有当前收益。

### 直接展示服务端 message

拒绝。代理、上游或错误实现可能提供不受产品控制的文本，甚至包含敏感或误导内容。

### 继续统一显示生成失败

拒绝。它隐藏了确定性资格边界，鼓励无意义重复操作，也不利于后续归档能力的产品解释。

### 收到 413 后自动重试或删除照片再重试

拒绝。重复请求不会改变规模；静默删减会破坏导出完整性与用户数据所有权。

### 立即提供“申请归档”按钮

拒绝。后台加密归档、对象保管、期限、授权与删除责任尚未实现，不能展示虚假入口。

## 验证

- 客户端单元测试必须证明 413 得到固定文案，500 等其他状态不进入该解释。
- H5 真实浏览器流程必须注入带不可信 message 的 413，证明固定产品文案可见、后端文本不可见、无下载事件且删除前导出选择仍为“尚未选择”。
- 同一浏览器流程随后继续证明旧版本、错误媒体类型被拒绝，合法 v4 仍成功下载，避免 413 分支污染后续权限。
- H5/WeApp 生产构建与客户端质量检查必须在原预算下通过。
- 完整格式、类型、单元、集成、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
