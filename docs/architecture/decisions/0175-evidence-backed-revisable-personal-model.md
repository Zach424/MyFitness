# ADR-0175：建立有证据、可校准、可修订的个人认知模型

日期：2026-08-11

状态：已采纳

## 背景

衡迹已经能够保存健康、训练、餐食、计划、结果回看与本人反思，并通过 `personal-state-ledger-v1` 在 Dashboard 中并列本人确认、已确认记录、系统观察和恢复估计/Unknown。该账本是一项安全的当前快照投影：每次读取重新计算，没有持久生命周期，不能回答某项认识何时形成、何种证据反对它、用户如何校准或它为何失效。

新的产品目标要求衡迹以健身为首个垂直领域，逐步成为“个人认知镜子”。如果直接把历史记录交给 LLM 生成自由文本画像，会丢失来源、时间、修订、反对证据和删除传播，也可能把记录缺失、短期状态、相关性或模型猜测固化为稳定标签。因此需要先建立独立领域边界，再进入 contracts、数据库、API 与客户端实现。

## 决策

1. 保留 `personal-state-ledger-v1` 作为非持久化当前状态投影；新的 Personal Model 是记录之上的长期派生层，不替代资料、记录、计划、反思或账本。
2. 个人认知严格分为 Goal、Constraint、Preference、Baseline、Behavior、State、Pattern 与 Hypothesis。Goal、Constraint 和 Preference 的权威来自用户确认，系统观察不得反向覆盖；Pattern 只描述重复关系，Hypothesis 始终是待验证解释。
3. 每个 `PersonalModelItem` 使用版本化结构化 claim 联合类型，不使用任意 JSON 或自由文本作为权威结论。条目拥有 `candidate`、`active`、`disputed`、`superseded`、`invalidated` 生命周期和独立反馈状态。
4. 每次有意义变化追加不可变 revision。相同输入指纹为 no-op；来源更正、软删除、政策升级和用户反馈追加新修订，不重写旧历史。
5. EvidenceReference 必须绑定精确所有者、聚合或修订、发生/观察时间和作用角色 `supporting`、`contradicting` 或 `context`。聚合数字还要公开窗口、覆盖、算法/策略版本和可回溯来源集合。
6. 置信不是 LLM 自评分或医学概率。确定性收据记录覆盖、跨窗口稳定性、来源质量、矛盾、时效和用户反馈状态；缺失、冲突、过期或争议会限制展示和决策资格。
7. 用户校准固定为“符合我、暂时情况、不同意、不确定”，绑定精确条目 revision 并使用乐观并发。反馈不静默修改来源事实，也不自动提高置信；不同意默认使条目进入 `disputed`，从建议输入中移除。
8. Weekly Cognitive Review 只引用少量精确条目修订，展示“我们观察到什么、依据是什么、可能遗漏什么、你怎么看”，并与反馈和后续模型修订形成最小闭环。
9. 首批实现只覆盖两个低歧义确定性场景：本人确认的可训练安排约束与完整八周已记录训练行为并列；至少六次且跨四周的已记录课次时长基线。两者都不推断依从性、动机、偏好、因果或健康正常范围。
10. LLM 可以提出受检候选表达，但不拥有事实、证据查询、生命周期、置信更新或自动决策权。医疗诊断、心理画像、人格标签、黑箱自动适应和静默处方继续排除。
11. 第 181 轮只接受领域设计、产品顺序和风险边界，不新增表、API、OpenAPI 路由或客户端功能。下一轮仅实现 P1 共享契约。

## 影响

- 产品北极星从单纯计划行动扩展为可追溯认知闭环，工程顺序改为 Evidence → Personal Model Item → Weekly Review → User Feedback → Model Revision。
- 现有记录、计划、洞察、结果回看和反思可以作为证据源复用，但任何一个都不能直接升级为长期认知。
- 未来数据库需要所有者隔离的条目、修订、证据引用、反馈事件和回顾快照；权限、保留、导出、更正与删除属于功能验收，而不是上线后的补充项。
- `R-033` 跟踪长期模型固化偏差或错误标签的产品风险；真实用户理解和纵向稳定性证据出现前保持高风险开放。
- 极端规模导出、云部署、真实模型与设备接入继续停放，除非阻塞当前认知闭环的数据安全、隐私或正确性。

## 备选方案

### 继续扩展当前个人状态账本

拒绝。当前账本有意每次重算且没有双时态修订、反对证据或反馈事件；把长期生命周期塞入同一响应会模糊“当前快照”和“历史认知”。

### 保存一段 AI 用户画像

拒绝。自由文本不能可靠表达类型、证据角色、时间有效性、置信收据、乐观并发和来源撤销，也会让模型文字冒充事实。

### 一次实现完整 Agent 与自动适应

拒绝。它会同时扩大推断、权限、因果、安全和可解释性风险，无法用小范围可复现证据验证。先完成少量确定性场景的最小闭环。

### 只保存用户反馈，不保存模型修订

拒绝。反馈若不绑定精确 revision，就无法判断用户针对哪一版结论，也无法解释后续状态和置信变化。

## 验证

- [个人认知模型](../PERSONAL_MODEL.md)必须固定八类边界、领域聚合、证据、状态机、置信、用户校准、周回顾、首批场景和分阶段验收。
- 产品简报、已实现 PRD、路线图、风险登记册、架构、数据库和 API 参考必须一致区分目标愿景、候选设计与当前实现。
- 文档语言与迁移索引、格式、链接、Obsidian 镜像和仓库状态检查全部通过后才能提交。
