# ADR-0146：便携归档的分块认证加密信封

日期：2026-08-11

状态：已采纳

## 背景

第 151 轮已经能安全预约归档意图，但尚无可以交给未来执行器的应用层加密格式。仅依赖对象存储 SSE 不能满足保管边界：对象离开存储提供方、进入备份或被错误复制时仍需要独立的机密性、完整性和归档身份绑定；一次性加密完整 JSON 又会延续同步路径的大内存问题。

本轮需要建立与数据库、对象存储和 KMS 解耦的内部 codec。它必须按固定上限消费/产生字节流，在完整帧边界验证后才释放明文，并使截断、重排、身份错配或尾随数据不能被当成成功归档。它不是公开文件格式承诺，也不代表执行器或生产密钥保管已经完成。

## 决策

1. 定义内部 `myfitness-portable-export-archive-envelope/v1`，算法固定为 AES-256-GCM、32 字节数据密钥和 16 字节认证标签。默认明文块为 64 KiB；解析器只接受 1 KiB–1 MiB，避免不可信头部触发任意大分配。
2. 54 字节头部由 8 字节 magic `MFPAE001`、版本、算法 ID、4 字节块大小、8 字节随机 nonce 前缀和 32 字节上下文摘要组成。上下文摘要规范绑定格式、owner UUID、archive UUID、v4 导出版本和非秘密密钥引用；这些字段变化都会使验证失败。
3. 每个数据帧由 1 字节 flags、4 字节明文长度、等长密文和 16 字节标签组成。nonce 为随机 8 字节前缀加单调 32 位帧序号；AAD 为完整头部、帧序号和帧头。每个密钥最多处理 `2^32-1` 个数据帧，保证同一信封内 nonce 不复用。
4. 数据结束后必须写入一个长度为零、带独立标签的 final 帧。解码器在 final 标签通过后还要求物理 EOF；因此删除完整尾帧、在帧边界截断或追加任意字节都失败关闭。
5. 加密会把任意输入切分为有界帧，并在输出被完整消费后才解析内部收据 Promise。收据含内部格式/算法、非秘密密钥引用、块数、明文/密文字节数和完整密文 SHA-256；中途取消、源错误或大小溢出只得到拒绝，不发布完成收据。
6. 解码器用有界读取器适配任意传输分片。头部通过上限和上下文检查后才按声明长度分配；每个 GCM 帧必须在 `decipher.final()` 验证标签后才输出。格式、上下文、密钥、标签、截断与尾随错误统一映射为固定内部错误，不暴露验证细节。
7. codec 只复制 32 字节数据密钥到会话内存并在结束时清零该副本。`generatePortableExportArchiveDataKey()` 使用运行时 CSPRNG 生成候选数据密钥；未来 KMS 提供方仍必须负责每归档生成/解封、包装密钥持久化、调用方原始副本清零和轮换。
8. 本轮不增加 KMS 适配器、数据库转换、任务执行器、JSON 流式快照、对象上传、下载解密、公开 API 或客户端。

## 影响

- 未来执行器可以在不拼接完整密文的情况下计算上传字节和 SHA-256，并把内部收据映射到 available 保管字段。
- owner/archive/schema/key-ref 进入认证上下文后，把一个对象复制到其他归档行不能通过验证。
- 分块 AEAD 允许验证一帧后释放一帧，内部缓冲与归档总量解耦；但只有最终帧和完整收据成功才能把整个作业视为完成。
- 随机数据密钥生成函数不等于生产密钥保管。没有 KMS 包装、最小权限和轮换证据时，不能把本地密钥称为可持久化方案。
- R-013 只获得一个基础缓解：codec 本身流式，但当前 v4 数据查询/序列化、对象上传和任务生命周期尚未接入。

## 备选方案

### 只使用对象存储 SSE

拒绝。SSE 是提供方静态控制，不能独立认证归档身份或保护离开桶边界的对象，也不能形成应用可验证的加密格式。

### 用一个 AES-GCM 实例处理整个归档

拒绝。加密可以流式，但解密若在最终标签前输出就会释放尚未认证的明文；若等待最终标签则重新引入完整归档缓冲。分块 AEAD 同时保留认证后输出和有界内存。

### 每帧使用完全随机 12 字节 nonce

拒绝。即使碰撞概率很低，也无需接受同密钥下的随机碰撞风险；每信封随机前缀加单调计数器能直接证明帧内唯一。

### 不写 final 帧，只依赖输入 EOF

拒绝。攻击者可以在完整数据帧边界截断，前序标签仍全部有效。认证的空 final 帧使“完整结束”成为密码学事实。

### 把 key-ref 或完整上下文明文写入头部

拒绝。解码方已从所有者限定数据库行取得这些字段，只需比较固定摘要；减少外露元数据同时仍可认证身份。

## 验证

- 空与非空明文必须在不规则输入切片和逐字节传输切片下往返，内部收据的字节数、块数和 SHA-256 必须精确。
- 同一密钥/上下文/明文的两次加密必须因随机 nonce 前缀产生不同密文；CSPRNG 生成的两个数据密钥也必须不同。
- owner、archive、key-ref 或数据密钥错配，以及密文篡改、截断、尾随数据和超上限头部必须返回同一验证错误。
- 8 MiB 以上输入必须边生成、边加密、边解密并得到相同 SHA-256；单个加密输出块不得超过配置块大小加 21 字节帧开销。
- 未完整消费输出时完成收据必须拒绝；配置错误必须同步失败。
- 完整格式、类型、单元、集成、构建、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
