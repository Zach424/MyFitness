# ADR-0098：计划结果回看绑定修订且不作因果归因

日期：2026-08-10

状态：已接受

## 背景

第 102 轮已经能从带来源的主观恢复观察形成校准状态估计，并只让中等置信且方向一致的结果影响计划。但计划只保存了最终恢复分数、指纹和活动计数，未保存形成该分数的状态估计及底层引用；采用计划之后，周计划页也只能分别看到决定历史和当前训练关联，不能回答“当时依据什么、我采用了什么、后来留下了哪些记录”。

直接把训练关联数量或后续恢复分数称为计划效果，会混淆时间先后、选择性记录、计划外行为和其他生活变化。把回看结果重新写成身体状态或自动改变下一份计划，还会把尚未评估的相关性提升成执行权限。

## 决策

- 新生成的计划在既有 `planning-impact-v1` 证据中保存完整 `subjective-recovery-state-v1` 快照，包括窗口、覆盖、置信度、方向一致性和逐条记录引用。历史计划仍可读取；缺少该字段时明确标为旧摘要，绝不反推底层证据。
- `GET /plans/weekly` 只为当前状态为 `accepted` 的精确计划修订附加非持久化 `plan-outcome-review-v1`。回看从该采用修订的不可变 `changed_at` 开始，固定观察七天，并把 `observedThrough` 限制在当前时刻与窗口结束之间。
- 用户调整通过“当前采用快照”与该修订之前最近一次 `generated` 快照的稳定活动 ID/所选选项比较得到；它描述被采用的替代，不解释用户动机。
- 后续训练只接受当前仍活动、绑定同一计划 ID/修订的显式 `plan_workout_links`，且训练发生时刻必须位于采用后的观察窗。后续恢复只接受当前未删除、`confirmed`、非 `ai_estimate` 的四类主观恢复记录，并保留记录 UUID、当前修订、发生时间、来源和规范值。
- 回看状态只有 `unknown` 与 `observed`。它不计算依从性、完成率、效果分、因果概率或下一步负荷；没有记录保持 Unknown，不解释成没有训练或没有效果。
- 训练解除关联后不再作为当前回看证据；关闭行仍保留在导出/审计数据中。健康记录更正或删除会让只读回看使用当前已确认事实重新计算，而不是保留已撤销的旧值。
- 当前只展示当前采用修订的回看。历史采用修订仍保留在不可变计划历史中，但尚没有独立的历史回看读取权限或界面。

## 影响

该设计首次连通“生成时状态证据—用户采用的计划版本/替代—采用后的确认记录”，同时保持各源聚合独立，不增加结果表、迁移、自动适应或 AI 调用。用户能看到精确 PLAN/WORKOUT/RECORD 修订与观察时间窗，但界面必须持续说明时间先后不能证明计划效果。

七天观察窗和用户主动记录都存在选择偏差，当前测试只能证明筛选、修订绑定、Unknown 和界面文案一致，不能证明窗口有效、计划有益或记录完整。R-031 因此保持高等级；任何方向比较、假设生成或自适应都必须经过单独策略、真实纵向数据和专家审阅。

结果回看使 WeApp 实测总量/最大页面由第 102 轮的 1,095,128/55,672 字节增至 1,101,099/60,318 字节。实现先压缩约 3 KB 的初版展示，再把内部总量/单页预算显式重基线为 1,110,000/63,000 字节，分别保留 8,901/2,682 字节；H5 仍为 1,199,241/315,096/200,006 字节。该预算变更不代表关闭 R-009，仍需真机和弱网证据。

## 验证

- 共享契约拒绝恢复状态与计划分数不一致，领域测试锁定替代比较、精确窗口、Observed 与 Unknown。
- PostgreSQL 集成验证完整状态证据写入、采用后手工恢复记录与精确训练链接进入回看，采用前证据和 AI 候选不进入。
- 真实 Chromium 验证移动端 Unknown 和 Observed 两种卡片、替代动作、PLAN v ↔ WORKOUT v 来源以及禁止因果文案。
- 全量类型、单元、集成、浏览器、双端构建、客户端质量和文档门禁在第 103 轮档案中记录。
