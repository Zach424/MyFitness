# ADR-0119：洞察聚合关系一致性

日期：2026-08-11

状态：已接受

## 背景

第 124 轮保证了动作/健康洞察来源的每个数值可安全表示，却没有证明同一聚合行内的字段彼此一致。替代适配器仍可返回课次数大于完成组数、完成组数大于总组数、健康记录数与记录日/统计存在性冲突，或最小值、平均值、最大值倒置的组合。单字段 Schema 无法识别这些不可能状态。

真实 SQL 通过 `COUNT`、`FILTER`、`MIN`、`MAX` 和 `AVG` 从同一已确认集合产生这些字段。纯构造器与公开契约应显式保留这些关系，而不能依赖实现偶然正确。

## 决策

- 动作来源窗口要求 `session_count <= completed_set_count`；共享窗口 Schema 对应要求 `sessionCount <= completedSetCount`。
- 动作来源点要求 `0 < completed_set_count <= total_set_count`；共享点 Schema 对应要求至少一组完成且完成组数不超过总组数。
- 健康来源窗口要求 `recorded_days <= record_count`。零记录必须同时为零记录日和全空统计；正记录必须至少一个记录日且三个统计齐全。
- 健康统计齐全时要求 `minimum <= average <= maximum`；共享健康窗口 Schema 对转换后的响应执行相同检查。
- 来源关系校验发生在对应单字段数值校验之后、映射之前，并覆盖全部原始点，包括隐藏第 181 点。
- 不验证跨窗口单调性，不把有限健康负值判为异常，不纠正冲突，也不生成趋势、因果或医疗结论。
- 保持 SQL、数值精度、分页、客户端、持久化、计划、AI 和健康解释不变。

## 影响

字段各自合法但组合不可能的聚合不能进入公开响应；共享契约也会拒绝外部/替代实现产生的同类冲突。合法 SQL 结果保持兼容，健康最小值/平均值/最大值关系只表达数学包络，不表达正常范围。

本决策不证明跨窗口查询完整或单调、记录真实、单位正确、健康范围正常或趋势有统计意义。第 123 轮允许稀疏窗口回退，因此跨窗口关系必须另行协调，不能在本轮暗中改变缺失语义。
