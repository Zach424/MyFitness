# ADR-0128：动作 90 日窗口与点截断收据

日期：2026-08-11

状态：已采纳

## 背景

动作洞察窗口公开 90 日 `sessionCount`，点查询最多读取 181 个训练并公开 180 点。既有通用规则只保证 `hasMore: true` 时公开前缀恰有 180 点，不能阻止窗口课次计数、实际来源行数、公开点数和 `hasMore` 互相矛盾。

SQL 审计确认两条查询共享同一用户、精确 `exerciseKey`、未删除训练、参考时刻上界、90 日下界和至少一组已完成的资格。窗口按训练 ID 去重计数；点查询按训练 ID 分组并每个训练产生一行，因此可以用 `sessionCount` 作为完整点集合的基数收据。

## 决策

1. 来源层在全部原始点通过时间、数值、快照、UUID、顺序和唯一性校验并排除未来点后，先保留最多 181 行的既有上界。
2. 读取 90 日窗口 `sessionCount`；缺失窗口按既有规则解释为零。
3. `sessionCount <= 180` 时，合格来源点行数必须精确等于 `sessionCount`；`sessionCount > 180` 时，合格来源必须恰有 181 行，作为存在更多记录的收据。
4. 公开响应必须满足 `series.length = min(sessionCount,180)`，并满足 `hasMore = (sessionCount > 180)`。
5. 冲突失败关闭，并分别定位到 90 日 `sessionCount` 或 `hasMore`；不补零、不从有限前缀重算窗口聚合。
6. 不修改 SQL、响应形状、分页、客户端、动作身份或历史记录。

## 影响

- 完整课次计数、181 行来源收据、180 点公开前缀和 `hasMore` 形成可验证闭环。
- 90 日来源窗口缺失时，只有零合格点可以继续生成空窗口。
- 完成组数不作为课次数；单次训练即使包含多组或同动作的多条明细，点与窗口仍按训练 ID 对齐。
- 本决策不证明动作跨窗口聚合单调、训练记录真实、动作执行安全、趋势意义、训练效果或用户理解。

## 备选方案

### 继续只检查 `hasMore: true` 的 180 点前缀

拒绝。该规则无法区分完整 180 点与被截断的 180 点，也不能发现 90 日窗口计数错配。

### 用完成组数与点数比较

拒绝。一个训练点可以包含多组，二者不是同一基数。

### 从公开点重算 90 日窗口

拒绝。超过 180 个训练时公开点只是有限前缀，不能代表完整窗口聚合。

## 验证

- 来源层覆盖 180 课次却收到 181 行、181 课次却只收到 180 行两类失败。
- 响应层覆盖 90 日 `sessionCount` 与公开点数错配，以及 `hasMore` 与完整课次计数错配。
- 真实 PostgreSQL 场景直接断言未截断响应中的 90 日课次数等于公开点数。
- 定向、完整单元、完整集成、严格类型、双端预算与生产依赖审计通过。
