# ADR-0144：异步便携归档的保管状态与数据库边界

日期：2026-08-11

状态：已采纳

## 背景

第 149 轮证明无媒体同步导出在 65,000 条记录时已达到 50 MiB 上限的 93.78%，并出现显著同进程内存增长。继续依赖同步对象图、base64 与最终字符串无法为较大账号提供可靠路径，但直接增加一个后台任务也不能证明归档安全：现有任务没有归档专用状态、密钥引用、下载期限或账号擦除协调。

必须先区分三类事实：用户请求了归档、对象已经以受控方式存在、对象已经被物理处置。只用一个 queued/completed 布尔值会把任务完成、可下载和删除完成混为一谈；让用户行级联删除归档元数据还可能留下无法追踪的私有对象。

## 决策

1. 在 `packages/contracts` 定义 `myfitness-portable-export-archive-receipt/v1` 和六状态：`queued`、`generating`、`available`、`failed`、`deletion_pending`、`disposed`。主路径单调前进；queued/generating 可进入失败或待删除，available 只能进入待删除，disposed 不可离开。
2. 最小收据只暴露归档 UUID、状态、请求/更新时间、生成期限、可选可用/下载期限、可选摘要/字节数、受控失败码和处置原因/时间。对象键、加密密钥引用、下载 URL、访问令牌、账号 ID 和导出内容没有字段，strict Schema 拒绝附加字段。
3. 迁移 0029 新建 `privacy_export_archives`。每行绑定 owner、幂等 UUID、请求 SHA-256、v4 导出版本和服务端生成期限；对象键固定为 `<user UUID>/<archive UUID>.json.enc`，避免客户端选择路径或任务重试产生多份名称。
4. available 必须同时具备确定性对象键、3–240 字符非秘密密钥引用、64 位小写十六进制 SHA-256、正字节数、可用时间和晚于它的下载期限。failed 必须没有对象/密钥/摘要并携带受控失败码。disposed 必须清除对象键和密钥引用并携带处置原因/时间，可保留聚合摘要/大小作为最小收据。
5. 生命周期 CHECK 约束当前行形状；更新触发器额外拒绝身份/生成期限变更、更新时间倒退、非法状态跳转、同状态修改保管字段，以及在指定转换之外改变对象键、密钥引用、产物收据、失败或处置证据。
6. `user_id` 外键使用 `ON DELETE RESTRICT`，不级联删除。未来账号擦除必须先阻止生成/下载、将对象置为 deletion_pending、完成物理删除、进入 disposed、删除归档行，然后才能删除用户；失败或无对象行可在确认没有对象后直接删除。
7. 本轮不增加公开路由、预约服务、持久任务类型、对象写入、加密实现、签名下载、保留扫描或客户端。没有执行器时不得创建用户可见 queued 请求或宣称异步归档可用。

## 影响

- 未来预约、执行、下载和擦除代码共享同一状态词汇，并必须同时通过应用 Schema 与数据库约束。
- 响应或日志无法从最小收据取得对象键、密钥引用或下载凭据；下载授权必须由未来独立端点按所有者与状态即时签发。
- 确定性对象键为上传提交丢失后的对账/删除提供稳定目标，但并不证明对象已存在；只有完整 available 行能发布产物收据。
- RESTRICT 会让未来账号擦除在归档未处置时失败关闭。正式接入前必须扩展擦除执行器，否则不能开放归档预约。
- 该设计没有改变当前同步导出，R-013 的内存与 50 MiB 风险保持不变。

## 备选方案

### 让归档表随 users 级联删除

拒绝。数据库行会消失，但对象存储不参与事务，可能留下既无 owner 也无删除目标的敏感孤儿对象。

### 在收据中返回对象键或预签名 URL

拒绝。对象键是服务端保管细节；URL 是短期授权结果，不是持久状态。两者都不能作为通用状态收据字段。

### 只有 queued/completed/failed 三状态

拒绝。它无法区分生成中、可下载、等待物理删除和已处置，也无法为账号擦除或保留到期提供失败关闭边界。

### 只在 TypeScript 中校验状态

拒绝。后台任务、运维 SQL 与未来迁移都可能绕过单一服务；敏感对象保管需要数据库生命周期 CHECK 和转换触发器作为第二道边界。

## 验证

- 共享契约测试覆盖 queued/available 收据、附加对象键拒绝、失败/处置/时间关系和状态转换图。
- 漂移测试锁定迁移的状态、v4、密钥引用、下载期限、账号处置、RESTRICT 和触发器，并证明迁移不含 URL/令牌字段。
- 真实 PostgreSQL 必须拒绝重复 owner/幂等 UUID、queued 直接 available、发布时移除密钥引用、available 原地替换摘要及归档未处置时删除 owner。
- 真实 PostgreSQL 必须接受 queued → generating → available，并接受 queued → deletion_pending → disposed → 删除归档行 → 删除 owner；测试后归档表为 0 行。
- 完整格式、类型、单元、集成、构建、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
