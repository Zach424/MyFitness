# ADR-0103：以非持久化证据账本表达当前个人状态

日期：2026-08-10

状态：已接受

## 背景

系统已经分别拥有用户确认的计划体验、当前已确认健康/恢复记录、七天跨领域观察和 `subjective-recovery-state-v1` 确定性恢复估计，但这些信息散落在结果页、仪表板与计划证据中。用户能看到若干数字，却无法从一个原子快照判断某项内容是本人确认、系统观察、确定性估计还是 Unknown，也不容易知道它依据哪个权威、截至何时以及什么变化会使它失效。

把这些内容复制到新的持久表会形成第二权威来源，并带来同步、保留、导出、更正与删除责任。让模型生成一段统一叙述又会把来源差异和不确定性压平，甚至被误读为医疗或因果结论。当前更安全的路径是从既有权威即时投影最小账本，并让共享契约证明其字段与来源一致。

## 决策

- 在原子仪表板响应中加入严格的 `personal-state-ledger-v1`，不新增数据库表、缓存、后台任务、轮询或第二 API 请求。仪表板统一返回 `Cache-Control: private, no-store`。
- 账本固定包含四类边界：精确采用修订上的最新 `user_confirmed` 计划体验；恢复估计实际引用的 `confirmed` 记录摘要；权威为七天趋势窗口的 `observed` 计数；权威为确定性恢复投影的 `estimated` 或 `unknown` 状态。
- 每项携带 `asOf`、固定为空的 `validUntil` 与有界 `invalidatedBy`。记录和估计在来源记录或时间推进后失效；本人反思在反思变化后失效。空记录与 Unknown 保持不同：前者是确认没有合格来源，后者是估计无法形成状态。
- 计划体验只读取同一所有者、精确计划修订且存在 `accepted` 修订事件的当前反思，并要求反思更新时间不晚于仪表板参考时刻。选择最新更新时间和 UUID 顺序稳定的一项；纠正或硬删除后，下次仪表板读取立即重新投影，历史参考时刻也不会读取未来反思。
- `dashboardSchema` 逐字段核对账本与仪表板权威，包括每类快照时间、七天窗口结束时刻/计数、恢复状态/置信/一致性/标签/证据数，以及已确认记录的数量、最近时间和来源类型。记录类只能声明“来源变化/时间推进”，反思只能声明“反思变化”；任何知识类别、权威或失效原因不匹配都失败关闭。
- 教练工作台只复用已接受的同一仪表板快照，把四类内容并列。它不新增 AI 调用、自由文本、诊断、因果、依从性评分或自动计划适应，也不把账本写回任一事实表。

## 影响

用户首次能在一个页面区分“我确认的体验”“系统确认引用的记录”“系统观察到的七天记录覆盖”和“系统估计/Unknown”。计划反思仍沿用既有纠正、删除、隐私导出和账号擦除边界；健康来源更正/删除仍由现有当前记录权威负责。账本只是一次读取的结构化解释，不扩大数据保留范围。

仪表板多执行一项所有者限定的最新反思查询，并在进程内构造小型投影。当前本地回归证明了 459 项单元、65 项 PostgreSQL 集成和 95 项 Chromium 流程；尚未用生产规模数据验证查询延迟，也没有证明真实微信设备上的阅读理解。

统一表面本身可能制造“完整个人画像”的错觉，因此新增 R-032。固定类别、来源、快照、无保证有效期和失效原因只是当前控制，不代表账本已经覆盖全部健康、饮食、训练、环境或心理背景。下一步应让用户追溯到既有权威表面并进行检查、更正或删除，而不是扩大为自动叙述。

客户端交付成本使 WeApp 总量达到 1,108,916/1,109,000 字节，只余 84 字节。后续来源追溯必须先证明结构余量，不得提高预算或删除隐私、安全、失败关闭与无障碍语义。
