# ADR-0107：营养洞察只接受连续参考本地日期序列

日期：2026-08-10

状态：已接受

## 背景

营养长期洞察返回恰好 90 个按请求时区生成的本地日期，并从末尾 7/30/90 日派生餐次、条目、营养和覆盖汇总。PostgreSQL 使用 `generate_series` 截至参考时刻 `at` 的本地日，当前数据库路径已经正确排除未来餐食并填出缺失日期。

公开 `buildNutritionInsight` 此前直接映射任意输入行并从数组末尾派生窗口。共享 Schema 只验证长度、单日空值语义和单个窗口内部计数，因此一个长度仍为 90 的错序、重复、未来、间断或整体偏移数组可以通过，并把错误日期范围带入趋势窗口。窗口也可以与序列内容不一致。

自动补齐缺日不安全：产品把缺失记录表示为未知/无证据，而不是确认零摄入。若内部来源没有返回预期日期，构造器必须失败关闭，不能发明一条空白日掩盖数据源缺陷。

## 决策

- `buildNutritionInsight` 以 `at` 在 `timezone` 中的本地日为末日，用 UTC 日历算术生成包含末日的连续 90 日预期序列。输入长度或任一 `local_date` 不精确匹配时，在派生任何窗口前抛出内部一致性错误。
- 合格输入继续由现有 `nutritionDay` 映射，再由 `nutritionWindow` 从末尾 7/30/90 日派生窗口；不新增零值、排序、去重或自动填补。
- `nutritionInsightSchema` 独立解析 `generatedAt + timezone`，只报告首个日期错位的精确路径。它还要求三个窗口按 7/30/90 顺序出现，并逐字段等于从已接受序列重新派生的记录天数、缺失天数、餐次、条目、纤维覆盖和五项营养总计。
- 保持现有 SQL、端点、查询参数、客户端、持久化与缺失日空值语义不变。无效内部响应由控制器现有 Schema 解析失败关闭，不降级成空/零趋势。

## 影响

替代适配器、测试夹具或未来模块抽取不能再把错误 90 日数组伪装成有效营养历史。固定窗口也不能与公开日序列分叉，减少用户对记录覆盖和营养趋势的错误理解。

UTC 日历算术只用于对已经解析出的 `YYYY-MM-DD` 做自然日增减，不用于把发生时刻映射到本地日；末日本地日仍由 IANA 时区格式化得到。这样可跨越 DST 变化而不把一天写死为 86,400,000 毫秒。

本轮没有证明真实浏览器或微信设备的时区数据库一致，也不提供饮食完整性、目标、依从性或处方判断。R-029 继续开放；真实平台验证仍是封闭测试门禁。
