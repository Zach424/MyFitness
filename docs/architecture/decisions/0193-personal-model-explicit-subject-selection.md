# ADR-0193：Personal Model 显式主题单选

日期：2026-08-12

状态：已接受

## 背景

第 198 轮只开放“已记录训练频次”，先证明一个主题的进入读取、刷新、失败和卸载权限。领域和 HTTP 契约其实已经支持训练安排、记录频次和记录时长三个严格主题；若为每项复制页面，会重复生命周期与文案。若进入页面时批量读取三个主题，又会扩大敏感数据范围，并容易把三项并列误解为完整画像或评分。

本轮只在现有页面加入显式主题单选。一次只能读取用户当前选择，切换必须撤销旧主题的状态、快照、回调和失败焦点；不批量预取、不缓存每个主题、不开放反馈、历史或证据正文。

## 决策

1. 页面固定提供三个主题索引：本人安排、记录频次、记录时长；默认仍是记录频次，避免改变既有首次读取行为。
2. 每个索引使用可键盘激活的 Taro Button 和唯一 `aria-pressed`，外层具名 group。视觉是紧凑的认知索引条，不使用评分卡、进度条或人格标签。
3. 当前选择下方单独显示来源与边界：本人安排明确来自本人提交且不代表完成；频次和时长明确来自已确认记录，并分别排除达标判断与效果/能力/强度评价。
4. 请求必须读取 `begin` 收据上的 subject，而不是闭包常量。切换先取消待执行的失败焦点，再调用既有 `replacePersonalModelCurrentSubject`，提高代次、清除旧快照/错误并回到 unread，随后只为新主题发起一次请求。
5. 旧请求即使晚到，也因 subject 与 generation 不再匹配而不能提交。失败焦点还必须核对页面活动、subject、generation 和当前 failure，不能在切换后把焦点拉回旧主题重试按钮。
6. 同一主题再次点击为 no-op，不刷新、不增加代次；重新核对仍由成功快照后的刷新按钮或失败后的重试按钮明确触发。
7. 切换不保留每个主题的独立缓存，也不并排展示多个快照。每次切换暂时回到 Unknown/加载态，以最小页面内存换取明确的当前读取权限。
8. 窄屏仍维持三列索引，源码最小高度提升到 48 px，以抵消 Taro H5 根字号缩放；360 px 浏览器实测触达高度约 44.3 px且无水平溢出。
9. 不提高客户端预算。通过移除重复卡片说明与无必要装饰，把 WeApp 总量控制在 1,149,474/1,150,000 字节；H5 最大异步块保持 149,898/152,000 字节。

## 影响

- 三个已经实现的严格主题现在都能由用户逐项进入同一可信读取闭环，不需要复制路由或状态机。
- 页面只持有一项快照，减少敏感派生数据在客户端内存中的同时暴露，并防止旧主题内容在切换后残留。
- 紧凑索引牺牲了每项同时可见的长说明，但当前来源和边界紧邻选择器，信息仍可理解且包体可控。
- 本地离线浏览器已经证明选择、pressed 语义、即时来源切换、焦点不回抢和窄屏尺寸；没有真实认证 API，尚未证明三个主题的成功正文。
- WeApp 总量只余 526 字节，下一轮若继续增加页面能力，必须先获得真实结构性降幅或重新拆分产物，不能直接放宽门槛。

## 备选方案

### 进入时并行读取三个主题

拒绝。用户没有明确选择全部读取，会扩大敏感数据处理；并排结果也容易被当作完整画像，且需要三套并发/失败状态。

### 为每个主题创建独立页面

拒绝。会复制五阶段生命周期、失败文案、卡片和样式，增加路由与 WeApp 总量，主题之间的安全语义也更容易漂移。

### 在切换后保留各主题缓存

拒绝。会扩大页面内存中的敏感数据集合，并需要独立的新鲜度、失效和账号切换清理决策；当前显式重读更诚实。

### 用原生 Tab 语义并让三个面板同时存在

拒绝。页面不是在三个已经加载的面板之间切换，而是在选择下一项要读取的敏感主题；pressed 按钮更准确表达命令和当前选择。

## 验证

- 页面模型、结构、入口和读取权限定向测试 4 个文件、23 项通过。
- 完整单元测试 115 个文件、699 项通过；完整 PostgreSQL 集成基线 29 个文件、174 项不变。
- 全工作区 typecheck 与生产 H5/WeApp 构建通过；API、admin 和数据库未变，沿用第 198 轮完整构建基线。
- H5 总量/入口/最大异步块为 1,250,606/315,456/149,898 字节；WeApp 总量/vendor/最大页面为 1,149,474/19,338/56,943 字节，禁止标记为零。
- 本地浏览器证明默认频次唯一 pressed，切换到本人安排后来源说明同步变化且无 error/warning；360 px 无水平溢出，三个按钮实测高度约 44.3 px。
