# ADR-0142：便携导出媒体展开的常数时间精确字节下界

日期：2026-08-11

状态：已采纳

## 背景

ADR-0141 在任何私有媒体读取前建立全部 `media: null` 的完整 v4 UTF-8 下界，能够拒绝非媒体内容本身已经超过 50 MiB 的请求。但只要初始下界合格，原实现仍会读取并 base64 编码全部媒体，直到控制器格式化最终附件后才发现媒体使结果超限。

每读取一张照片后重新格式化完整导出可以得到精确下界，但会让多照片账号产生 O(n²) 序列化成本。数据库 `byte_size` 仍不能成为拒绝权威；只有本次对象存储读取返回的 Buffer 长度能证明当前媒体存在及其真实字节。

## 决策

1. 初始下界继续使用 ADR-0141 的完整 `media: null` v4 字节数，作为一个单调运行值。
2. 使用与最终照片条目相同嵌套深度的规范 JSON 包装器，在模块加载时计算 `null` 到空 base64 媒体对象、以及 `null` 到 `{ unavailable: true }` 的固定 pretty JSON 字节增量；不手写空白或键名常数。
3. 对已成功读取的 Buffer，base64 字符数精确为 `4 * ceil(sourceByteLength / 3)`。固定包装增量加该字符数就是把当前 `media: null` 替换为最终媒体对象的精确 UTF-8 增量；输入必须是非负安全整数。
4. 对 `ENOENT`，把规范包装器计算的不可用标记增量加入运行下界。没有存储键的条目继续保持 `null`，增量为零。
5. 每个增量加入后立即执行共享 50 MiB 数值门禁。成功读取的当前对象若使下界超限，必须在 `bytes.toString('base64')` 前返回既有固定 413；后续食物/进度照片对象不得读取。缺失对象导致超限时同样停止后续读取。
6. 增量维护每个媒体只执行 O(1) 算术，不逐照片重序列化完整导出。控制器最终格式化与附件门禁继续保留，作为真实成功产物的最终权威。
7. API、Schema、媒体顺序、缺失语义、客户端 413 解释和擦除权限均不改变；本轮不实现并发媒体读取、流式响应、压缩、后台归档、加密或外部对象存储。

## 影响

- 如果第 k 个媒体使最终附件必然超限，API 只读取到第 k 个对象，不为它生成 base64，也不读取第 k+1 个及后续对象。
- 增量来自本次真实 Buffer 或实际 `ENOENT`，不会把数据库声明大小误当成当前对象事实。
- 正常导出不增加逐媒体完整序列化；除既有初始下界和最终字符串外，每个媒体只增加常数时间计数。
- 这仍不能避免导致越界的当前 Buffer 读取，也不能消除完整数据库结果、非媒体对象图、初始下界字符串或正常导出的最终字符串；R-013 保持开放。
- 媒体对象键、嵌套深度、缩进或最终编码若变化，规范包装器与逐字节等价测试必须同时更新，否则不得接受该变化。

## 备选方案

### 每读取一张照片就重新序列化完整导出

拒绝。结果虽然精确，但照片越多，重复扫描的对象图越大，会把同步导出的 CPU 成本扩大为 O(n²)。

### 用数据库 `byte_size` 在对象读取前累计

拒绝。对象可能缺失，声明值不能证明最终会输出 base64；用它拒绝仍可能误伤合法的不可用标记导出。

### 先生成当前 base64，再检查最终增量

拒绝。Buffer 长度已经足以精确计算 base64 字符数；先分配字符串会失去本轮降低峰值的主要收益。

### 删除越界媒体并交付部分导出

拒绝。它改变成功契约并破坏用户数据所有权，固定 413 必须继续代表整份同步产物不可交付。

## 验证

- 纯测试必须覆盖 0、1、2、3、4、17、1024 字节，证明 base64 和不可用标记增量之和与两类照片集合的最终 pretty JSON UTF-8 字节逐一相等。
- 纯测试必须拒绝负数、非整数、无穷大和超出安全整数的来源长度，并证明数值门禁精确等于上限时接受。
- 真实 PostgreSQL/私有对象存储测试必须创建至少两个实际照片对象，触发首个展开增量 413，并证明对象读取一次、base64 编码零次、后续对象未读取。
- 既有媒体读取前下界和合法 base64 导出测试必须继续通过。
- 完整格式、类型、单元、集成、构建、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
