# ADR-0094：产品简报迁移为受保护的中文权威正文

日期：2026-08-06

状态：已接受

## 背景

产品简报定义 MyFitness / 衡迹为何存在、为谁服务、解决哪些核心任务、首个版本包含和排除什么，以及怎样判断成功。它已经被项目状态引用为 MVP 范围证据，但正文仍是英文，也仍位于待迁移专题清单中。只翻译文字而不转移迁移分类，会使同一文件同时表现为“已完成”和“待处理”；只转移分类而不加入失败关闭的正文门禁，则允许产品边界悄然恢复为英文或丢失导航结构。

这次迁移不能借机扩展产品范围。治疗性计划、未成年人、疾病诊断、治疗声明和无条件设备集成等排除项必须保留；AI、照片、数据控制与商业模式仍遵循原有非医疗、用户确认和隐私优先边界。

## 决策

- 把 `docs/product/PRODUCT_BRIEF.md` 的全部自然语言正文迁移为中文，保留 MyFitness / 衡迹、MVP、AI、RPE 与 EXIF 等需要和实现或行业术语对应的字面量。
- 保持提交前的结构签名：13 个标题及其层级、6 个编号任务、26 个项目符号、7 行表格、零行内代码、零链接、零代码围栏和按顺序排列的 8 个数字令牌必须完全一致。
- 将产品简报加入 `myfitness-chinese-documentation/v2` 的活跃权威文档清单，固定从“产品主张”到“商业模式假设”的 13 个中文导航标题，并继续要求正文中文占比至少为 72%、纯英文叙述行为零。
- 将产品简报从 `topic-product-design` 待迁移批次移入活跃权威文档分类；待迁移专题由 19 份降为 18 份，总待办由 193 份降为 192 份。
- `myfitness-documentation-migration-index/v1` 同步要求人读索引保留精确的受保护活跃文档数量。活跃文档分类发生变化而索引未更新时必须失败关闭，并增加对应单元回归。
- 本轮不改变客户端、API、AI 服务、数据库、发布配置或产品能力，也不把翻译和本地门禁证据扩大为用户研究或生产验证。

## 影响

产品责任人现在可以直接用中文审阅 MVP 的受众、任务、范围和排除边界；后续编辑一旦删掉关键导航标题、恢复纯英文叙述或使全文中文占比跌破门槛，CI 会立即失败。迁移索引继续保持每份 Markdown 恰好归类一次，并能证明产品简报不再属于待办。

结构签名证明技术和数量锚点未增删，不能替代逐段语义审阅，也不能证明产品假设已经被真实用户验证。风险登记册、设计系统和 API 说明仍在专题待办中，必须各自经过同样的有界迁移流程。
