# ADR-0117：洞察来源窗口身份集合

日期：2026-08-11

状态：已接受

## 背景

动作与健康洞察构造器接收 PostgreSQL 或替代适配器返回的窗口聚合行，再用 `.find(row.days === days)` 生成固定 7/30/90 日公开窗口。缺失来源行会有意回退为空窗口，但重复 `days` 会静默选择首行，未知 `days` 会被忽略。替代查询、测试适配器或未来重构因此可能隐藏冲突或错配的聚合证据。

共享响应 Schema 已要求公开窗口严格保持 7/30/90，但它看不到构造阶段未被选择的重复或未知来源行，不能替代来源集合门禁。

## 决策

- 动作与健康纯构造器共用来源窗口身份校验，只允许 `days` 为 7、30 或 90。
- 每个已提供身份至多出现一次；重复和未知身份统一抛出 `insight window rows must use unique 7/30/90 day identities`。
- 来源数组不要求顺序，也不要求三个身份齐全；缺失身份继续生成计数为零、统计为空的明确空窗口。
- 参考时刻和响应时区先验证，来源窗口身份随后验证，再进入点时刻、顺序、唯一性、过滤、截断和摘要派生。
- 保持 SQL、公开 Schema、窗口数值换算、分页、响应形状、客户端、持久化、计划、AI 和健康解释不变。

## 影响

重复来源窗口不再由数组顺序决定公开证据，未知窗口也不能被静默丢弃。合法稀疏/乱序适配器保持兼容，公开响应仍按固定 7/30/90 顺序产生。

本决策证明来源窗口身份属于约定集合且唯一，不证明查询返回完整、窗口数值有限或非负、聚合统计正确、来源记录真实或趋势具有统计/医疗意义。原始数值有效性仍需独立门禁。
