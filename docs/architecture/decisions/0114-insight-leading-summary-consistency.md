# ADR-0114：洞察首点摘要一致性

日期：2026-08-11

状态：已接受

## 背景

动作与健康洞察按发生时间降序公开最多 180 个点。动作顶层 `identity` 和健康顶层 `canonicalUnit` 都由最新公开点派生，供客户端在时间线上方显示当前证据标签。生产构造器已经使用首点派生这些值，但共享 Schema 此前允许空序列携带非空摘要、非空序列携带旧摘要，也允许健康点在同一时间线中混用不同规范单位。

健康构造器还会接收最多一个用于判断截断的隐藏点。单位检查若只覆盖公开 180 点，第 181 点可能逃逸；若在未来过滤前执行，则一个尚未发生且本次不会公开的异常点又会错误阻断当前结果。

## 决策

- 动作共享 Schema 将顶层 `identity` 与 `series[0].identity` 逐字段比较，包括有序器械数组；空序列要求顶层值为 `null`。错位统一定位到 `identity`。
- 健康构造器先执行既有时区、输入顺序和 UUID 唯一性检查，再过滤晚于参考时刻的点；随后在 180 点截断前验证全部合格点使用同一 `canonical_unit`。
- 健康共享 Schema 要求顶层 `canonicalUnit` 等于首点单位，空序列时为 `null`；任一后续点单位不同则定位到 `series[index].canonicalUnit`。
- 不自动换算、删除或选择冲突单位，因为替代适配器没有足够证据决定哪个量纲正确。
- 保持 SQL、窗口统计、响应形状、客户端、持久化、计划、AI 和健康解释不变；既有时间、日期、顺序和身份门禁继续执行。

## 影响

最新动作不会再被旧名称或旧器械摘要标注，健康时间线也不能把不同量纲当成同一纵向序列。未来异常点在进入参考时刻前不影响当前响应，进入后会失败关闭；隐藏第 181 个合格点仍受检查。

本决策只证明一个响应内部的摘要和规范单位一致，不证明来源记录真实、单位换算正确、指标配置合理、趋势显著或具有医疗含义。`hasMore` 是否由精确截断收据支持仍需独立门禁。
