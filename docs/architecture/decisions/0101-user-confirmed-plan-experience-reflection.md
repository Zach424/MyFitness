# ADR-0101：计划体验使用精确修订绑定的用户确认事实

日期：2026-08-10

状态：已接受

## 背景

`plan-outcome-review-v1` 只说明采用计划以后仍可见的训练关联与恢复记录，不能回答用户主观上是否觉得安排合适。若从训练次数、恢复分数或记录缺失推断体验，会把系统观察误写成用户事实；若把自由文本直接送入 AI，又会提前扩大敏感内容、提示词注入、保留和审核范围。

第 105 轮已把当前/历史采用结果放入独立页面，因此本轮需要在同一页面增加最小的本人确认能力，同时保持精确修订、读取权限、隐私所有权和包体门禁。

## 决策

- 新建 `plan_experience_reflections`，一条记录唯一绑定所有者、计划 UUID 与精确 `accepted` 修订。只有四个有界选择：`easier_than_expected`、`about_right`、`not_right_for_me`、`not_sure_yet`；来源固定为 `user_confirmed`，本轮不接收自由文本。
- `GET/PUT/DELETE /plans/weekly/:planId/history/:revision/reflection` 都先验证目标是当前用户拥有的采用修订。外部所有者、非采用修订和不存在目标统一隐藏为 `404`；读取与写入响应使用 `private, no-store`。
- GET 使用带 `reflection` 可空字段的对象信封，避免跨运行时顶层 `null` 被解释为空响应。PUT 用 `expectedRevision` 区分首次新建与显式纠正，行锁与事务保证单调修订；DELETE 要求精确修订并真正移除内容。
- 纠正只保留当前本人确认值和递增修订，不保存被替换的主观内容历史。删除后便携导出不再包含该内容；账号擦除依所有者外键级联删除。当前记录进入隐私清单计数与 v4 便携导出的对应计划快照。
- 客户端把系统结果读取和本人确认读取建模为两个权限状态。反思读取失败不能显示成“未填写”，也不能隐藏已成功读取的系统证据；重试显式取得焦点。四个按钮点选即创建或纠正，删除先确认。
- 本人确认不改变 `Unknown/Observed`，不证明效果、因果或依从性，不触发 AI，也不自动生成或调整下一份计划。
- 复用既有结果页面，不新增 Taro 路由、不提高 H5/WeApp 预算。为守住总包门禁，证据表现收敛为紧凑账本并保留显式按钮语义、键盘激活和失败关闭。

## 影响

用户现在可以为当前或历史采用修订留下一个来源明确、可纠正、可删除的主观事实，且它和系统观察在数据、API、读取状态及文案上都保持分离。隐私清单、导出和账号擦除覆盖该表；非采用与跨所有者路径不能探测记录。

代价是客户端包体已经没有可用增长空间：最终 WeApp 为 1,109,995/1,110,000 字节，只余 5 字节。该结果不是提高预算的理由；第 107 轮必须先做页面/共享块结构减重，再允许任何客户端功能增长。当前值的纠正会覆盖旧主观内容，因此它不是不可变审计历史；如未来确需反思历史，必须重新评估敏感内容保留、导出、删除和用户理解成本。
