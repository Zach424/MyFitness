# ADR-0118：洞察来源数值有效性

日期：2026-08-11

状态：已接受

## 背景

动作与健康洞察来源行把 PostgreSQL `bigint`/`numeric` 聚合表示为字符串，并把修订表示为 JavaScript number。纯构造器此前直接调用 `Number(...)`：空白可变成零，`NaN`/无穷值会穿透，超出安全整数的计数会丢失精度，非整数/负计数和负训练量也可能被公开。`JSON.stringify` 还会把 `NaN`/无穷 number 写成 `null`，使来源错误伪装为缺失证据。

共享响应 Schema 已对转换后的计数、测量和修订施加有限性/整数性/符号约束，但它无法恢复已经发生的整数精度损失，也不能证明构造器扫描了被截断的来源行。

## 决策

- 动作窗口与点计数只接受 PostgreSQL 风格十进制文本表示的安全非负整数；点 `total_set_count` 必须是正安全整数。
- 动作窗口与点的负荷、秒数和距离只接受有限非负十进制文本。
- 健康窗口计数只接受安全非负整数文本；可空最小值、最大值、平均值以及点规范/展示值只接受有限十进制文本。
- 健康数值允许负数且不实施按指标的正常/异常范围判断；统计 `null` 的既有缺失语义保持不变。
- 动作/健康修订必须是正安全整数。校验扫描全部来源行，包括隐藏第 181 点，并发生在任何数值转换、过滤、截断和摘要派生前。
- 参考时刻、时区和窗口身份的既有错误优先级保持；点时刻先于点数值，以保留第 122 轮错误语义。
- 保持 SQL、公开 Schema、数值精度、分页、响应形状、客户端、持久化、计划、AI 和健康解释不变。

## 影响

来源特殊值不能退化为 `null`，大计数不能静默舍入，训练负量和非法修订不能进入公开投影。合法 PostgreSQL 十进制文本保持兼容；健康有限负值不会被通用门禁误判为医学异常。

本决策证明单个来源数值可安全表示且满足最小字段语义，不证明完成组/总组、健康记录/统计、最小值/平均值/最大值之间的关系，也不证明数据真实、范围正常或趋势具有统计/医疗意义。
