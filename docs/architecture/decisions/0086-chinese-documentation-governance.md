# ADR-0086：用自动门禁约束新增中文项目记录

日期：2026-08-05

状态：已接受

## 背景

项目从第 030 轮开始把 `docs/PROJECT_STATUS.md` 逐字节镜像到本机 Obsidian，并要求每轮归档结构、设计、技术、功能、实现方法与经验。但此前的权威状态、路线图、架构和运行手册大多使用英文，CI 只检查 Markdown 格式，无法落实“所有新增记录使用中文”的项目要求。一次性翻译九十轮历史档案会制造无法可靠审阅的大范围语义改写，也会把语言迁移混入产品功能迭代。

## 决策

- 仓库状态继续是唯一权威来源，Obsidian 继续保存逐字节镜像；语言门禁不建立第二份状态数据。
- 第 091 轮先中文化四份活跃权威文档的一级、二级导航结构和项目状态模块总览，同时建立术语与迁移规范。详细英文正文按后续受控轮次迁移。
- 第 090 轮起的迭代档案和 ADR-0085 起的架构决策必须使用中文标题、中文日期/状态字段，并达到排除代码与链接后的最低中文正文数量及占比。
- `scripts/docs-language-policy.mjs` 保持无第三方运行时依赖；本地 `pnpm docs:check-language` 和 CI 使用同一实现。检查失败时不得进入后续质量门禁。
- 代码标识符、命令、路径、协议、Schema、环境变量、产品名和依赖审计原始级别可以保留英文；检查器必须排除代码块、行内代码、链接目标和 URL，避免用翻译技术字面量换取指标。
- 历史英文档案低于编号门槛时保持原样，直到单独迁移；门槛不得回退，新档案不得通过改名绕过编号约束。

## 影响

新增项目记录出现英文标题、英文元数据、正文过短或英文占主导时会在本地和 CI 明确失败。四份活跃文档的中文导航标题成为稳定契约，后续翻译正文时可以逐段推进而不改变链接与技术语义。

该检查只能发现结构与语言比例问题，不能证明翻译准确、术语选择正确或记录内容完整，因此人工审阅、迭代档案和验证证据仍是必要门禁。生产运行时代码、客户端产物、API、数据库和用户数据均不受本决策影响。
