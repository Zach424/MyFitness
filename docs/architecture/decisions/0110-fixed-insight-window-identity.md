# ADR-0110：非营养洞察固定窗口身份

日期：2026-08-10

状态：已接受

## 背景

Dashboard 趋势、动作洞察和健康洞察都返回三个统计窗口，生产构造器固定按 7、30、90 日生成。客户端和个人状态账本依赖 `days` 区分近期证据与较长历史范围。

三个共享 Schema 此前只要求数组长度为三，单项 `days` 属于 7/30/90 枚举；因此 `[7, 7, 90]`、`[30, 7, 90]` 或 `[7, 90, 30]` 都可通过基础校验。重复允许值会替代缺失窗口，错序则可能让按位置读取的消费者把统计值配到错误时域标签。营养窗口已由第 112 轮从合格 90 日序列逐字段重算，不存在同一缺口。

## 决策

- 共享 `fixedInsightWindowDays` 固定为 `[7, 30, 90]`，无依赖 refinement 按索引比较每个窗口的 `days`。
- Dashboard 在 `trends[index].days` 报告错误；动作和健康洞察在 `windows[index].days` 报告错误，统一消息为 `insight windows must use the fixed 7/30/90 order`。
- 动作/健康原有未来点校验继续在同一顶层 refinement 中执行；窗口身份错误不能跳过发生时间证据检查。
- 保持生产构造器、窗口统计 SQL、营养窗口重算、客户端、响应形状、持久化、计划算法和健康解释不变。

## 影响

三个非营养响应现在既必须有三个窗口，也必须各自占据唯一、固定的位置。替代适配器、错误夹具或未来模块抽取不能再用重复或错序的允许枚举伪装成完整时间证据。

本决策只证明窗口身份，不证明窗口统计的临床意义、模型阈值或用户理解。窗口聚合仍由数据库参考时刻资格保证，不从最多 180 个公开点反推；R-030/R-032 继续开放。
