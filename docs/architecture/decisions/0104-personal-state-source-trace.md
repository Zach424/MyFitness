# ADR-0104：个人状态只追溯到既有权威表面

日期：2026-08-10

状态：已接受

## 背景

`personal-state-ledger-v1` 已经把本人确认、确认记录、系统观察与确定性估计/Unknown 分开，并公开权威、快照和失效原因，但第 108 轮的四张卡仍是只读终点。用户知道系统为什么这样表达，却不能从该事实附近直接回到已有页面检查、纠正或删除来源。另建来源详情 API、复制记录摘要或给账本增加持久状态都会形成第二权威，也会扩大健康数据的路由、保留与删除边界。

现有客户端已经具备三个合适的所有者权威表面：计划列表与精确计划结果页、身体/恢复记录账本、跨领域历史日历。首页还通过 `useDidShow` 在从子页面返回时重新读取仪表板，并在刷新期间保留带标签的旧快照。因此最小控制应是确定性导航，而不是增加一套数据层。

## 决策

- 四类个人状态卡都成为具备 `button` 角色、键盘焦点、Enter/Space 激活和可见焦点的来源入口。视觉值保持为账本已经接受的同一快照，不在客户端重新推导健康状态。
- 本人确认已有反思时，入口只携带计划 UUID 与精确采用修订，进入现有计划结果页；没有反思时进入计划列表。确认恢复记录与恢复估计都进入现有记录账本；七天系统观察进入现有跨领域历史日历。
- 路由映射由纯函数 `personalStateSourceUrl` 负责并接受严格的 `PersonalStateLedger`。查询参数不携带健康值、体验内容、来源记录或 AI 结果；目标页面继续独立认证、读取和执行其既有纠正/删除权限。
- 导航成功不表示来源已读取或证据仍有效。返回首页后复用既有 `useDidShow` 重新取得原子仪表板；刷新期间旧快照仍可见但带有刷新状态，失败时保留旧快照并标为过期，只有成功响应才能成为新权威。
- 不新增 API、路由声明、数据库表、持久缓存、轮询、AI 调用、诊断、因果、依从性或自动计划适应。来源入口也不绕过目标页面的未知态、失败关闭、所有者、更正、删除和隐私生命周期。
- 浏览器测试统一从 `tests/e2e/runtime.ts` 取得隔离 API 地址；隐私测试的普通种子等待基础快照完成，显式离线注入保持独立失败/重试断言。测试只收紧可复现性，不放宽产品错误边界。

## 影响

用户现在可以从“我确认的体验”进入精确计划修订，从“确认记录”和“恢复估计”进入可更正/删除的记录权威，从“七天观察”进入跨领域日历。来源页面不会因为入口来自教练工作台而声明记录存在、完成、正确或最新；返回时也不会把一次导航冒充刷新成功。

实现只增加客户端纯映射和交互语义。最终 H5 总量/入口/最大异步 JavaScript 为 1,210,899/315,266/152,167 字节；WeApp 总量/vendor/最大页面为 1,108,121/19,338/57,302 字节，通过既有预算且没有提高门禁。WeApp 总量仍只余 879 字节，后续客户端表达必须继续先证明结构余量。

来源可达改善了 R-032 的可纠正性，但不能证明四类账本已经完整，也不能替代真实用户对知识类别、遗漏和时效的理解验证。下一轮应优先审计仪表板参考时刻的封闭性，确保所有来源事实都不晚于请求的 `at`，再考虑扩展个人状态表达。
