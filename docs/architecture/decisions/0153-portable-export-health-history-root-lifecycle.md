# ADR-0153：便携归档健康历史的同事务根生命周期

日期：2026-08-11

状态：已采纳

## 背景

第 155–158 轮分别建立只读 repeatable-read 流事务、可组合懒数组、64 KiB 单 payload 门禁，以及健康记录和健康修订两个 keyset 行源。两个行源各自正确，但各自开启事务；若直接同时放进一份 v4，第一字段和第二字段可能看到不同提交时刻。

仅把两个查询放进同一个异步生成器也不够。现有 JSON 取消可以关闭正在读取的懒数组，但第一字段已经结束、第二字段尚未开始时没有活动内层迭代器；若数据库事务仍由字段自己保管，外层下载取消可能留下暂停连接。反过来，若第二字段结束就让数据库源到达 EOF，后续静态 JSON 尚未完成时事务已经提交，也不符合“完整文件成功才发布快照收据”的语义。

## 决策

1. 新增 `createHealthHistorySnapshot()`，在一个延迟开启的只读 `REPEATABLE READ` 事务中只校验一次 active owner，随后按 v4 顺序交付 `healthRecords` 与 `healthRecordRevisions`。
2. 两个集合继续复用默认 25/最大 100 行、最大 64 KiB payload、UUID 锚点、数据库原生时间元组比较和页面完整性校验。原有两个独立单集合方法保持兼容。
3. 事务内部使用私有的行/字段边界事件。第一边界结束健康记录但不预取修订；第二边界结束修订但不推进数据库源物理 EOF。
4. 会话只允许两个集合各读取一次并严格按顺序读取。乱序、重复读取、来源边界错位或提前结束均失败关闭并回滚。
5. 统一收据保存共享 `batchRows`、`maximumPayloadBytes`，并分别记录两集合的 `batchCount` 与 `rowCount`；只有事务提交成功后才解析收据。
6. JSON 字节源新增显式根生命周期。所有 JSON 字节已经被消费、调用方继续拉取物理 EOF 时先调用 `complete()`，由协调器推进数据库源 EOF 并提交；任何来源错误、大小错误或调用方取消则把同一根错误交给 `cancel()`。
7. 根清理错误不得掩盖原错误；两者不同时按“原错误在前、清理错误在后”的 `AggregateError` 传播。正常调用方提前 `return()` 仍通过收据观察未完成错误。
8. 真实 PostgreSQL 必须证明跨字段并发隔离、双懒数组与 eager v4 字节相同，以及字段间取消时第二源尚未启动、事务回滚且 JSON/数据库收据同根失败。

## 影响

- 健康当前事实与其更正历史首次属于同一个数据库事实时刻，不再存在两个独立事务拼接造成的时间裂缝。
- 事务寿命从“最后一个数组结束”提升到“外层 JSON 根完成”；因此后续字段取消不能把一个不完整文件误记为已提交快照。
- 字段边界不读取下一集合的第一行，保留真正的字段级延迟加载，也使字段间取消测试可以确定第二查询尚未启动。
- 统一收据能按集合定位批次数和行数，但不包含用户标识、记录内容、游标或数据库连接信息。
- 事务可能跨越两个集合和其间 JSON 标点而更久保持连接；后续执行器必须结合租约、超时和容量测量，不能从本地测试推断生产并发能力。
- 其他十一个顶层集合、嵌套聚合和媒体仍未迁移；同步导出路径也没有切换，因此 R-013 继续开放。

## 备选方案

### 继续组合两个独立快照

拒绝。即使每个快照内部一致，两者仍可能看到不同提交时刻，无法声明一个文件代表一个事实快照。

### 第二集合结束时立即提交

拒绝。v4 在该字段后仍有其他字段；若其后编码失败或调用方取消，数据库收据会错误地领先于文件完成。

### 依赖活动懒数组的 `return()` 传播

拒绝。字段之间和最后懒字段之后都可能没有活动内层迭代器，必须由 JSON 根显式保管事务。

### 一次查询把两张表聚合为一个 JSON 对象

拒绝。它会把有界 keyset 与单 payload 门禁重新折叠成数据库端大聚合，失去字段级背压、批次收据和可复用迁移路径。

## 验证

- 单元测试必须证明两个集合共用一个流和一次 owner 校验，第二边界后尚未提交，根 `complete()` 后才提交并解析统一收据。
- 单元测试必须证明第一字段结束后的根 `cancel()` 回滚，并使统一收据使用调用方给出的同一错误对象。
- JSON 单元测试必须证明根 `complete()` 只在最后一块之后运行，提前停止调用 `cancel()` 且 JSON 收据保留同一取消原因。
- 真实 PostgreSQL 测试必须在第一字段完成后插入记录及修订，证明第二字段仍只看到原快照；新会话必须能看到新增行。
- 双懒数组的 43 字节块必须与 eager v4 逐字节相同；1 字节块字段间取消时修订迭代器不得开始，数据库与 JSON 收据必须对象恒等。
- 完整格式、类型、单元、集成、构建、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
