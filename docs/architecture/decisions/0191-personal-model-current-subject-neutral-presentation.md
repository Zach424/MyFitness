# ADR-0191：Personal Model 当前主题中性展示

日期：2026-08-12

状态：已接受

## 背景

第 196 轮已经建立当前主题的严格客户端适配和页面内存读取权限，但严格数据仍不能直接交给页面。字段名、置信等级和证据计数缺少产品语境时，容易被误解为表现评分、完成率、依从率或训练建议；空主题也可能被渲染成零，用户不同意或终态内容可能看似仍可驱动计划。

本轮只建立纯展示模型和未接线组件，不引入 API 调用、路由、React 状态或反馈操作。展示必须忠实反映严格视图中的事实与限制，并为后续独立页面提供一个不可绕过的中性表达边界。

## 决策

1. 展示模型只接受已经通过共享 Schema 的 `PersonalModelCurrentSubjectView`，不自行解析 unknown，也不读取内部 owner、前代或证据正文。
2. 空主题使用独立 empty 展示，明确“不是数值为零，也不代表系统已经了解”；不得生成虚构 item、证据或时间。
3. `training.availability` 只表达本人提交的可安排星期与单次时长，并明确不代表训练完成。
4. `training.recorded_frequency` 只表达完整观察周内的已记录中位数、范围和纳入课次数，明确未记录的现实训练不在范围。
5. `training.recorded_session_duration` 只表达已记录课次的样本数、中位数、四分位区间和覆盖周数，明确不评价训练效果、能力或强度。
6. candidate、active、disputed、superseded、invalidated 各有独立中性状态文案。candidate 不得驱动计划，disputed 明确用户不同意且不得驱动建议，两个终态明确不再作为当前计划依据。
7. 本人 feedback state 与系统 status 独立展示，不能用其中一个覆盖另一个；confirmed 也不自动提高或隐藏资料限制。
8. confidence 不显示百分比、分数或进度条。只显示“资料不足/覆盖较少/达到最低覆盖/覆盖较多”与全部限制标签；无额外限制时仍显式说明。
9. 证据使用合格、支持、冲突、撤回四个原始计数构成“证据刻度”，同时显示声明时区下的观察窗口和整理截止时间。刻度是分类计数，不计算比例或好坏。
10. 代次、修订、有效开始/结束与来源保留为次级元数据；不展示内部 UUID、策略版本或 EvidenceReference 正文。
11. 组件只接收展示 props，没有按钮、请求、状态 hook、缓存或持久化。语义根使用 group，状态提示使用 status，证据刻度与资料限制使用具名分组。
12. 视觉延续现有矿蓝、杜松绿、警示色和三类字体。唯一标志性结构是四格证据刻度；320–360 px 下变为 2×2，正文辅助文字不使用难读的微型字号。
13. 组件在页面接线前不得被生产路由导入，H5/WeApp 产物必须与第 196 轮逐字节相同。

## 影响

- 页面后续无需根据原始枚举拼接敏感文案，三个主题共享同一套事实、限制和时域表达规则。
- 空主题、资料不足、用户异议和终态不会被视觉压缩成普通成功卡片，也不会产生表现评分或处方暗示。
- 精确计数与窗口同时可见，有助于用户判断系统看到的只是记录范围；它仍不证明现实数据完整或用户理解正确。
- 未接线组件不产生新的网络、权限、缓存、包体或用户可见行为，下一轮仍需验证真实页面状态闭环。

## 备选方案

### 直接在页面 JSX 中格式化共享视图

拒绝。文案、安全限制和时区格式会与页面生命周期耦合，难以独立测试，也容易在第二个主题页面复制漂移。

### 把 confidence 显示为百分比或进度环

拒绝。当前契约只有受策略约束的离散覆盖等级，没有校准后的概率；百分比会制造不存在的精度和成绩感。

### 用单一“当前/失效”简化全部状态

拒绝。candidate、用户异议和两个终态拥有不同决策含义，压缩会隐藏资料不足或用户不同意。

### 本轮同时接 API 和路由

拒绝。先独立验证展示语义、字段完整性和双端结构，下一轮再单独处理进入、刷新、失败与卸载权限。

## 验证

- 纯展示模型覆盖空主题、三个 claim、声明时区、精确计数、用户异议、终态和禁用评分/建议措辞。
- 组件结构测试覆盖 group/status、证据/限制具名分组、无按钮/副作用/API 引用、共享令牌和 360 px 证据网格。
- 定向 2 个文件、11 项通过；客户端与工作区 typecheck 通过。
- 完整单元测试 112 个文件、672 项通过；完整 PostgreSQL 集成测试 29 个文件、174 项通过。
- H5/API/admin/WeApp 构建通过；客户端体积与第 196 轮逐字节相同。生产依赖审计保持 0 个 critical/high、9 个 moderate。
