# ADR-0140：共享读取权限内核与收紧客户端预算

日期：2026-08-11

状态：已采纳

## 背景

第 145 轮结束时，WeApp 总量为 1,108,452 字节，距离 1,109,000 字节门禁只余 548 字节。继续增加必要的隐私、安全或恢复能力容易被微小编译变化阻断。提高预算、缩短安全说明、删除失败状态或改变 Taro 模板递归都会隐藏交付成本。

产物归因显示最大页面仍低于页面预算，增长主要进入跨页面业务代码。源码审计发现十一种读取表面分别复制同一个离线/HTTP 4xx/HTTP 5xx/未知分类器，九种标准快照读取还复制同一个初始加载、就绪、刷新、初始错误和保留旧数据阶段函数。它们的产品文案和权限不同，但这两段判定完全相同。

## 决策

1. 新增无框架依赖的 `apps/client/src/lib/read-authority.ts`，只导出 `classifyReadFailure` 和 `snapshotReadPhase` 两个纯函数及其公共类型。
2. 十一种读取模型继续以原函数名和类型名对外导出，但把相同失败分类重新导出到共享实现；现有调用方和测试导入路径不变。
3. 九种标准快照读取以原函数名重新导出共享五阶段实现。聚合历史的 `continuing`、同意历史的 `collapsed/continuing/retained-stale` 等不同状态机保持独立，不为减少字节强行统一语义。
4. 页面自有错误文案、冻结权限、焦点、缓存、重试和生命周期逻辑不进入共享内核。共享函数不读取后端自由文本，也不增加持久化、轮询或后台重放。
5. 新共享测试覆盖全部失败分类和五个阶段；现有各表面测试继续通过，以证明原导出契约和行为等价。
6. 生产实测通过后，把 H5 最大异步 JavaScript 上限由 160,000 收紧到 152,000 字节，把 WeApp 总量上限由 1,109,000 收紧到 1,107,000 字节。H5 总量/入口和 WeApp vendor/页面上限保持不变。
7. 本轮不修改 React/Taro 版本、页面拆分、模板层级、用户文案、CSS、API、数据 Schema 或发布目标。

## 影响

- WeApp 总量由 1,108,452 降到 1,105,112 字节，减少 3,340 字节；vendor 不变，最大页面由 57,302 降到 56,943 字节。按收紧后的 1,107,000 字节门禁仍余 1,888 字节。
- H5 总量由 1,211,160 降到 1,206,969 字节，减少 4,191 字节；入口由 315,266 降到 315,262 字节，最大异步块由 152,167 降到 149,734 字节。按收紧后的 152,000 字节异步门禁仍余 2,266 字节。
- 失败分类和标准阶段的未来修正现在只有一个实现位置，但页面文案与权限仍由各自模型负责，避免形成过大的通用读取框架。
- R-009 获得结构性缓解但不能关闭；H5 入口仍高于 webpack 建议值，真实网络、浏览器缓存、微信开发者工具和真机加载没有被本地字节测量证明。

## 备选方案

### 提高 WeApp 总量预算

拒绝。它不会减少交付内容，只会让后续增长失去门禁。

### 缩短隐私、安全或失败文案

拒绝。产品语义是已验证行为的一部分，不能为了包体数字删除用户需要的边界说明。

### 使用更激进的压缩或后处理生成物

暂不采用。额外压缩配置可能改变 WXML 属性、模板或运行时语义，也会让源码和最终产物难以对应；当前重复实现已经提供可解释的源码级收益。

### 把所有读取状态机统一为一个框架

拒绝。聚合续页、同意历史和普通快照的阶段不同；强行参数化会扩大抽象、增加分支并模糊权限。只收敛完全相同的部分。

### 只共享类型，不共享运行时函数

拒绝。它能减少源码重复但不会恢复生产包体余量，也不能形成单一行为实现。

## 验证

- 客户端 strict 类型和全部客户端单元测试必须通过；共享测试覆盖失败分类与五阶段矩阵。
- H5/WeApp 必须从生产构建重新生成，并由 `myfitness-client-quality/v1` 按收紧预算验证。
- H5 入口、WeApp vendor 与页面预算不得回退；禁止验证运行时标记仍为零。
- 完整格式、类型、单元、集成、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
