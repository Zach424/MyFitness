# ADR-0196：Personal Model 本人校准界面

日期：2026-08-12

状态：已接受

## 背景

第 201 轮已经提供严格反馈 request/receipt 适配器和页面内存写权限，但用户仍看不到反馈入口，也无法确认系统整理的认识是否符合自己。服务端共享契约有四种选择，其中 `temporary_context` 必须携带用户明确指定的未来截止时间；在没有日期选择器和产品默认期限证据时，直接开放第四个按钮会迫使客户端臆造敏感语义。

反馈界面接入还会增加中文文案。Taro 默认把非 ASCII 字符转义为六字节序列，使 WeApp 总量超过既有预算；与此同时，工作站默认测试并发会让两项既有 CPU 密集用例在完整测试中超时，而同一用例单独执行稳定通过。两项工程约束都需要可复现处理，不能靠提高预算或偶发重跑掩盖。

## 决策

1. 当前页面只开放 `matches_me`、`disagree`、`uncertain` 三种完整合法选择，分别展示“符合我”“不同意”“暂不确定”。`temporary_context` 明确说明需要本人指定截止时间，并留待独立日期选择轮次；客户端不提供隐含默认期限。
2. 反馈入口只在当前主题存在非终态快照且读取处于 ready 时开放。提交期间冻结当前目标、主题切换、手动刷新和其他反馈按钮；终态、空主题、初始加载、过期快照及读取失败都不能写入。
3. 每次新反馈生成 UUID event，并把 `subjectKey + itemId + revision + eventId + choice` 固定在写权限收据中。网络未知或暂时服务失败只允许用户明确重试同一 event；页面不创建定时器、持久队列、路由参数或后台重放。
4. 最小写收据只证明精确命令已接受，不能代替完整当前视图。写入成功后显式重新请求当前主题；只有重读后的 `itemId + currentRevision + feedbackState` 与收据一致，页面才说明当前认识已经重新核对。重读失败时保留有界成功信息并要求手动更新。
5. 409 冲突不会把旧修订反馈重放到新修订。页面要求先读取最新认识，并在成功取得新快照后清除旧冲突；拒绝、无效收据、离线与服务错误使用不同的产品自有文案，原始服务正文不进入状态或界面。
6. 页面沿用“证据核对表”的既有视觉语言：在认识卡下方增加紧凑的绿色校准签署区，使用文本层级、边框、pressed 状态和可见焦点表达交互，不引入评分、完成度、情绪颜色或装饰图像。
7. 生产 Terser 输出设置 `ascii_only: false`，保留 UTF-8 中文而不改变内容语义、压缩算法或质量预算。该配置由回归测试固定；双端产物仍必须通过既有总量、入口、异步块、vendor 和页面门禁。
8. 根测试命令固定 `--maxWorkers=25%`，让完整 suite 在当前工作站资源压力下保持确定性。所有测试仍完整执行；定向测试、完整单元、完整 PostgreSQL 集成、typecheck 和生产构建继续分别保留证据。

## 影响

- 用户可以在当前三项认识上完成首个可见校准动作，异议和不确定不会被误写为确认。
- 成功状态来自服务端写收据与后续完整视图的两段证据，不会因为最小响应而伪造已刷新页面。
- `temporary_context`、reason、敏感 note、历史和回顾仍未开放，因此 P5 只是取得最小反馈闭环，不是完整认知镜子。
- 保留 UTF-8 后 WeApp 获得可测余量，但 H5 入口和最大异步块仍接近门槛；后续接线仍需逐轮实测。
- 降低测试 worker 会延长完整单元测试时间，但消除了并发资源争用造成的非业务超时，且没有减少测试范围。

## 备选方案

### 同时开放“只是暂时情况”并使用固定期限

拒绝。期限改变认识的失效语义，必须由本人明确选择；当前没有足够证据支持产品替用户决定七天、一个月或其他默认值。

### 写入成功后直接修改当前卡片

拒绝。最小收据不包含完整 claim、证据、限制与时域，客户端合成会让显示状态脱离服务端当前修订。

### 网络错误时自动重试

拒绝。虽然相同 event 支持幂等恢复，但敏感反馈必须由用户明确触发重试，页面不能在后台替用户继续提交。

### 提高 WeApp 总量预算

拒绝。超量主要来自中文字符转义而不是必要功能体积；保留 UTF-8 可以在不降低功能和不放宽门禁的情况下恢复余量。

## 验证

- 页面模型、事件生成、写权限与页面结构测试覆盖三种选择、temporary 延后、精确 choice 收据、同 event 重试、冲突重读、主题/卸载失权及零自动重放。
- 本地 H5 真实页面以已记录训练频次 R1 提交“暂不确定”，服务端生成 R2，重读后显示 `uncertain` 与完成文案；390 × 844 视口无横向溢出，三个按钮均为 304 × 46 像素，控制台无 error/warn。
- 完整单元、PostgreSQL 集成、strict typecheck、生产构建、客户端质量和依赖审计结果记录在第 202 轮档案与项目状态中。
