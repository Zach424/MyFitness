# ADR-0092：统一“我的”入口只编排权威页面，不复制敏感状态

日期：2026-08-06

状态：已接受

## 背景

产品信息架构把“我的”定义为个人资料、目标、单位、授权、导出和删除的统一入口，但首页此前直接跳到隐私页面。用户可以从隐私页再进入资料编辑，却无法先理解“计划依据”和“数据保管”是两个不同的权限边界；从其他页面进入时，“返回今日”文案也可能与真实上一页不一致。

资料/目标登记册和隐私保管清单都已经有严格的未读、已确认缺失、就绪、刷新、初始失败和旧快照权限。统一入口不能为了展示一张概览而复制这些请求、缓存敏感值，或把未知状态写成已完成、零数据和已授权。

## 决策

- “我的”作为首页同路由内的第三个本地标签实现，不新增完整 Taro 路由，也不发起资料、目标、授权、导出或数据清单请求。
- 一个纯 TypeScript 固定配置按“我提供的依据 → 我控制的保管”排列能力。资料、目标、单位/时区和安全边界只导航到现有建档页面；授权历史、便携导出和账户删除只导航到现有隐私页面。
- 入口只说明能力和边界，不显示完成率、当前修订、零值、授权状态或操作可用性；也不提供保存、撤回、导出和删除快捷按钮。对应权威页面仍须取得自己的当前读取权限后才能开放敏感操作。
- 建档和隐私页面的返回标签改为来源无关的“返回上一页”。导航仍使用平台页面栈，不在查询参数或持久存储中记录来源。
- H5/WeApp 相对第 096 轮增加 6,555/7,309 字节，总量达到 2,838,465/1,093,598 字节。总文件树预算分别增加 7,000/8,000 字节至 2,842,000/1,098,000；H5 入口/最大异步块和 WeApp vendor/最大页面预算保持不变。
- 真实托管部署仍依赖外部账号、域名、凭据和责任人，因此第 097 轮用于完成该本地关键闭环；部署和原生设备范围顺延至第 098/099 轮，不删除发布门禁。

## 影响

底部五个主要导航现在不仅有真实去向，也都先给出符合其用户问题的信息架构。“我的”不会把隐私页误写成全部个人设置，资料页和数据保管页也继续拥有各自的读取、变更和恢复权限。

目录的静态配置减少了文案与路由分散漂移，并由单元测试锁定完整能力集合和敏感操作归属。它仍不是账户概览；若未来需要显示资料修订或授权摘要，必须设计组合读取权限、失败状态和最小化响应，不能从两个页面状态中隐式拼接。
