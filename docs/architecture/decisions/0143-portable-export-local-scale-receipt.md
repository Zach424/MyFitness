# ADR-0143：便携导出本地规模测量收据

日期：2026-08-11

状态：已采纳

## 背景

ADR-0141 与 ADR-0142 已让同步便携导出在非媒体内容或某个真实媒体必然越过共享 50 MiB 上限时分阶段拒绝，避免不必要的对象读取、base64 和后续媒体处理。但 R-013 仍缺少一份可复现的账号规模、附件大小和进程内存证据，无法判断同步实现接近交付上限时的实际压力。

直接开始“异步加密归档”也不安全。现有持久任务只覆盖照片对象删除、照片前缀删除和账号擦除；仓库尚未定义归档所有者请求、状态转换、保留期限、加密密钥引用、下载授权、过期处置和账号擦除竞态。把本地对象路径或同步 Buffer 放进普通任务不能满足这些保管责任。

## 决策

1. 增加独立运维命令 `pnpm ops:measure-portable-export`，只允许 `postgres:`/`postgresql:` 且主机为 `localhost`、`127.0.0.1` 或 IPv6 回环的数据库 URL；对非回环目标必须在迁移或写入前失败关闭。
2. 命令创建随机合成用户，并通过一次 `generate_series` 写入 1–100,000 条已确认、无媒体、固定来源元数据的健康记录。它启动真实 Nest 应用，调用正式 `PrivacyService.portableExport` 和 `serializePortableExport`，而不是复制导出算法。
3. 运行结束无论成功或失败都删除该合成用户，依数据库所有者级联清理夹具；应用关闭失败不得掩盖数据库清理失败。该工具不得写入共享或远程数据库。
4. 输出严格的 `myfitness-portable-export-measurement/v1` 聚合 JSON 收据。收据只包含夹具类型/数量、接受后的附件字节数或既有固定 413、耗时、前后 RSS/heap 快照、进程生命周期最大 RSS、Node/平台/架构和固定限制；禁止账号 UUID、用户 ID、记录值和导出正文。
5. 收据必须固定声明：夹具没有媒体；`processMaxRssKiB` 是整个测量进程的高水位而非隔离的导出增量；本地测量不能外推为生产容量或 SLA。前后快照也受 JavaScript 垃圾回收和同进程框架成本影响，不作为预算门禁。
6. 本轮只建立风险测量，不修改公开 API、50 MiB 契约、客户端、数据库 Schema、持久任务类型或生产配置。异步加密归档必须在后续 ADR 中先定义完整保管契约，再实现持久状态。

## 影响

- 开发者可以用相同命令和显式记录数复现“数据库 → 服务 → Schema → pretty JSON/Buffer”路径，并获得不含敏感正文的机器可读收据。
- 2026-08-11 本地 Windows/Node 24.14.0 实测：25,000 条为 18,904,658 字节；65,000 条为 49,168,658 字节，即上限的 93.78%；70,000 条由固定 `portable_export_too_large` 拒绝。
- 65,000 条运行期间 RSS/heap 前后快照分别增加约 349.16/315.98 MiB，进程最大 RSS 为 1,115,600 KiB。这个结果证明接近上限时存在显著同进程内存压力，但不证明单次导出的独立峰值。
- 70,000 条拒绝运行的 RSS/heap 前后快照分别增加约 223.78/233.81 MiB，说明最终拒绝仍发生在数据库结果与对象图已经构建之后；本轮没有消除 R-013。
- 三档边界运行及最终 10 条轻量复核后，按夹具标记查询的健康记录残留为 0。该结果只证明本地清理路径，不取代生产数据保管审计。

## 备选方案

### 只用估算公式推导记录规模

拒绝。记录字段、UUID、时间、来源元数据、JSON 缩进和完整服务映射都会影响真实附件与内存行为；估算不能替代正式路径的可复现收据。

### 在单元测试里伪造大量对象

拒绝。这样无法覆盖真实 PostgreSQL 行映射、Nest 服务装配、契约解析和最终序列化，也不能形成面向运维的独立命令。

### 直接实现异步归档任务

本轮拒绝。没有密钥引用、授权、保留和删除责任的“归档”会制造新的敏感副本，却无法证明谁可下载、何时过期以及擦除时由谁删除。

### 把每次完整收据或账号 ID 写入仓库

拒绝。原始时间戳和逐次运行值没有成为版本控制资产的必要；权威文档只记录审阅后的聚合结果，机器收据不包含任何直接账号标识。

## 验证

- 纯测试覆盖记录数上下界、非 PostgreSQL/非回环拒绝、IPv4/IPv6 回环接受和严格收据无账号标识。
- 10 条最终轻量实跑必须成功生成收据，并以 SQL 证明夹具残留为 0。
- 25,000、65,000 和 70,000 条实跑分别形成中等规模、接近上限与固定拒绝证据。
- API strict 类型、完整单元/集成、完整 strict 类型、生产构建、格式、生产依赖、中文文档、迁移索引和 Obsidian 门禁通过后才允许提交。
