# ADR-0198：版本化 Muscle Model v1 共享契约

日期：2026-08-12

状态：已接受

## 背景

iLens 的动作肌群关联、肌群状态、训练量聚合、训练分析、人体 SVG、计划和 AI 查询都需要引用同一套身体部位。如果各模块使用中文标签、自由字符串或各自枚举，“中胸”“胸大肌中部”或大小写不同的英文键会成为不同实体，历史训练与新词表也无法可靠对账。

目标 `dataModel.md` 给出 5 个一级区域和 26 个细分项，其中“核心整体”是聚合概念，不应冒充单一可解剖测量的肌肉。当前仓库没有肌群数据库或动作关联；本轮需要先固定公共语言，同时避免把契约完成夸大成用户可见功能。

## 决策

1. 发布 `ilens-muscle-model-v1`，固定胸、背、肩/手臂、腿/臀、腹/核心 5 个一级 region，以及 26 个稳定小写 snake_case muscle ID。ID 是跨领域引用身份，中文名只用于当前版本展示，调用方不得用名称反查身份。
2. 每个定义必须具有唯一 `regionId`、中文名、`muscle_group|aggregate` 节点类型、至少一个 `front|back` 身体视图及 region 内从 1 开始的连续 `displayOrder`。一级 region 自身也有固定身份和顺序。
3. `core_global` 是 v1 唯一 aggregate；其余 25 项都是 `muscle_group`。aggregate 可作为汇总筛选，不得被动作主肌群权重、身体测量或解剖声明当成一块具体肌肉。
4. 常量与严格 Zod Schema 分为 `muscle-model.constants` 和 `muscle-model` 子路径。无 Zod 客户端可读取只读常量；需要处理不可信数据的服务/API 使用完整严格 Schema。根导出暂不加入，避免现有浏览器入口因一个尚未接 UI 的词表装载 Zod 和全部常量。
5. 完整 catalog Schema 要求精确版本、精确 region/muscle 数量、规范顺序和每个字段与 v1 常量一致。未知字段、别名式 ID、大小写漂移、重复视图、层级/名称/顺序/视图修改都失败关闭。
6. 同一版本禁止静默修改语义。新增、合并、拆分、改名或改视图时必须发布新版本，并在动作关联或持久化进入生产前设计显式兼容映射；不能原地编辑 v1 历史解释。
7. 本轮不定义动作 primary/secondary 关联、训练量权重、肌群状态、SVG path、医学解剖坐标、数据库或 HTTP。它们分别在后续纵向切片中消费该身份体系。

## 影响

- 后续 Training、Performance、Body State、Plan 和 AI 可以共享稳定 muscle ID，不再依赖界面中文标签。
- 前/后视图只表达未来人体图的可展示面，不是疼痛位置、医学边界或 SVG 几何定义。
- 词表是版本化产品语义；修正看似简单的名称或归属也必须经过版本迁移，而不能当作无影响文案修改。
- 用户当前仍看不到肌群信息，动作目录响应也没有关联字段；第 204 轮只能描述为 Muscle Model 契约基础。

## 备选方案

### 直接在动作定义中保存自由中文标签

拒绝。自由标签无法稳定关联人体图、历史训练、AI 查询或跨语言展示，也不能可靠检测重复和漂移。

### 用一级区域代替细分肌群

拒绝。它无法支持目标中的动作主/次肌群、细分训练量和肌群状态，同时会迫使后续再次迁移动作数据。

### 本轮同时实现动作关联和数据库

拒绝。词表身份、starter 映射、用户动作权限、修订历史和迁移策略是不同风险；先固定可测试语言，下一轮再独立验证持久化/API。

### 把人体 SVG path 放进 Muscle Model v1

拒绝。SVG 几何是客户端资产版本，不是领域身份；绑定会让纯视觉修改迫使领域词表升级。

## 验证

- 7 项定向契约测试覆盖完整 catalog、5 区域、26 个规范 ID、连续局部顺序、唯一 aggregate、未知/别名 ID、重复视图、错误层级、同版本漂移和未知字段拒绝。
- `@myfitness/contracts` strict typecheck 与 build 通过；完整工作区单元测试为 121 个文件、782 项，全工作区 typecheck 通过。
- OpenAPI、数据库与客户端均未修改；本轮没有 HTTP、迁移、集成或浏览器行为声明。
