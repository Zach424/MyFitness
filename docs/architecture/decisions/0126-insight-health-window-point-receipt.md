# ADR-0126：健康 90 日窗口与点截断收据

日期：2026-08-11

状态：已接受

## 背景

健康洞察分别查询 7/30/90 日完整窗口聚合与最多 181 个 90 日点。已有门禁验证窗口行内部关系、点行上限和公开 `hasMore` 的局部形状，但没有把 90 日 `recordCount` 与点收据绑定。替代适配器可以声称窗口有记录却返回空点，也可以在少于 180 条时丢点，或让 `hasMore` 与完整计数矛盾。

真实窗口和点 SQL 使用相同的所有者、精确指标、`confirmed`、未删除、`occurred_at <= at` 与 `occurred_at >= at - 90 days` 资格边界。窗口计数是完整集合大小；点查询以 181 行作为“180 个公开点 + 一条更多证据”的收据。

## 决策

- 在纯构造器完成原始点有效性、顺序、唯一性、未来过滤和最多 181 行检查后，读取 90 日窗口的安全 `record_count`。
- 当 `recordCount <= 180` 时，合格来源点行数必须精确等于 `recordCount`；当 `recordCount > 180` 时，来源必须恰好包含 181 行。多取、少取或窗口/点资格漂移都失败关闭。
- 缺失 90 日来源行继续按现有稀疏规则解释为零窗口，但只有合格点也为零时才合法；有点却缺窗口不再静默生成矛盾响应。
- 共享响应 Schema 独立要求 `series.length === min(recordCount, 180)`，错误定位到 90 日 `recordCount`；同时要求 `hasMore === (recordCount > 180)`，错误定位到 `hasMore`。
- 保留通用 `hasMore:true` 必须有完整 180 点前缀的门禁。`hasMore:false + 180 点` 只有在 90 日完整计数恰为 180 时合法，不再依赖不可区分假设。
- 不从 181 行有限前缀推断超过阈值后的具体记录，不重算窗口最小值、最大值或平均值，不补零、不改 SQL、响应形状、分页、客户端、历史值、计划、AI 或医疗解释。

## 影响

90 日完整聚合、来源查询收据、公开前缀和更多标志形成一条可执行证据链。少报、过取、漏窗和错误 `hasMore` 无法各自通过局部门禁后组成矛盾响应。

来源窗口仍可稀疏，以保留既有替代适配器回退；但稀疏只代表真实空集合，不能掩盖已经出现的点。响应形状不变，现有客户端无需调整。

本决策不证明 7/30/90 日嵌套窗口集合单调、窗口统计由点前缀重算、记录真实、设备准确、健康范围或趋势意义。
