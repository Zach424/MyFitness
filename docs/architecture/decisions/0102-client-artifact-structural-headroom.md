# ADR-0102：以平台原生压缩和异步缓存边界恢复客户端余量

日期：2026-08-10

状态：已接受

## 背景

第 106 轮结束时，H5 最大异步 JavaScript 为 202,930 字节，距离 206,000 字节门禁只余 3,070 字节；WeApp 总量为 1,109,995 字节，距离 1,110,000 字节门禁只余 5 字节。继续添加个人状态、证据来源或纠正能力会被代码哈希和微小模板变化阻断。直接提高预算、降低模板递归层级，或者删除隐私、安全、失败关闭与无障碍语义都会隐藏真实交付成本。

现有 H5 `client-async-shared` 同时承载项目共享代码和 Taro 组件运行时，形成单个 202,930 字节块。WeApp 的 `base.wxml` 保留构建格式空白；本地 Taro 4.2.1 构建器已经提供 `minifyXML.collapseWhitespace`，无需引入额外压缩器或重写产物。

## 决策

- 在 H5 `splitChunks.cacheGroups` 中新增 `taro-components`：只匹配 pnpm 依赖图中的 `@tarojs/components`，使用异步块、强制复用和优先级 20。发生时间组件继续使用优先级 30，通用 `client-async-shared` 保持优先级 10；入口和页面业务边界不改变。
- 在 WeApp 平台配置中启用 Taro 内建 `minifyXML.collapseWhitespace`。不降低 `baseLevel`，不后处理已生成文件，不更改组件、属性、模板递归或运行时权限。
- 把 H5 最大异步 JavaScript 入库上限从 206,000 收紧到 160,000 字节，把 WeApp 总量上限从 1,110,000 收紧到 1,109,000 字节。H5 总量/入口和 WeApp vendor/页面上限保持不变；预算只能由后续显式 ADR 调整。
- H5 路由仍可先展示页面壳层再完成隐私概览读取。需要直接修改测试数据库并立即刷新的浏览器用例，必须先等待其保管总数证据完成，避免测试自己的导航取消被误报为产品请求失败。
- 本决策属于 K（基础设施）。它只保护未来认知能力的工程带宽，不新增用户事实、系统观察、估计、AI 结论或计划调整。

## 影响

H5 最大异步 JavaScript 降到 151,816 字节，比第 106 轮减少 51,114 字节；入口从 315,089 变为 315,266 字节，总量从 1,210,241 变为 1,210,470 字节。多出的约 50 KiB `taro-components` 请求是可缓存的异步平台运行时，未进入首屏入口；完整 Chromium 95/95 证明当前路由加载和交互未回归，但仍需代表性网络条件与浏览器复核缓存收益。

WeApp `base.wxml` 从 61,611 降到 59,834 字节，生成内容不含换行或连续格式空白；总量降到 1,108,179 字节，比第 106 轮减少 1,816 字节，vendor 与最大页面 JavaScript 不变。当前证据只覆盖 Taro 编译和静态质量门禁，不能代替微信开发者工具与真机加载、模板递归和无障碍检查。

预算收紧使移除本轮优化会立即失败，而不是重新回到 5 字节余量的表面通过。WeApp 在新内部预算下仍只余 821 字节，后续客户端功能仍需逐轮测量；内部预算不是平台极限，也不授权通过提高阈值吸收无界增长。
