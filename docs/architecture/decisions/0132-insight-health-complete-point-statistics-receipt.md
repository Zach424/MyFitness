# ADR-0132：健康未截断窗口与点统计收据

日期：2026-08-11

状态：已采纳

## 背景

健康洞察已经用 90 日 `recordCount` 证明：记录数不超过 180 时，公开点是完整规范值集合；超过 180 时，公开点只是有限前缀。但窗口 minimum、maximum 与 average 仍可能和完整点集合矛盾。

数据库审计确认健康规范值为 `NUMERIC(14,4)`，窗口使用 PostgreSQL `MIN`、`MAX` 和 `AVG`，点查询返回相同 `canonical_value`。来源适配器会把十进制文本转成 JavaScript `Number`；公开窗口统计统一舍入到四位小数，而点值已经是四位持久化规范值。负数虽然不是常见体重等业务值，仍是契约允许的有限历史事实，完整性门禁不能借机增加医疗范围规则。

## 决策

1. 只有当 90 日 `recordCount <= 180` 且点数收据已证明来源/响应点集完整时，才执行统计收据；超过 180 时立即跳过。
2. 来源层从全部 `canonical_value` 点计算 minimum、maximum 与 average，并与 PostgreSQL 统计比较。
3. 来源允许的误差只由 `Number.EPSILON × max(1,|窗口统计|,点绝对值和,|复算统计|) × (点数+2) × 4` 推导；不使用任意业务容差。
4. 响应层同样从全部 `canonicalValue` 点复算三项统计。公开窗口统计已舍入到四位小数，因此允许 0.00005 半单位，再叠加同形式浮点误差。
5. 三类冲突分别定位到 90 日窗口 `statistics.minimum`、`statistics.maximum` 或 `statistics.average` 并失败关闭；来源冲突使用一个领域级统计收据错误。
6. 门禁不自动改值、不从截断前缀重算窗口、不增加正值/正常范围、趋势或医疗判断。

## 影响

- 未截断健康窗口的三项统计与完整规范值集合形成可验证收据。
- PostgreSQL 高精度平均转成二进制浮点，以及公开四位舍入造成的合法差异不会被误拒绝。
- 181 条截断响应明确不声称可以由公开前缀复算完整窗口。
- 合法负值继续通过，避免完整性检查扩张成未经设计的范围校验。
- 下一步仍需独立核对 `recordedDays` 与完整点的响应时区本地日集合。

## 备选方案

### 对所有统计使用严格浮点相等

拒绝。高精度 PostgreSQL AVG 转成 `Number`，以及公开四位舍入，都会产生可推导的微小差异。

### 使用固定宽松容差

拒绝。容差必须由持久化/公开精度、数值幅度和点数推导，不能掩盖任意错配。

### 截断时也比较前 180 点

拒绝。有限前缀不是完整集合，无法支持窗口极值或平均结论。

### 顺便拒绝负健康值

拒绝。这是数据完整性收据，不是指标范围或医疗语义设计。

## 验证

- 来源层覆盖 minimum、maximum、average 三类错配、精确两点集合、181 条跳过和合法负值。
- 响应层覆盖三类精确字段错配、四位小数舍入边界、181 条跳过和合法负值。
- 真实 PostgreSQL 场景直接从全部公开 `canonicalValue` 复算三项统计并与 90 日窗口相等。
- 定向、完整单元、完整集成、严格类型、文档语言/迁移和 Obsidian 镜像门禁通过。
