# ADR-0134：健康完整点集与短窗口子集收据

日期：2026-08-11

状态：已采纳

## 背景

健康洞察已经在 90 日 `recordCount <= 180` 时证明公开点集完整，并分别核对该窗口的 minimum、maximum、average 与 `recordedDays`。然而 7 日和 30 日窗口仍只受跨窗口单调关系约束；一组错误的短窗口计数、记录日或统计仍可能同时满足单调性。

健康窗口 SQL 以同一个参考时刻 `at` 和闭区间 `occurred_at >= at - days`、`occurred_at <= at` 计算 7/30/90 日结果。90 日点查询使用相同的上界和 `at - INTERVAL '90 days'` 下界，因此未截断的 90 日点集足以重建两个短窗口。响应的 `generatedAt` 与来源参考时刻相同，逐点 `occurredAt` 已经受有效时刻、未来点、顺序和身份收据保护。

## 决策

1. 只在 90 日 `recordCount <= 180` 且既有点数收据已经证明点集完整时执行短窗口子集收据；`recordCount > 180` 时来源与响应都完整跳过。
2. 来源层从完整 90 日来源点按绝对时刻闭区间 `occurred_at >= at - days` 分别筛出 7 日和 30 日子集；响应层从 `generatedAt` 和逐点 `occurredAt` 使用相同毫秒边界重建子集。
3. 每个短窗口的 `recordCount` 必须精确等于子集点数；`recordedDays` 必须精确等于子集按响应 IANA 时区投影后的去重本地自然日数量。
4. 非空子集的 minimum、maximum 与 average 必须由规范值复算。来源沿用十进制转 `Number` 后按幅度、绝对值和点数有界的 IEEE 误差；响应沿用四位小数的 0.00005 半单位并叠加相同形式的浮点误差。
5. 空子集继续要求零 `recordCount`、零 `recordedDays` 和三个 `null` 统计；负值仍是合法测量，不增加医疗范围判断。
6. 恰好位于 7/30 日下界的点属于短窗口，下界前 1 ms 的点不属于该窗口；上界继续由既有未来点收据保护。
7. 冲突失败关闭：来源分别报告短窗口点数、记录日或统计收据错误；共享 Schema 定位具体短窗口字段。两层均不自动修改窗口、点、单位或日期。
8. 不修改 SQL、公开响应形状、客户端、趋势语义或医疗解释。若未来数据库会话、时间计算或适配器产生不同边界结果，应暴露冲突而不是放宽收据。

## 影响

- 未截断健康洞察的 7/30/90 日窗口都能由同一完整证据集合复算，不再只依赖单调关系。
- 边界时刻、空短窗口、同日多点、夏令时和负数值获得可重复的来源/响应双层证明。
- 181 条截断响应明确不声称公开前缀能证明任何短窗口，即使最新 180 点看似全部落在短窗口内。
- 统计收据仍只验证数据一致性，不把观察值解释为正常范围、改善、恶化、诊断或建议。
- 每次请求最多对 180 个点执行两次线性筛选与聚合，保持有界成本；日期格式化继续复用既有请求级格式器。

## 备选方案

### 只保留跨窗口单调性

拒绝。单调性只能发现顺序矛盾，不能证明任何短窗口恰好对应其时间子集，也不能约束 average。

### 分别查询 7 日和 30 日点集

拒绝。现有未截断 90 日集合已经包含所需证据；新增查询会扩大数据库工作和快照不一致面，且不改善公开契约。

### 使用本地日历日而非绝对 24 小时边界筛选

拒绝。生产 SQL 使用 `make_interval(days => windows.days)` 作用于带时区参考时刻，当前数据库会话实测为 UTC；收据必须匹配实际绝对时刻边界，而记录日去重才使用响应时区。

### 从公开 180 点前缀始终复算短窗口

拒绝。90 日截断意味着更早记录仍可能落入 7 日或 30 日窗口，有限前缀不能证明计数、记录日或统计完整。

### 用跨窗口 average 单调性替代子集复算

拒绝。加入更早的高值或低值都可能使 average 上升或下降；只有对应点子集的复算结果是有效收据。

## 验证

- 来源和响应单元测试覆盖 7/30 日边界、边界前 1 ms、计数错配、记录日错配、统计错配、空短窗口和截断跳过。
- 原有 average 非单调夹具改为三个真实时间子集，证明平均值无需跨窗口单调，但必须与各自证据集合一致。
- 真实 PostgreSQL 场景逐窗口从公开点重算点数、记录日和三项统计；本地会话时区与夏令时参考边界另行审计。
- 定向、完整单元、完整集成、严格类型、格式、生产依赖、中文文档、迁移索引和 Obsidian 镜像门禁通过后才允许提交。
