# ADR-0100：计划结果回看使用独立页面与独立读取权限

日期：2026-08-10

状态：已接受

## 背景

第 104 轮把历史采用修订的结果回看直接展开在周计划页。该最小实现证明了精确修订、撤销证据和失败关闭语义，但 WeApp 计划页 JavaScript 达到 62,998 字节，距离 63,000 字节门禁只剩 2 字节。下一步若继续在同一同步页面加入用户反思，会迫使提高预算、删除安全文案或让计划页承担更多互不相同的读取状态。

结果回看本身是一项短生命周期的精确读取：用户选择一个当前或历史采用修订，核对证据后返回计划。它不需要和计划生成、采用、训练关联、AI 边注与历史分页共享一个 React 状态树。

## 决策

- 新增 Taro 路由 `pages/plan-outcome/index`。当前采用卡与每条历史 `accepted` 修订只保留轻量入口，并通过计划 UUID 与正整数修订进入同一页面；URL 不携带健康值、训练内容、恢复记录或用户笔记。
- 独立页面只调用现有所有者作用域精确路由 `GET /plans/weekly/:planId/history/:revision/outcome`。直接访问、错误参数、外部所有者或非采用修订都不能绕过 API 权限；无效参数不发起读取。
- 页面以“生成依据 → 你的决定 → 后续确认”三段证据轨展示精确版本、观察窗、替代、当前确认来源和撤销计数。撤销项位于证据轨之外，Unknown/Observed 与非因果边界保持不变。
- 初始读取、失败、重试与就绪互斥。失败不显示空结果或原始服务消息，H5 把焦点交给重试；进入页面后返回按钮延迟获得焦点。单调递增的页面内存代次拒绝卸载后的迟到响应，不增加轮询、持久缓存或后台重放。
- 周计划页不再保存或渲染完整 `PlanOutcomeReview`，即使列表响应仍兼容携带该投影。结果状态和来源只在用户明确进入独立页面后展示。
- 不提高 H5/WeApp 入库预算。页面视觉保留衡迹的矿物蓝、雾灰、度量字体与纵向证据轨，去除独立 ScrollView、重复装饰和非必要排版层，以包体门禁约束设计复杂度。

## 影响

计划页最大 JavaScript 从 62,998 降至 57,400 字节，恢复 5,600 字节页面余量；当前与历史回看共享同一专用读取表面，错误状态不再嵌套在历史列表中。用户返回后仍保留计划页的滚动与内存状态，回看页面卸载即丢弃结果。

新增完整 Taro 路由仍有运行时与样式固定成本。WeApp 总量最终约为 1.108 MB，只剩约 1.6 KB 入库余量；因此这次拆分解决的是“单页同步增长”而不是全部包体压力。第 106 轮用户反思必须复用该页面，并先减少或延迟现有代码，不得再新增完整路由或放宽预算。查询参数中的计划标识可能进入 H5 浏览器历史，但不包含健康内容；若未来威胁模型把聚合 UUID 也列为不可留存标识，需要改用短生命周期导航通道并单独验证刷新行为。
