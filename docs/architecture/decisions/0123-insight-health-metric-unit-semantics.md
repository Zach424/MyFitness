# ADR-0123：健康洞察指标单位语义一致性

日期：2026-08-11

状态：已接受

## 背景

健康洞察已拒绝未知单位代码，并要求所有合格点共用一个规范单位，但这仍允许所有体重点一致使用 `cm`。领域归一化早已为九个指标定义规范单位和允许展示单位；共享响应契约若复制同一张表，会在新增指标时产生漂移。

ADR-0002 把完整指标定义放在无框架领域包。跨传输边界也需要的单位身份是其中稳定、无范围判断的子集，适合提升为 contracts/domain 共用常量；范围、整数、换算和可接受值仍属于领域规则。

## 决策

- 在无依赖 `health-record.constants` 中新增完整覆盖九个指标的 `metricUnitDefinitions`，每项只包含 `canonicalUnit` 与 `allowedUnits`，并由 TypeScript `satisfies` 检查指标和单位枚举覆盖。
- 领域 `metricDefinitions` 展开共享单位身份，再追加既有 min/max、整数和换算行为；归一化输出不变。
- API 构造器用领域定义扫描全部原始健康点；规范单位必须等于精确指标定义，展示单位必须属于允许集合。未来点和隐藏第 181 点同样受检。
- 共享健康响应 Schema 用同一常量逐点独立验证规范/展示单位，并在精确字段路径报告错误。
- 来源凭据门禁改为复用公开健康点所组合的 confirmed 来源、记录时区和单位子 Schema，避免重复执行完整点的 UUID、日期与数值格式化。完整单元超时必须通过减少重复工作解决，不提高测试超时。
- 不验证数值范围、整数性或展示/规范值换算，不转换、删除或修复历史值；保持 SQL、响应形状、分页、客户端、持久化、计划、AI 和健康解释不变。

## 影响

指标单位身份只有一份跨层权威，已知但语义错误的单位不能通过全序列一致性。领域写入归一化与只读洞察使用相同单位集合，同时保持范围和换算规则只在领域层。

来源门禁的精确子 Schema 复用把完整单元恢复到既有 5 秒上限内，且没有减少隐藏点覆盖。

本决策不证明展示值和规范值互相换算正确、持久化值真实、范围健康、设备准确或趋势具有医学意义。
