# ADR-0127：健康跨窗口集合单调性

日期：2026-08-11

状态：已采纳

## 背景

健康洞察已固定 7/30/90 日窗口身份，并验证单个窗口内的计数、统计存在性与 `minimum <= average <= maximum`。第 132 轮还绑定了 90 日完整计数、有限点收据和 `hasMore`。但来源适配器或替代实现仍可能返回彼此不可能同时成立的嵌套窗口，例如 30 日记录少于 7 日记录，或 90 日最小值高于已有的 30 日最小值。

窗口平均值不具有集合包含下的单调性。稀疏来源也可能真实缺少较短窗口行，因此不能把“来源缺行”本身一律判为错误。

## 决策

1. 来源层先把缺失的 7/30/90 日窗口按既有语义归一为 `recordCount = 0`、`recordedDays = 0`、`minimum/maximum/average = null`，再按固定 7→30→90 顺序比较相邻窗口。
2. 随窗口增大，`recordCount` 和 `recordedDays` 必须非递减。
3. 较短窗口非空时，较长窗口必须有统计值，并满足较长 `minimum <=` 较短 `minimum`、较长 `maximum >=` 较短 `maximum`。
4. average 不参与跨窗口单调性；它仍只受单窗口统计次序约束。
5. 共享响应 Schema 独立执行相同关系校验，并把问题精确定位到较长窗口的 `recordCount`、`recordedDays`、`statistics.minimum` 或 `statistics.maximum`。
6. 任一冲突失败关闭；不补造统计、不自动修正值，也不修改 SQL、响应形状、分页、客户端或历史记录。

## 影响

- 7/30/90 日健康窗口不能再表达违反嵌套集合关系的计数、记录日和极值边界。
- 较短窗口真实为空时仍允许较长窗口存在记录，保留稀疏来源的可逆回退。
- 规则不会把平均值波动误判为证据错误，也不会生成改善、恶化、正常、异常或医疗结论。
- 本决策不证明动作洞察收据一致、查询完整、记录真实、设备准确、健康范围、趋势意义或用户理解。

## 备选方案

### 只在客户端显示前排序或修正窗口

拒绝。这样会隐藏服务端证据矛盾，并让不同客户端获得不同事实。

### 要求三个来源窗口必须全部存在

拒绝。现有来源边界明确支持缺行回退；零记录的较短窗口并不必然与较长窗口有记录冲突。

### 同时要求 average 单调

拒绝。嵌套集合的平均值可以随新增样本向任一方向变化。

## 验证

- 来源层覆盖计数减少、记录日减少、最小值升高和最大值降低四类失败。
- 响应层覆盖同四类失败及精确问题路径。
- 合法平均值 70→71→69 保持通过。
- 定向、完整单元、完整集成、严格类型与真实 PostgreSQL 验证通过。
