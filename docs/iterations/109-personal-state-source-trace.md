# 第 109 轮：个人状态证据来源追溯

日期：2026-08-10

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 J（用户体验）。范围只有一个有界控制：把教练工作台的四张个人状态卡变成可访问的既有来源入口，并在返回首页时重新读取同一原子仪表板。本人确认已有反思时必须进入精确计划结果页，没有反思时进入计划列表；确认恢复记录与恢复估计进入记录账本；七天观察进入跨领域历史日历。

验收要求固定为：点击、Enter 和 Space 等价；路由不携带健康内容；目标页面继续独立认证和读取；返回后由既有 `useDidShow` 刷新，旧快照在刷新/失败期间明确保留或过期；导航成功不得冒充新鲜证据。不得新增 API、路由声明、存储、缓存、轮询、AI、医疗、因果、依从性或自动计划适应，也不得提高客户端预算。完整测试、文档、Obsidian、Git 提交与推送必须通过。

视觉设计继续使用既有证据卡，不加入新的按钮条、图标、评分颜色或页面。整张卡是来源入口，屏幕阅读器名称以“当前值；检查来源”表达动作；可见内容保持简短，避免在只余有限 WeApp 空间时重复权威说明。

## 3. 实现方法

### 用纯映射追溯，不复制来源

`personalStateSourceUrl` 只读取已经通过共享契约的账本。计划反思存在时生成 `/pages/plan-outcome/index?planId=...&revision=...`；不存在时返回计划列表。确认记录和恢复估计返回记录页，七天观察返回历史页。计划标识经过编码，修订来自正整数契约；健康值、反思选择和记录引用都不进入 URL。

### 让目标页面继续拥有权限

入口不向目标页面传递“已确认”“有记录”或“可更正”等状态。计划结果、计划列表、记录和历史页面各自重新执行所有者、读取权限、失败关闭与更正/删除规则。教练页只提供方向，不成为这些事实的新权威，也没有新增返回来源专用状态。

### 把返回刷新与导航分开

首页已有 `useDidShow` 前台读取；从来源页返回会重新调用仪表板。刷新时仍渲染上一份已接受快照并标记刷新，失败时标记过期，成功后才替换。本轮 E2E 以请求计数证明返回触发了新读取，但不把请求发出或路由恢复视为刷新成功证明。

### 保持跨端无障碍与包体边界

证据卡保持 `View`，通过共享 `buttonActivationProps` 获得跨 H5/WeApp 的角色、焦点和键盘激活，避免引入新的按钮样式或组件。实现同时移除客户端重复的 `generatedAt`/趋势快照字段并压缩重复说明，最终 WeApp 总量比第 108 轮减少 795 字节，没有提高预算。

### 把测试环境本身纳入证据质量

完整回归先暴露三类非产品失败：重复文本的严格定位器歧义、onboarding 独有旧环境变量造成的 3100/3110 分叉，以及隐私主动重载取消尚未完成请求。修正分别是限定语义目标、统一 `runtime.ts`、等待普通基础快照并让离线注入保持独立。隐私成功/离线路径随后连续 6/6，通过后完整套件单次 95/95；没有用重试拼接全绿，也没有把未知网络错误整体加入白名单。

## 5. 发现的问题与经验

- 写出来源名称不等于提供用户控制。最小有效追溯是到达已有权威表面，并让该表面继续拥有读取、更正和删除权限。
- 来源入口不能携带事实结论。URL 只需要定位计划修订或固定页面；把健康值或“已确认”状态塞进参数会制造可伪造的第二状态。
- 返回触发请求不代表刷新成功。旧快照必须继续带有刷新/过期标签，只有新原子响应可替换权威。
- 跨端可访问交互可以复用现有激活契约，不必为卡片引入更重的组件；可见焦点仍需要明确纳入样式选择器。
- 测试运行时是证据链的一部分。一个测试文件独自读取旧端口变量，就能让本地残留服务产生似乎属于产品的 404；端点必须来自单一运行时来源。
- 主动导航取消请求是可观察竞态。等待普通权限快照完成比忽略所有 `ERR_ABORTED` 更严格；故障注入则必须保留自己的失败断言，不能被公共成功等待吞掉。
- WeApp 余量改善但仍很小。删重复字段和文案可以为高价值控制腾出空间，但不是无限增长许可。

## 6. 全局状态、项目反思与下一步

本轮把个人状态账本从“可解释的只读汇总”推进到“可返回权威表面检查”的最小用户控制。系统没有复制记录，也没有因为用户点开来源就声称证据最新；这使来源、纠正和删除继续沿原有隐私生命周期生效。

全局反思发现下一个更基础的问题位于时间边界：历史 `at` 查询必须保证每一类仪表板来源都不晚于参考时刻，不能只限制计划反思而让未来发生记录或随后变化泄漏进旧快照。第 110 轮应归类为 B（时间建模），审计并失败关闭 Dashboard 的参考时刻封闭；先在 SQL 与投影测试中证明健康、训练、饮食、恢复和计划体验都满足 `occurred_at/updated_at <= at` 的资格，再考虑更多个人状态功能。

R-032 仍未关闭：来源可达不能证明账本完整或真实用户理解正确。R-009 仍要求代表性浏览器与微信真机加载证明；R-030/R-031 仍要求真实纵向校准和非因果理解。风险登记册全表时效复核及所有需要账号、预算、域名、凭据或责任人的托管工作继续停放。
