# 第 148 轮：便携导出媒体展开的常数时间精确字节下界

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 R（Risk Reduction）。范围只包含同步便携导出在媒体对象读取后的精确增量、base64 分配前拒绝、后续媒体停止读取、常数时间算法、纯测试、真实 PostgreSQL/私有对象存储集成测试和相应文档；不包含公开 API/Schema、数据库字段、媒体顺序、部分导出、并发读取、流式响应、后台归档、压缩、加密、客户端、云服务或真实设备。

验收标准固定为：增量必须只依本次真实 Buffer 长度或实际 `ENOENT`，不得使用数据库 `byte_size`；对当前全部媒体结果，运行下界必须与最终 pretty JSON UTF-8 字节逐字节等价。每个媒体只能做 O(1) 计数，不得重序列化整份导出。首个对象使下界超限时必须返回既有固定 413，读取次数为一、base64 次数为零、后续对象不读取；精确等于上限继续执行，正常导出与最终控制器门禁保持不变。

## 2. 项目结构、设计、技术与实现功能

- `apps/api/src/privacy/portable-export-artifact.ts`：公开数值字节断言；用同层级规范 JSON 包装器计算空 base64/不可用媒体相对 `null` 的固定增量，并用 `4 * ceil(sourceByteLength / 3)` 追加真实 base64 字符数。
- `apps/api/src/privacy/portable-export-artifact.test.ts`：覆盖七个 Buffer 长度、食物/进度两类集合、不可用结果、非法长度和精确数值边界，直接对比完整最终格式字节。
- `apps/api/src/privacy/privacy.service.ts`：从初始完整下界开始累计已处理媒体的精确增量；提取一次共享媒体读取函数，成功对象在 base64 前检查，`ENOENT` 在发布不可用标记前检查，两类集合保持原顺序。
- `apps/api/src/privacy/privacy.integration.spec.ts`：通过正式上传路径创建两个真实净化照片，监听真实对象读取和当前 Buffer 的 base64 调用；首个增量被测试门禁拒绝后证明读取 1 次、编码 0 次。
- ADR-0142、架构、隐私所有权模型、路线图、R-013 与项目状态同步记录分阶段门禁和剩余风险。

本轮没有修改数据库 Schema、公开 API/OpenAPI、客户端、UI、路由、产品文案、照片保留/删除权限、擦除流程或 AI 行为。

## 3. 实现方法

### 从完整下界维护单调运行值

第 147 轮的完整 `media: null` JSON 字节数是起点。每处理一个有存储键的照片，只把该条目的实际最终表示相对 `null` 增加的字节加入运行值；尚未处理的条目继续由 `null` 代表。因此任一时刻的运行值都是“已处理媒体使用真实结果、未处理媒体使用最小结果”的完整最终下界。

### 由规范格式计算包装，而不手写魔数

规范包装器使用 `{ data: { photos: [{ media }] } }`，使 `media` 与 v4 中食物/进度照片条目处于相同缩进深度。模块加载时分别格式化 `null`、空 base64 对象和不可用对象，差值自动包含花括号、换行、缩进、键名、引号和固定值。未来格式变化必须通过最终载荷等价测试，不依赖人工重算常数。

### 不分配 base64 就得到精确长度

base64 对任意 n 字节 Buffer 的字符数恒为 `4 * ceil(n / 3)`，且字符集全是单字节 ASCII、不会被 JSON 转义。把这个字符数加到空 base64 对象固定增量即可得到最终 UTF-8 增量。服务在 `bytes.toString('base64')` 之前执行数值门禁，所以越界对象不会产生第二份大字符串。

### 用多对象证明短路顺序

集成测试仍读取本地 MinIO 中的真实对象，只把共享数值断言的测试上限设为当前运行值减一。首个 Buffer 返回后立即触发 413；为该 Buffer 安装的实例级 `toString` 监听证明 base64 未调用，存储读取监听证明第二个对象未访问。正常导出和第 147 轮媒体读取前拒绝用例仍覆盖其他两条路径。

## 5. 发现的问题与经验

- “必须先读取当前对象”和“必须先生成当前 base64”是两个不同边界；前者用于取得真实字节，后者可以由数学长度提前替代。
- 计算公式只负责 base64 数据字符，固定 JSON 包装应由真实格式化器生成，避免空白、缩进或键名变化成为隐藏魔数。
- 增量正确性需要覆盖 n mod 3 的全部余数；0–4 字节能够锁定填充分界，较长样本再证明线性关系。
- 运行下界保留完整最终拓扑，使多个媒体增量可以直接相加；纯测试同时放入食物和进度照片，证明两类集合深度一致。
- 集成测试监听实际 Buffer 的实例方法，可以证明“对象已读取但尚未编码”，同时不会污染进程中其他 HTTP Buffer。
- 常数时间计数避免了简单但危险的逐照片全量序列化；性能优化本身也需要复杂度门禁。
- 本轮仍会读取导致越界的当前对象，且同步数据库/对象图/初始与最终字符串问题没有消失，不能声称内存有界或归档就绪。

## 6. 全局状态、项目反思与下一步

本轮把同步导出从“媒体全部展开后才拒绝”推进为分阶段资格门禁：非媒体下界超限时零对象读取；第 k 个真实媒体使下界超限时只读取到 k，不编码 k，也不读取 k+1；所有阶段仍共享同一 50 MiB 固定 413 与最终附件权威。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，安全且局部的同步早拒绝空间已经基本穷尽。第 149 轮应重新检查全局风险与产品缺口，再决定是建立可复现的封闭测试账号导出规模/峰值测量收据，还是切出异步加密归档的第一个本地持久任务边界。若选择异步路径，必须先定义所有者请求、状态、保留、加密密钥引用、下载授权和删除责任，不能把本地对象路径或同步 Buffer 包装成“已归档”。

R-013 再获局部缓解但保持中等级开放：越界当前 Buffer、完整数据库结果、非媒体对象图和初始下界仍同步驻留，合法请求仍生成全部 base64 与最终字符串。R-009 和其他风险等级不变，真实云服务、账号、域名、设备与付费 API 继续停放。
