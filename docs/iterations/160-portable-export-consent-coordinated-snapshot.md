# 第 160 轮：便携归档同意证据协调快照

日期：2026-08-11

状态：完成

## 1. 范围、分类与验收标准

本轮分类为 K（Infrastructure），同时服务隐私证据保真。第 159 轮已经证明健康当前值与修订历史可以共享一个事实时刻；本轮选择 v4 中位于健康字段之前、体量较小且已有稳定历史索引的 `consentEvents`，把数据处理来源证据并入相同快照。

验收标准固定为：同意事件必须按 `(accepted_at,id)` 形成数据库总序，复用有界批次和 64 KiB 单 payload 门禁；同步导出必须使用同一尾序。协调器必须由顺序集合描述驱动，并在一个 repeatable-read 事务内只校验一次 active owner，严格依次交付同意、健康记录与健康修订；根物理 EOF 才提交，跳过、重复、乱序或任意取消均失败关闭。真实数据库还必须证明同时间 UUID 总序、跨 owner 排除、跨字段并发隔离、三懒数组与 eager v4 字节相同和同意/健康字段间取消回滚。

范围不迁移训练等嵌套集合或媒体，不实现生产聚合服务、KMS、租约执行器、公开路由、下载授权、客户端入口或同步导出切换。

## 2. 项目结构、设计、技术与实现功能

- `apps/api/src/privacy/portable-export-database-snapshot.ts`：新增同意事件页面源、独立快照入口、描述驱动通用协调器和三集合 `createConsentHealthSnapshot()`；原健康双字段入口保持兼容。
- `apps/api/src/privacy/privacy.service.ts`：同步 v4 同意事件排序从 `accepted_at` 补强为 `(accepted_at,id)`。
- 数据库快照单元测试新增独立同意收据、三集合单事务/根提交和跳过字段失败关闭；假数据库扩展同意表观测。
- PostgreSQL 快照组合测试新增同时间排序、既有索引、跨 owner、并发隔离、47 字节三懒 v4 等价和 1 字节字段间取消证明。
- 同步隐私集成测试把同一用户同意时间固定为同一微秒，并以数据库查询证明 UUID 尾序。
- ADR-0154 固定同意 keyset、索引复用和描述驱动协调策略；架构、数据库、隐私、已实现 PRD、路线图、R-013 和项目状态同步更新。

## 3. 实现方法

1. 读取第 159 轮状态、档案与 ADR-0153，核对 v4 同意字段位置、同步投影和现有 `consent_events_user_history_idx`。
2. 先给同步查询补上 UUID 尾序，再实现独立同意页面源；游标继续只保存 UUID，由数据库回查 `(accepted_at,id)` 锚点。
3. 复用健康行源已有的默认 25/最大 100 行、PostgreSQL JSON 编码、64 KiB UTF-8 门禁、页面收据和 owner 门禁。
4. 把固定双字段逻辑收敛为私有描述数组；状态机只读取当前描述，边界事件、消费索引和收据键都从描述产生。
5. 保留双字段公共入口用于回归；新三字段入口只替换描述列表，避免两套生命周期语义。
6. 用假数据库观察流数量、owner 查询、集合启动顺序、根提交和回滚；用跳过同意字段读取健康字段证明严格顺序失败关闭。
7. 在真实 PostgreSQL 中制造相同微秒的同意事件，并在同意字段完成后写入新同意、健康记录和修订，排除独立事务拼接。
8. 以 `chunkBytes: 47` 对账三懒数组与 eager v4；以 `chunkBytes: 1` 停在同意/健康字段之间，确认健康源未启动后取消并比较统一错误对象。
9. 运行目标测试后执行完整单元、集成、strict 类型、生产构建和全部治理门禁。

## 4. 验证证据

- 数据库快照单元测试 11/11 项通过；目标 PostgreSQL 快照组合测试 11/11 项通过；公开同步隐私集成测试 8/8 项通过。
- 完整单元为 98 个文件、518/518 项；完整集成为 23 个文件、87/87 项。
- 假数据库只建立一个流并执行一次 owner 查询；三集合均读完时仍未提交，调用根 `complete()` 后才提交并解析三份分集合收据。
- 跳过 `consentEvents` 直接读取 `healthRecords` 固定失败关闭并回滚，不启动被跳过或后续来源。
- 真实 PostgreSQL 证明同一 `accepted_at` 下 UUID 形成总序、其他 owner 被排除，既有 `(user_id,accepted_at DESC,id DESC)` 索引覆盖完整键且可反向扫描。
- 在同意字段结束后写入的新同意、健康记录和修订不进入当前后续字段；新会话能看到全部新增行。
- 三个懒数组的 47 字节块与 eager v4 完全相同，JSON 字节数/SHA-256 与三集合批次/行数收据对账。
- 1 字节块在同意与健康之间停止时健康源尚未启动；外层 `return()` 触发回滚，JSON 与统一数据库收据保留同一取消错误对象。
- 完整 strict 类型和生产构建通过；H5 仍只有已登记的 308 KiB 入口预算与 Taro webpack cache 警告，本轮没有客户端源代码变化。
- 完整格式、生产依赖、中文与文档索引门禁通过；生产依赖为 0 个 critical/high、9 个已登记 moderate。
- Obsidian 镜像完成写入并逐字节验证：68,768 字节，SHA-256 为 `c1d35da30184b8ebdf429f65022f53eaf34f5aaba0084c594f278fdd9fbf0daa`；权威来源始终是 `docs/PROJECT_STATUS.md`。

## 5. 发现的问题与经验

- 同意证据不是普通附属元数据。若它与健康事实不在同一快照，导出文件可能无法解释处理依据在该事实时刻是否存在。
- 只按时间排序即使人工看起来稳定，也不是数据库契约；任何 keyset 都必须有不可为空且唯一的尾序。
- B-tree 索引方向不是新增迁移的充分理由。固定前缀下反向扫描现有完整索引可以避免重复存储与写放大。
- 描述驱动协调器缩小了字段数增长带来的状态空间，但不能替代逐集合分析；每个集合仍要独立证明投影、排序、payload 上限和嵌套边界。
- 兼容入口应复用同一内核而不是长期复制实现，才能让根 EOF、取消和收据语义在回归中保持一致。
- 跨字段并发测试需要同时修改已完成字段和未开始字段，才能证明整个会话是一个快照，而不是只证明单个查询稳定。

## 6. 全局状态、项目反思与下一步

本轮把隐私同意来源、健康当前值和修订历史连接为同一事实时刻的可携带片段，并消除了同步同意排序歧义。它提高 Personal Cognitive Mirror 的证据来源完整性，没有把同意事件解释为健康结论，也没有改变任何用户确认事实或 AI 输出。

Inspect → Rank → Improve → Validate 的下一步应评估 `workouts`。它是纵向训练理解的核心集合，但包含 exercises、sets 与可能的历史关系，不能机械复制简单表行源。必须先固定顶层 `(started_at,created_at,id)` 总序、嵌套数组确定顺序、单次训练合法最大体量和 64 KiB 门禁可行性；若一个合法训练会超过单 payload 上限，应先设计嵌套增量边界，而不是提高上限或拆散证据。

R-013 保持中等级开放；R-005、R-009 和其他风险等级不变。真实 KMS、云存储、账号、域名、设备与付费 API 继续停放。
