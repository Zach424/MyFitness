# 第 124 轮：洞察来源数值有效性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 D（Data Quality）与 F（Consistency Checking）。范围只有动作/健康洞察纯构造器接收的窗口与点数值表示。

验收标准固定为：全部来源计数必须是可无损表示的非负整数，点总组数与修订必须为正安全整数，训练负荷/时长/距离必须有限且非负，健康统计/记录值必须有限但不做正负或正常范围判断；可空健康统计保持 `null`。空白、特殊值、超安全整数、非整数计数、负训练量和非法修订必须在任何数值转换与公开派生前失败。检查必须覆盖隐藏第 181 点。不得修改 SQL、公开 Schema、数值精度、分页、客户端、持久化、计划算法、AI 或健康结论。

- `apps/api/src/insights/insights.service.test.ts`：既有动作/健康投影用例覆盖小数计数、训练负数、超安全整数、无穷统计、非法修订及隐藏第 181 点的 `NaN`。
- `packages/contracts/src/insights.ts`：不修改；公开 Schema 继续验证转换后的数字，本轮保护转换前的来源表示与完整集合。
- `docs/product/IMPLEMENTED_PRD.md` 与 `docs/api/API_REFERENCE.md`：补充来源计数、测量、修订与健康非医疗范围边界。
- ADR-0118、架构、路线图、风险登记册、项目状态和本档案：同步门禁顺序、限制、无新增/关闭风险及第 125 轮候选。

本轮没有改变正常响应或错误 HTTP 映射；正常 PostgreSQL `bigint::text`、`numeric::text` 和正整数修订保持兼容。

## 3. 实现方法

### 先验证表示，再转换数值

计数使用十进制整数正则并结合 `Number.isSafeInteger`，避免空白、十六进制、指数/特殊表示和超安全整数在转换时取得似是而非的值。测量使用与 PostgreSQL `numeric::text` 对齐的定点十进制正则，再用 `Number.isFinite` 拦截溢出。

### 字段语义分组

计数允许零；动作点总组数和两个聚合修订必须为正；训练负荷、秒数、距离不允许负数。健康统计、规范值与展示值只要求有限，允许负数且不附加指标范围，因为通用构造器没有医疗判断授权。

### 全部来源行扫描

四类检查都覆盖构造器收到的完整数组，而不是最终公开窗口或 180 点前缀。未来位置与隐藏第 181 点的非法数值不能逃逸，也不能在 JSON 序列化时退化为 `null`。

### 分层错误优先级

参考时刻、响应时区和窗口身份保持既有优先级；窗口身份后检查窗口数值，点有效时刻后检查点数值，再进入顺序、UUID、过滤、截断、单位和摘要派生。这样保留既有错误可诊断性。

## 5. 发现的问题与经验

- `Number(...)` 是转换器，不是输入验证器；空白、特殊格式和精度边界需要在转换前处理。
- 有限整数不等于安全整数；计数一旦超出 `Number.MAX_SAFE_INTEGER`，即使仍显示为整数也可能已经失真。
- `JSON.stringify` 会把 `NaN` 和无穷 number 序列化为 `null`，对健康证据尤其危险，因为 `null` 已有“缺失”含义。
- 来源扫描必须覆盖过滤/截断外的行，否则非法值仍可改变收据或在参考时刻移动后进入公开前缀。
- 数据表示规则与医疗范围规则必须分开；健康有限负值可被表示，不代表产品确认其合理、正常或异常。
- 单字段有效不证明字段之间一致，聚合关系需要下一层门禁。

## 6. 全局状态、项目反思与下一步

本轮关闭了洞察来源数值在转换时静默丢失精度、生成非有限 number 或伪装成 `null` 的路径，并拒绝明确违反训练/修订最小语义的值。它没有纠正任何数值，也没有进行医疗范围判断。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处候选缺口位于原始聚合关系。动作点的完成组数可能大于总组数；健康窗口可能出现计数/统计存在性或 min/avg/max 次序冲突。下一轮第 125 轮必须重新排序；当前最小候选是在来源边界验证这些 SQL 已保证的关系，并与公开 Schema 对齐，不从关系推断趋势或正常范围。

本轮未新增或关闭风险：数值表示门禁不证明字段关系、记录真实性、健康正常范围、统计意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
