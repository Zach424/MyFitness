# 第 120 轮：洞察首点摘要一致性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 C（Evidence Modeling）与 F（Consistency Checking）。范围只有动作顶层身份、健康顶层规范单位与最新公开点的派生关系，以及健康点的规范单位一致性。

验收标准固定为：动作共享 Schema 必须要求空序列的 `identity` 为 `null`，非空时逐字段等于首点身份；健康纯构造器必须在未来过滤后、180 点截断前验证全部合格点使用同一 `canonical_unit`，隐藏第 181 点漂移也必须失败；健康共享 Schema 必须要求空序列 `canonicalUnit` 为 `null`、非空时等于首点，并在首个漂移点给出精确路径。不得自动换算、删除冲突点或修改 SQL、窗口统计、客户端、响应形状、持久化、计划算法、AI 或健康结论。

## 3. 实现方法

### 摘要只引用最新公开证据

动作身份比较覆盖名称、类别、跟踪模式、器械备注和有序器械数组。空序列单独处理，避免 JavaScript 可选链把两个空值误判为相等或不等。错误放在顶层 `identity`，因为被拒绝的是摘要声明而不是首点事实。

健康顶层 `canonicalUnit` 使用同样的首点/空序列规则。顶层错位定位到 `canonicalUnit`，后续点漂移定位到具体点字段，从而区分“摘要陈旧”和“时间线混入不同量纲”。

### 先确定当前证据，再检查量纲

服务端继续先验证全部原始输入的时间顺序和 UUID 唯一性，再排除晚于参考时刻的点。规范单位检查只扫描过滤后的全部合格点，并发生在 180 点切片前。这既保留未来证据隔离，也覆盖决定 `hasMore` 的隐藏点。

### 失败关闭而不猜测换算

同一指标通常应有固定规范单位，但替代响应若混入 `kg` 与 `cm`，边界不知道是指标配置、查询、适配器还是夹具错误。自动换算可能把不同量纲伪装成可比值，因此本轮只失败关闭并保留上游可观察性。

## 5. 发现的问题与经验

- 构造器正确派生摘要不能替代公开契约验证；测试夹具、缓存和替代适配器仍可能发布陈旧顶层标签。
- 顶层摘要和首点事实应有单向权威关系：首点是证据，摘要只是引用，不能反过来修写点。
- 健康规范单位一致性必须覆盖隐藏截断点，否则下一页证据可能与当前时间线量纲冲突。
- 未来过滤与单位检查的顺序具有产品语义；尚未发生的点不属于当前证据，但进入参考时刻后必须接受全部门禁。
- 自动单位换算只有在指标和单位映射均受信时才安全；边界遇到不同量纲不应猜测。
- 单一规范单位仍不能证明展示单位、换算数值、来源记录或趋势解释正确。

## 6. 全局状态、项目反思与下一步

本轮防止最新动作被陈旧身份摘要标注，也防止不同规范量纲进入同一健康纵向观察。它没有从单位一致推断数据真实、变化显著、训练效果或医疗结论。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处 Foundation Value 较高的缺口位于截断收据。生产 SQL 精确限制 181 行，构造器公开 180 点并由额外合格点派生 `hasMore`，但纯构造器未拒绝超过 181 个合格输入，共享 Schema 也允许不足 180 点却声明 `hasMore: true`。下一轮第 121 轮必须重新排序；当前候选是失败关闭超限输入，并要求真值截断声明至少有满 180 点公开前缀，同时保留“恰好 180 点且无更多”这一不可区分合法态。

本轮未新增或关闭风险：摘要与量纲一致不证明来源真实性、换算正确性、证据完整性、统计意义或用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
