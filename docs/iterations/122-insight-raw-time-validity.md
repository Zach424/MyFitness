# 第 122 轮：洞察原始时刻有效性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 D（Data Quality）与 F（Consistency Checking）。范围只有动作/健康洞察的参考 `Date` 和原始点 `occurred_at` 有限性。

验收标准固定为：两个生产构造器必须在时区派生前拒绝无效参考时刻，并在排序、唯一性、未来过滤、截断和摘要派生前拒绝任一无效原始点时刻；隐藏第 181 点和原本处于未来位置的无效点都必须失败。参考时刻错误不得继续误报成 IANA 时区错误。不得静默删除或替换无效点，也不得修改 SQL、窗口、分页、公开 Schema、客户端、持久化、计划算法、AI 或健康结论。

## 2. 项目结构、设计、技术与实现功能

- `apps/api/src/insights/insights.service.test.ts`：现有动作投影用例覆盖无效参考时刻与隐藏第 181 点；健康投影用例覆盖首个未来位置的无效点。
- `packages/contracts/src/insights.ts`：不修改；公开 `generatedAt`/`occurredAt` 已由带偏移 datetime Schema 验证，本轮保护的是序列化前来源边界。
- `docs/product/IMPLEMENTED_PRD.md` 与 `docs/api/API_REFERENCE.md`：补充参考/来源点必须是有效时刻且不得静默变成缺失证据。

本轮没有改变正常响应或错误 HTTP 映射；正常 PostgreSQL `timestamptz` 行保持兼容。

## 3. 实现方法

### 有限值优先于所有时间语义

`Number.isFinite(date.getTime())` 是判断 JavaScript `Date` 能否参与比较和序列化的最小条件。参考时刻先于时区格式化验证，来源点先于顺序与过滤验证，避免 `NaN` 进入任何比较。

### 全部来源点一次扫描

检查覆盖原始数组而不是最终公开前缀，因此未来点和隐藏第 181 点不能逃逸。最多正常读取 181 行，额外线性扫描有固定小边界，不保存请求外状态。

### 不把无效值解释为未来或缺失

`NaN <= reference` 为假并不意味着该点在未来，也不意味着用户没有记录。构造器没有证据修复时间，因此失败关闭并保留上游适配器错误可观察性。

### 公开契约与来源门禁互补

共享 Schema 能拒绝已序列化的无效 datetime 字符串，却无法看到在构造阶段被过滤的行。来源有限值检查保护数据选择，公开 Schema 继续保护传输表示，两者不重复替代。

## 5. 发现的问题与经验

- `Date` 的静态类型不保证运行时有效；`Invalid Date` 仍是一个对象，必须显式检查内部时间值。
- `NaN` 会让所有顺序比较失效，并在布尔过滤中表现为“不合格”，这是危险的静默数据丢失路径。
- 验证顺序决定错误语义；参考时刻必须先于 IANA 时区格式化，才能区分数据错误和配置错误。
- 来源边界检查必须覆盖将被过滤或截断的点，否则无效证据仍可影响选择规则。
- 公开 datetime Schema 不能证明构造前的来源集合完整，分层门禁不可互相替代。
- 有限时间不证明时间真实、时区正确、发生顺序完整或记录具有健康意义。

## 6. 全局状态、项目反思与下一步

本轮关闭了无效原始时刻静默变成缺失证据的路径，并让参考时间与时区故障保持可区分。它没有纠正或推断任何时间，也没有扩展产品结论。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处候选缺口位于窗口原始行身份。动作与健康构造器用 `.find` 选取 7/30/90 日行；重复身份会静默取首行，未知身份会被忽略。下一轮第 123 轮必须重新排序，并与更广的原始数值有限性缺口比较；当前最小候选是只允许 7/30/90 且不重复，同时继续允许缺失行回退为空、不要求输入顺序。

本轮未新增或关闭风险：有限时刻不证明发生时间真实、数据库查询完整、客户端时区数据、趋势意义或用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
