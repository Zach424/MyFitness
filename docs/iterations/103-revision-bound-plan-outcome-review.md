# 第 103 轮：修订绑定的计划结果回看

日期：2026-08-10

状态：已完成

## 1. 范围与验收标准

本轮只建立“状态估计→用户采用的计划调整→采用后的确认记录”最小回看链，不接入设备、云服务、真实 AI，不生成效果分或自动调整计划。验收要求是：新计划保存真正参与安排的恢复状态及逐条引用；回看绑定精确采用修订与七天观察窗；只纳入采用后、用户仍保留的训练关联和非 AI 已确认恢复记录；无证据保持 Unknown；界面明确禁止因果和依从性解释；契约、领域、API、H5/WeApp、文档、Obsidian 与 Git 均有可复现证据。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/plan.constants.ts` 与 `plan.ts`：新增 `plan-outcome-review-v1`、窗口/状态、调整、训练与恢复证据契约；交叉校验七天时域、计划修订、发生时刻、证据总数和 Unknown/Observed 一致性。
- `packages/domain/src/plan.ts`：新生成计划把完整 `subjective-recovery-state-v1` 快照写入计划证据；历史计划缺失该可选字段时继续兼容。
- `packages/domain/src/plan-outcome.ts`：比较最近生成快照与采用快照的稳定活动选择，筛选采用后的精确关联/记录，并产生无因果结论的只读投影。
- `apps/api/src/plans/plans.service.ts`：计划列表批量读取当前采用修订、最近生成基线、活动训练链接与七天内当前已确认恢复记录；不新增结果表或迁移。
- `apps/client/src/pages/plans/index.tsx` 与 `index.scss`：周计划页显示生成依据、采用版本/替代、后续训练/恢复来源和 Unknown/Observed；写入、刷新和关联继续沿用既有读取权限。
- `apps/client/client-quality-budget.json`：初版门禁失败后先压缩约 3 KB 展示代码，再依据最终实测把 WeApp 总量/单页预算重基线为 1,110,000/63,000 字节，保留 8,901/2,682 字节余量。
- 共享契约/领域测试、计划 PostgreSQL 集成与 `tests/e2e/plans.spec.ts`：锁定恢复快照一致性、调整比较、来源筛选、Unknown/Observed 和移动端来源展示。
- `docs/architecture/decisions/0098-revision-bound-noncausal-plan-outcome-review.md`、计划/健康模型、架构基线、路线图、风险登记册与本档案：记录边界、R-031、包体重基线和下一轮历史回看方向。

## 3. 实现方法

### 让计划保存它真正使用的状态证据

计划证据不再只有一个恢复分数。新计划同时保存当时的状态、窗口、基线、覆盖、置信度、冲突和记录修订引用；契约要求该状态经过既有 `planningReadinessScore` 投影后与计划分数一致。旧计划无法重建的底层证据保持缺失，并在回看限制中明确说明。

### 用不可变采用时刻建立时域

回看从 `weekly_plan_revisions` 中当前 `accepted` 修订的 `changed_at` 开始，观察窗固定七天，当前读取只观察到 `min(now, adoptedAt + 7 days)`。调整来自该采用快照与之前最近一次生成快照的稳定活动 ID 比较，不从决定备注猜测。

### 只连接用户仍确认的后续事实

训练必须有活动的显式计划关联、匹配同一计划修订，且训练发生在采用后；恢复必须是当前未删除、已确认、非 AI 的主观记录。训练和恢复都保留精确聚合修订。采用前记录、AI 候选、已删除记录、旧计划修订或已解除关联均不能成为当前结果证据。

### 把“观察到记录”和“产生效果”分开

投影只回答是否有后续确认记录。没有证据时是 Unknown；有证据时是 Observed，而不是“有效”。客户端把生成依据、用户决定和后续来源顺序展示，并固定说明共现不能证明因果、不会评分依从性或自动调整下一份计划。

## 5. 发现的问题与经验

- 结果反馈首先是时间与来源建模问题，不是再计算一个分数。没有精确采用时刻和修订，后续记录很容易错误归到另一份计划。
- “用户明确关联”证明关系由用户选择，不证明训练完全执行计划，也不证明计划导致任何变化；关联权限不能自动升级为依从性或因果权限。
- 生成计划时只保存摘要会切断未来审计。状态证据必须在决策发生时快照，事后用当前仪表盘重建会混入未来记录。
- 旧数据缺证据时兼容读取比伪造回填更诚实。可空的旧摘要限制使新计划增强不需要迁移或重写历史。
- 严格包体门禁暴露了真实交付成本。先压缩可见实现，再基于实测显式重设并保留余量，比忽略失败或无说明提高上限更可审计。

## 6. 全局状态、剩余风险与下一步

项目现在能在当前采用计划上回答“当时用了什么状态证据、我采用了哪些替代、采用后留下了哪些确认记录”，但不能回答计划是否产生效果。七天窗口、主动记录覆盖和活动关联都可能产生选择偏差；R-030 继续覆盖状态估计启发式，新增 R-031 覆盖结果窗口和过度归因。当前回看也只随当前 `accepted` 聚合返回，一旦同周计划被重新生成、跳过或修改，旧采用修订虽然仍在不可变历史中，却没有独立可见的结果回看。

下一轮第 104 轮优先为历史采用修订提供所有者作用域、精确修订绑定的只读结果回看入口与读取权限，使纵向记忆不随当前计划状态变化而消失。它继续复用当前事实重算、标注已解除/已删除证据缺失，不做方向比较、假设生成、因果归因或自动适应。
