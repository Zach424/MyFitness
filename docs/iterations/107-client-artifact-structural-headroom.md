# 第 107 轮：客户端构建产物结构余量

日期：2026-08-10

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 K（基础设施）。它不直接增加对用户的理解，而是解除第 106 轮只剩 5 字节 WeApp 余量的硬阻塞，保护后续构建长期个人状态与证据模型的工程带宽。

范围只包括一项可逆的双端构建产物治理：H5 拆分单个过大的异步公共块，WeApp 使用框架自有能力删除模板格式空白，并把改善后的预算向下收紧。不得新增路由、依赖、业务数据、AI 调用或用户结论；不得提高任何预算、降低 Taro 模板递归层级，或删除隐私、安全、失败关闭和无障碍语义。

验收要求是：H5 最大异步块至少减少 40,000 字节且入口仍低于 320,000 字节；WeApp 总量至少减少 1,500 字节且 vendor/最大页面不增长；两项改善均由更严格的入库预算防止反弹；双端生产构建、客户端质量校验、完整单元/集成/Chromium 和中文文档门禁通过；项目状态、Obsidian、ADR 与 Git 完整归档。

## 2. 项目结构、设计、技术与实现功能

- `apps/client/config/index.ts`：H5 新增优先级 20 的 `taro-components` 异步缓存组，位于优先级 30 的发生时间专用块和优先级 10 的通用共享块之间；WeApp 启用 Taro 4.2.1 内建 `minifyXML.collapseWhitespace`。
- `apps/client/client-quality-budget.json`：H5 最大异步 JavaScript 上限从 206,000 收紧到 160,000 字节，WeApp 总量上限从 1,110,000 收紧到 1,109,000 字节；其余入口、总量、vendor、页面与运行时标记门禁保持不变。
- `tests/e2e/privacy.spec.ts`：需要直接修改同意历史数据再刷新的用例，先等待 `.custody-total__value` 成为数字，明确证明隐私概览读取已完成，再改变数据库和导航。
- `docs/PROJECT_STATUS.md`、架构、路线图、风险登记册、ADR-0102 与本档案：记录双端结构、预算、实测结果、适用边界和下一轮个人状态证据账本方向。

视觉与交互设计没有变化。H5 拆块只改变资源加载图；WeApp 压缩只删除生成 XML 的格式空白。现有衡迹设计语言、320 px 适配、键盘焦点、敏感失败状态和所有用户文案均保留。

## 3. 实现方法

### 从实际产物定位最大结构成本

第 106 轮基线显示 H5 的 `client-async-shared.js` 为 202,930 字节，是唯一接近 206,000 门禁的异步块；它同时包含项目共享代码与 `@tarojs/components`。本轮不按页面复制代码，而以更高优先级从现有通用规则中提取平台组件运行时，生成约 50 KiB 的 `taro-components.js`。通用块降到 151,816 字节，入口仍只引用 `js/78.js`、`js/app.js` 与 `css/app.css`。

### 只使用框架支持的 WeApp 压缩能力

本地 Taro 4.2.1 `MiniPlugin` 在 `minifyXML.collapseWhitespace` 为真时使用内建 HTML 压缩器，并保留闭合斜线。配置放在 `mini` 平台边界；没有脚本直接编辑 `dist-weapp`，也没有降低默认模板递归层级。`base.wxml` 最终为 59,834 字节，且静态检查确认没有换行或连续格式空白。

### 用向下收紧的预算保存成果

只观察一次更小产物不能阻止后续反弹。因此在同一轮把 H5 最大异步块和 WeApp 总量上限分别收紧 46,000 与 1,000 字节。当前 H5 对新异步上限余 8,184 字节；WeApp 对新内部总量上限余 821 字节，相对上一轮旧上限恢复 1,821 字节。去掉任一结构优化都会触发门禁，而不是悄悄回到危险边缘。

### 让浏览器测试等待数据权限而不是页面外壳

异步块拆分使页面标题可见和隐私概览完成之间的间隔更明显。原测试在 `seedAccount` 返回后立刻改数据库并 `reload`，会取消仍在飞行的 `/me/privacy` 请求。测试现在等待保管总数的数字证据；这不是人为延时，也不忽略请求失败，而是以用户可见的数据完成状态作为下一操作权限。

## 5. 发现的问题与经验

- 包体“通过预算”不等于具备增长能力。第 106 轮的 5 字节余量会把任何哈希漂移变成阻塞；优化后立即下调预算，才能把改善变成可执行约束。
- 拆分共享块有请求数量与缓存复用的权衡。当前最大块减少 25%，入口只增加 177 字节，且 95 条 Chromium 流程通过；但真实弱网缓存收益仍需代表性浏览器测量，不能从字节数直接推断体验改善。
- WeApp 模板递归层级可能带来更大减重，但会改变运行时路径和性能。本轮缺少微信开发者工具/真机证明，因此明确不动 `baseLevel`，只采用框架已支持的格式空白折叠。
- 本机 3100 端口被另一个项目占用时，Playwright 会等待错误服务的健康路径。隔离端口运行必须同时设置服务端口、客户端 API 基址和测试夹具 API 基址；漏掉任一项都会产生误导性的 404 或未命中路由。
- 页面外壳可见不代表数据读取已完成。需要直接改变后端状态的测试应等待用户可见的数据完成证据，而不是使用固定延时或忽略导航取消。

## 6. 全局状态、项目反思与下一步

本轮没有增加新的用户价值表面，但解除了阻碍认知能力继续建设的交付约束。保留了完整的隐私、安全、失败关闭和无障碍语义，并用更严格预算锁定结果，因此它是服务于长期理解能力的必要 K 类基础设施，而不是以包体数字代替产品进展。

全局反思表明，当前项目已经分别拥有用户确认体验、系统观察结果和确定性主观恢复估计，但它们仍散落在计划、结果、首页与领域投影中。系统能显示多个证据，却还没有一个最小、诚实且统一的状态表达来回答“这是本人确认、系统观察还是估计；依据何时发生；置信到什么程度；何时失效”。这比继续增加新的孤立洞察更能提升长期个人理解能力。

因此第 108 轮选择“个人状态证据账本”作为最高杠杆改进：先建立最小只读契约与投影，并列 `user_confirmed`、`observed`、`estimated` 和 Unknown 的来源、证据时间、置信与失效边界。它不生成新 AI 结论、不诊断、不解释因果、不自动改计划，也不复制领域事实形成第二权威来源。R-009 继续要求微信真机和代表性浏览器加载/缓存证明；风险登记册全表时效复核及所有需要账号、预算、域名、凭据或责任人的托管工作仍停放。
