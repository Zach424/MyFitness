# 第 105 轮：独立计划结果回看与页面包体余量

日期：2026-08-10

状态：已完成

## 1. 范围与验收标准

本轮只把当前/历史采用修订的结果回看从周计划同步页面迁移到一个独立读取页面，为后续用户反思恢复可维护空间；不新增 API、数据库、AI、效果方向或计划适应。验收要求是：当前与历史 `accepted` 修订进入同一精确回看；计划页不再持有完整结果状态；无效/失败读取不发布空结果或原始服务消息并提供可聚焦重试；卸载后的响应不能提交；三段证据轨、撤销计数与非因果边界保持；320 px 无横向溢出；计划页最大 JS 明显低于 63,000 字节且双端总预算不提高；文档、Obsidian 与 Git 完整归档。

## 2. 项目结构、设计、技术与实现功能

- `apps/client/src/app.config.ts`：注册延迟访问的 `pages/plan-outcome/index`，不改变首页或应用入口加载路径。
- `apps/client/src/pages/plan-outcome/index.tsx`：解析计划 ID/修订，独立读取精确结果，管理加载/失败/重试/就绪和页面代次；以精简三段证据轨展示计划依据、采用决定、后续来源、撤销计数和安全边界。
- `apps/client/src/pages/plan-outcome/index.scss`：沿用既有设计令牌，以纵向编号轨作为唯一识别元素；移动端优先、返回/重试触控高度、320 px 与减少动态效果边界明确。
- `apps/client/src/pages/plans/index.tsx` 与 `index.scss`：当前采用卡和历史采用行只保留导航入口；移除内联证据组件、历史回看请求状态与完整结果 React 状态，计划生成/决策/关联权限不变。
- `tests/e2e/plans.spec.ts`：真实 Chromium 覆盖当前 v3 与历史 v3 的独立导航，历史首次 503、隐藏原始消息、重试焦点、当前 v11/历史 v3 分离、撤销证据、返回焦点、320 px 无溢出和已关联训练来源。
- `docs/PROJECT_STATUS.md`、计划模型、架构基线、路线图、风险登记、ADR-0100 与本档案：同步页面责任、包体权衡和第 106 轮约束。

## 3. 实现方法

### 让周计划页只保留选择修订的责任

计划页仍从权威列表读取计划、历史和关联，但不再把 `outcomeReview` 写入页面状态。当前采用卡显示“独立读取”，历史只有动作精确为 `accepted` 的行显示入口；两处都导航到同一 `planId/revision` 页面。计划写入、AI 和训练关联仍沿用原读取权限，不因结果页新鲜度发生变化。

### 让结果页拥有完整且短生命周期的读取权限

结果页验证非空计划 ID 与正整数安全修订后才请求精确所有者路由。请求获得单调代次；重试推进代次，卸载也使当前代次失效。初始错误只显示产品自有文案，成功前不构造 Unknown；API 仍负责隐藏非采用、缺失和外部所有者目标。

### 用证据轨编码真实顺序

页面唯一显著结构是 01 生成依据、02 你的决定、03 后续确认的纵向轨道，因为三者确实有时间和权限顺序。撤销计数放在轨道之外，避免视觉上把已删除/解除的项目继续当成后续证据；底部边界明确时间先后不能证明效果、因果或依从性。

### 用真实包体测量约束页面复杂度

首版完整页面使 WeApp 总量达到 1,114,827 字节，超预算 4,827 字节；压缩版一度只剩 22 字节余量。最终移除独立 ScrollView、重复装饰、主页完整结果状态和多余排版层，在不删证据/错误/安全语义且不改预算的前提下使计划页最大 JS 降到约 57.4 KB、总包恢复约 1.6 KB 余量。

## 4. 验证证据

- 工作区格式与 TypeScript strict 检查、完整生产构建通过。
- 完整 Vitest 保持 88 个文件、456/456 项通过；本轮没有改变共享契约或领域规则。
- 完整 PostgreSQL 集成保持 19 个文件、64/64 项通过；现有精确历史结果 API 行为未改。
- 计划页 Chromium 14/14 通过；新增页面证明失败关闭、聚焦重试、当前/历史版本绑定、320 px 无横向溢出、返回后计划状态保留。最终全量浏览器回归为 95/95。

- 生产依赖审计保持 0 个 critical/high、9 个已登记 moderate；中文文档、迁移索引与 Obsidian 字节级同步通过。

## 5. 发现的问题与经验

- 从一个页面移到另一个页面不等于包体优化。完整 Taro 路由有固定 JS/WXML/WXSS 成本，必须同时删除原页面状态和重复表现，并测量总树与最大页两种指标。
- 单页门禁和总包门禁解决不同问题。本轮恢复计划页余量，却消耗了大部分总包余量；后续只能复用结果页或进一步拆共享实现，不能继续横向增加路由。
- 证据页面的特色不需要大量装饰。真实的三段时序和撤销分叉已经是产品独有结构，移除网格背景、重复标签和独立滚动容器后反而更清楚。
- 路由切换动画会让过早截图看似横向溢出。最终证据等待 Taro 过渡完成，再验证 320 px 文档宽度，区分动画瞬态与静态布局缺陷。
- 主页不持有完整结果意味着 Unknown/Observed 不会在用户未请求时出现，更符合“先取得读取权限，再展示证据”的项目原则。

## 6. 全局状态、剩余风险与下一步

项目现在用一个独立页面承载当前和历史采用修订的结果回看，周计划页恢复了可维护的单页余量；读取失败、撤销证据与非因果语义保持不变。R-009 仍需跟踪总包只有约 1.6 KB 余量，R-031 继续覆盖七天窗口和主动记录选择偏差。计划标识进入 H5 查询参数但不含健康内容；该保留边界需要在真实身份/共享设备审阅中复核。

下一轮第 106 轮在现有结果页中加入用户主动确认的计划体验反思。先定义一条精确采用修订绑定、可更正、可删除、进入导出/擦除且来源固定为用户确认的事实；选项保持“更容易、合适、不适合、尚未判断”等主观表达，不从训练/恢复证据推断，不进入效果或因果结论，也不自动修改计划。实现必须先回收足够总包余量，不能新增完整客户端路由。
