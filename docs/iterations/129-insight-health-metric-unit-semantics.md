# 第 129 轮：健康洞察指标单位语义一致性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 D（Data Quality）与 F（Consistency Checking）。范围只有健康指标与规范/展示单位的身份关系，以及该门禁引出的可复现性能回归。

验收标准固定为：九个指标的规范单位与允许展示单位必须有一份 contracts/domain 共用权威；生产构造器在排序、未来过滤和 180 点截断前拒绝任一指标单位错配，检查覆盖未来点与隐藏第 181 点；公开响应 Schema 必须逐点独立拒绝同类错配。领域归一化行为不得改变。不得重跑数值范围、校验展示/规范值换算、自动修复历史值或修改 SQL、响应形状、分页、客户端、持久化、计划、AI、医疗结论。完整单元不得通过提高超时才能成功。

## 3. 实现方法

### 单位身份提升为跨层常量

共享常量只包含传输和领域都必须知道的单位身份。领域以对象展开追加原有范围、整数和换算配置，因此无需反向依赖，也不把医疗/产品范围阈值带进 contracts。

### 来源与响应双层关系门禁

API 使用领域定义扫描原始行；公开 Schema 使用共享常量扫描响应点。两层都要求规范单位精确相等，展示单位属于允许集合，但不读取或改变数值。

### 完整来源扫描

指标单位关系发生在排序和未来过滤前。未来点和隐藏第 181 点不能等到进入公开前缀后才暴露错配；合法未来点仍不影响当前摘要，进入参考时刻后按原序公开。

### 性能回归的根因修复

首次完整单元运行在健康洞察大用例超过 5 秒。根因是来源门禁对每条点重复运行完整公开点 Schema，其中包含与来源凭据无关的日期、UUID 和数值工作。实现改为导出并复用点 Schema 的 confirmed 来源、记录时区和单位组件；定向 3 文件执行恢复，完整单元在原超时内通过，没有减少场景或提高阈值。

### 不验证换算或范围

单位身份正确仍不证明两个数值互相换算。该关系需要持久化精度与舍入政策，留给独立迭代；本轮不调用会执行 min/max 的完整归一化来验证历史点。

## 5. 发现的问题与经验

- 枚举合法和序列单单位都不能证明单位属于当前指标；关系约束需要精确指标身份。
- 跨层共享应提升最小稳定子集，而不是把范围、换算和产品策略全部移进传输常量。
- 复用 Schema 不等于每次都应解析最大对象；复用其精确组件可保持语义同源并避免重复计算。
- 测试超时是性能证据；应先消除无关工作，而不是增加阈值。
- 单位身份正确不证明数值换算、来源真实性、健康范围或趋势意义。

## 6. 全局状态、项目反思与下一步

本轮关闭了已知但与精确指标不匹配的规范/展示单位进入健康洞察的路径，并建立 contracts/domain 单一单位身份。它没有读取、纠正或解释记录值。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处同类缺口位于展示值与规范值换算。单位均正确时，替代适配器仍可返回彼此不代表同一测量的两个数值。下一轮第 130 轮必须重新排序，当前最小候选是提取不执行范围判断的确定性换算、定义 NUMERIC(14,4) 舍入容差，并让来源与公开响应独立验证；不得覆盖历史展示值或把错配自动修复。

本轮未新增或关闭风险：单位关系门禁不证明换算正确、记录真实、设备准确、健康范围、趋势意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
