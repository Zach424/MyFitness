# 第 099 轮：产品简报中文权威正文迁移

日期：2026-08-06

状态：已完成

## 1. 范围与验收标准

本轮只迁移 `docs/product/PRODUCT_BRIEF.md` 的自然语言正文，并把它从待迁移专题唯一转入受中文门禁保护的活跃权威文档；不改变产品范围、客户端、服务端、数据库或部署行为。验收要求是：产品主张、初始受众、核心任务、信息架构、MVP 功能范围、明确排除项、成功模型与商业假设完整保留；标题层级、列表、表格、链接、代码和数字结构签名不漂移；全文通过中文正文门禁；迁移索引待办和活跃文档计数同步变化；状态、路线图、架构、ADR、Obsidian 和 Git 归档完成。

## 2. 项目结构、设计、技术与实现功能

- `docs/product/PRODUCT_BRIEF.md`：13 节中文权威产品简报，覆盖受众、任务、五区信息架构、四类 MVP 能力、排除项、指标与商业假设。
- `scripts/docs-language-policy.mjs`：将产品简报加入活跃文档，固定全部 13 个中文导航标题、72% 最低中文占比和零纯英文叙述行。
- `scripts/docs-migration-inventory.mjs`：将产品简报从 `topic-product-design` 移入活跃分类，并新增人读索引的受保护活跃文档计数标记。
- `scripts/docs-migration-inventory.test.ts`：新增陈旧活跃文档计数回归，使分类转移只有在人读索引与机器策略同时更新时才通过。
- `docs/DOCUMENTATION_MIGRATION_INDEX.md`：活跃权威文档更新为六份，专题待办更新为 18 份，总待办更新为 192 份。
- `docs/DOCUMENTATION_LANGUAGE_POLICY.md`：登记产品简报为第六份活跃权威文档。
- `docs/architecture/decisions/0094-authoritative-product-brief-chinese-narrative.md`：记录本轮范围保真与分类转移决策。

## 3. 实现方法

### 先固定结构，再逐段迁移语义

迁移前从提交版本提取标题层级、编号列表、项目符号、表格行、行内代码、链接、代码围栏和数字令牌的有序签名。候选正文按段人工迁移，保留“不提供医疗诊断或治疗”“AI 估算由用户确认”“照片用途受限”“健康数据不用于定向广告或出售”等原有边界。完成后用同一提取规则比较两个版本，任何数量或顺序差异都失败。

### 把中文导航当成产品范围接口

产品简报不是普通历史说明，而是项目状态引用的当前 MVP 证据。因此门禁不只计算全文比例，还要求 13 个中文标题继续存在。未来可以修改正文，但不能在没有显式决策的情况下删除受众、排除项、安全图像边界、成功模型或商业假设章节。

### 原子转移迁移分类

产品简报从专题待办删除的同一变更中，被加入活跃文档分类和中文策略。迁移索引同时把待办总数从 193 调整为 192，并写入六份活跃文档的受控标记。新增回归故意把该数字改旧，证明只改机器策略或只改人读索引都会失败关闭。

### 区分翻译完成、假设验证与生产证明

本轮只证明中文正文和历史结构保真。目标用户、北极星指标、订阅假设、微信/手机号边界和照片成本仍需真实研究或生产证据；没有把中文化表述为用户验证，也没有触发任何外部服务接入。

## 4. 验证证据

- 提交前/候选结构签名一致：13/13 个标题层级、6/6 个编号任务、26/26 个项目符号、7/7 行表格、0/0 个行内代码、0/0 个链接、0/0 个代码围栏和 8/8 个有序数字令牌完全一致。
- 定向 Vitest：迁移索引与中文正文策略共 12/12 通过；完整 Vitest 为 85 个文件、436/436 项通过。
- `pnpm docs:check-language` 通过：产品简报包含 1,193 个汉字、33 个拉丁字母，中文占比 97.3%，纯英文叙述行为零；六份活跃权威文档全部超过 72%。
- `pnpm docs:check-migration-index` 通过：219 份 Markdown 恰好归类一次；六份活跃文档、一份治理规范、十份当前迭代、十份当前 ADR、18 份待迁移专题和 174 份待迁移历史完整且互斥，总待办为 192。
- 六个 TypeScript 工作区严格检查、全仓 Prettier、高风险生产依赖门禁与既有客户端产物复核通过；生产依赖为 0 个 critical/high、9 个已登记 moderate，客户端体积峰值沿用第 097 轮已构建证据。
- `docs/PROJECT_STATUS.md` 与 Obsidian 镜像逐字节一致；本档案在 vault 的 `iterations` 目录保存同名副本并通过 SHA-256 核验。

## 5. 发现的问题与经验

- 产品简报中的自然语言同样承担安全契约。把“治疗性计划”“疾病诊断”“精确体脂推断”等排除项翻得更宽或更窄，都会实际改变产品边界。
- 只用中文比例无法保护章节完整性；固定导航标题可以用很小成本防止一整类范围被无声删除。
- 迁移清单的“完成”必须是分类转移，不是勾选文字。旧分类删除、新分类加入、正文门禁和索引数字需要在同一可逆提交中发生。
- 数字令牌签名会同时捕获编号列表和业务数字，因此必须按顺序比较，不能只比较去重后的集合。
- 外部部署尚缺账号、域名、凭据和责任材料，不应继续占用一个看似确定的本地迭代编号；它仍是发布门禁，但等待输入期间可以继续完成有界本地工作。

## 6. 全局状态、剩余风险与下一步

当前六份活跃权威文档均已由中文正文门禁保护，专题待办剩余 API 说明、设计系统、风险登记册、11 个架构模型和四份运行手册，共 18 份；174 份历史档案仍按六个连续批次等待迁移。结构与语言通过不代表产品假设得到用户验证，也不代表真实身份、数据保管、遥测、备案或云部署完成。

下一轮第 100 轮迁移 `docs/product/RISK_REGISTER.md`，优先保护高风险事项、缓解措施、责任归属、触发条件和审阅节奏。托管共享环境部署改为等待强制外部输入后再编号，原生设备同步继续等待 MVP 留存门禁。
