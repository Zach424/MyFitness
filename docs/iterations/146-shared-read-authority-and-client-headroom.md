# 第 146 轮：共享读取权限内核与客户端包体余量

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 R（Risk Reduction）。范围只包含客户端重复读取失败分类、标准快照阶段函数、对应类型/导出兼容、定向测试、双端生产产物与预算收紧；不包含页面文案、权限、焦点、缓存、重试、API、数据 Schema、Taro/React 升级、模板层级、真实设备或外部环境。

验收标准固定为：所有原分类函数必须继续把 Error/`errMsg` 视为离线、4xx 视为拒绝、5xx 视为服务中断、其他值视为未知；九种标准读取必须继续区分初始加载、就绪、刷新、初始错误和保留旧数据。调用方导入名、类型名、产品文案和失败关闭权限不得改变，特殊续页状态机不得被错误合并。WeApp 相对第 145 轮必须至少减少 476 字节，使原预算余量恢复到至少 1 KiB；收益成立后应收紧预算，并继续为后续功能保留至少 1 KiB。

## 2. 项目结构、设计、技术与实现功能

- `apps/client/src/lib/read-authority.ts`：新增无 React/Taro 依赖的失败分类与标准快照阶段纯函数。
- `apps/client/src/lib/read-authority.test.ts`：覆盖六类输入与初始/保留快照的五阶段矩阵。
- 十一种读取模型：保留原导出名和类型名，把相同分类器重新导出到共享内核。
- 九种标准快照模型：保留原导出名，把相同阶段函数重新导出到共享内核。
- 聚合历史和同意历史：保留各自的继续加载、折叠与保留旧数据阶段，没有为了减少字节改变行为。
- `apps/client/client-quality-budget.json`：H5 最大异步上限收紧到 152,000 字节，WeApp 总量上限收紧到 1,107,000 字节。
- 架构、路线图、R-009、项目状态与 ADR-0140 同步记录结构、产物证据、预算和剩余风险。

本轮没有修改 UI、文案、样式、路由、API、数据库、隐私内容、AI 或外部服务。

## 3. 实现方法

### 从生产产物回到源码重复

第 145 轮 WeApp 最大页面仍低于 63,000 字节门禁，主要体积位于 `taro.js`、`app.js`、`common.js` 和 `base.wxml`。不改平台运行时和模板后，审计跨页面源码发现相同失败分类与快照阶段被多个模型逐字复制；这些函数正适合进入已有异步共享代码，而无需减少用户表达。

### 只共享完全相同的权限判定

共享内核只接受一个未知错误，或三个布尔状态。它不知道页面主题、当前数据、文案、操作、焦点或持久化，因而不能扩张权限。各模型用重新导出保留公共 API，类型别名在编译时消失，不引入运行时包装器。

### 不统一特殊状态机

聚合历史的已接受前缀在忙碌时使用 `continuing`，同意历史还有 `collapsed`、`refreshing`、`continuing` 和 `retained-stale`。这些差异与游标和生命周期权限相关，继续由原模型实现；共享范围只包含逐字等价的五阶段函数。

### 双层测试证明等价

新测试直接锁定共享函数全部分支。原有页面/模型测试仍从旧导出路径导入并通过，因此同时证明重新导出兼容和每个表面的既有预期没有漂移。

### 先测量，再收紧预算

先按旧预算生产构建，确认 WeApp 减少 3,340 字节并超过 476 字节最低目标，H5 也没有成本转移。随后把 WeApp 总量门禁收紧 2,000 字节，把 H5 最大异步门禁收紧 8,000 字节；最终仍保留 1,888 与 2,266 字节余量，未来增长必须显式消耗而不能静默吃回全部收益。

## 5. 发现的问题与经验

- 包体归因不应只看最大页面；跨页面重复更可能进入共享业务块和小程序总量。
- 类型共享不会自动减少运行时字节，只有把相同函数指向一个实现才产生实际收益。
- 重新导出可以保留调用方 API，同时让打包器消除重复实现；现有分页面测试是兼容性的直接证据。
- 抽象边界必须服从权限语义。相同的普通快照阶段适合共享，不同的续页/折叠状态不应为了数字被参数化成一个大框架。
- 产物优化必须同时测量两端；本轮 H5 同样缩小，证明没有把 WeApp 成本转移到 H5 异步块。
- 优化收益若不进入预算，后续无意回归仍可能被旧门禁接受；收紧部分预算能在保留功能余量的同时固定成果。
- H5 入口只减少 4 字节且仍触发 webpack 建议警告，因此 R-009 不能因总量改善而关闭。

## 6. 全局状态、项目反思与下一步

本轮把重复读取权限判定收敛成一个小型、可测试的内核，在不删除用户信息或改变失败关闭行为的前提下恢复双端余量。WeApp 从只余 548 字节转为在更紧预算下仍余 1,888 字节，后续客户端安全功能重新具备可控空间。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，第 147 轮应重新排序。R-009 获得缓解后，当前最相邻的内部缺口是 R-013：同步便携导出的最终 50 MiB 拒绝发生在数据库行、对象图和格式化字符串已经形成之后。下一轮应先逐段审计数据与照片加载路径，只在精确持久化元数据足以保证超限时才提前拒绝，并用真实 PostgreSQL/对象存储夹具证明至少一类大对象不再建立；不能用估算误拒绝合法导出。

本轮未新增、关闭或调整风险等级。R-009 因 H5 入口和真机证据继续开放；R-013 未被本轮客户端结构变化缓解。真实云服务、账号、域名、设备与付费 API 继续停放。
