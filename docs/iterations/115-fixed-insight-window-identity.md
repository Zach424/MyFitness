# 第 115 轮：固定洞察窗口身份一致性

日期：2026-08-10

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有 Dashboard 趋势、动作洞察和健康洞察的三个固定窗口身份。每个响应必须按索引精确返回 `[7, 30, 90]`；重复窗口造成的身份缺失、错序或替代都必须失败关闭。

验收标准固定为：共享校验器同时保护三个 Schema；Dashboard 在 `trends[index].days`、动作/健康在 `windows[index].days` 给出精确 Issue。正常生产构造器继续通过，动作/健康未来点检查仍执行。不得修改窗口 SQL、统计值、营养序列、客户端、响应形状、持久化、计划算法、AI 或健康结论。

- `apps/api/src/insights/insights.service.test.ts`：现有 Dashboard 用例新增 `[7, 7, 90]` 重复趋势窗口及 `trends[1].days` 精确路径证明。

## 3. 实现方法

### 把窗口身份从允许集合提升为有序元组

基础窗口 Schema 仍负责单项字段和允许枚举；顶层 `validateFixedInsightWindowDays` 接收三个窗口、响应字段名和 refinement 上下文，逐索引比较常量 `[7, 30, 90]`。数组长度由现有 Schema 先保证，因此校验器只处理身份，不重复结构验证。

长度为三但内容为 `[7, 7, 90]` 时，第二项虽然是允许枚举，却替代了必需的 30 日身份；校验器会在第二项失败。`[30, 7, 90]` 会在首项和次项失败，消费者不能再依赖一个表面合法但位置错误的数组。

### 保持独立一致性检查可组合

Dashboard 在现有日期、未来证据和个人状态账本 refinement 之前调用窗口校验。动作与健康从单一发生时间函数改为组合 refinement，先校验窗口身份，再逐点校验 `occurredAt <= generatedAt`。任何一类错误都产生自身路径，不因另一类错误短路。

### 不从有限点序列重算窗口

动作和健康公开点最多 180 个，并以 `hasMore` 表示截断；窗口统计可能覆盖更多原始事实，不能从公开点安全重建。本轮只固定时域身份，统计值继续由已验证 SQL 计算。营养拥有完整连续 90 日公开序列，仍采用更强的逐字段重算。

## 5. 发现的问题与经验

- “数组长度正确 + 每项枚举合法”不能证明集合完整；固定窗口是有序元组，不是允许值的多重集合。
- 重复窗口不仅是重复数据，也意味着另一个必需时域缺失；错误应定位到占用错误位置的元素。
- 共享一致性校验器适合跨响应复用，但字段路径必须由调用者传入，才能保持 Dashboard 与独立洞察的公开结构。
- 同一顶层 refinement 可以组合多个独立检查；不应因加入窗口门禁而覆盖未来发生事实校验。
- 有限公开点不能作为完整窗口统计的重算来源。只在证据集合完整时做逐字段派生，避免制造虚假的一致性。
- 纯服务端契约变化应使用类型、单元和集成回归证明；没有视觉影响时保留最近完整浏览器基线，不制造无意义截图差异。

## 6. 全局状态、项目反思与下一步

本轮确保三个核心纵向观察响应对“最近、月度、季度”使用唯一稳定身份，提高时间证据的可解释性与抗适配器偏差能力。它没有把固定窗口解释成目标、正常范围或健康结论。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处 Foundation Value 更高的缺口位于点级自然日：动作和健康 SQL 已按响应时区正确生成 `local_date`，但纯构造器与共享 Schema 只检查格式，未证明 `localDate` 等于 `occurredAt + timezone`。错误自然日会污染纵向趋势和变化起点解释。下一轮第 116 轮应重新排序；当前最高价值候选是 E/F（Temporal Modeling / Consistency Checking），在 180 点截断与身份派生前失败关闭错位输入，并由契约逐点验证，不重复修改 SQL 或改变记录原始时区。

本轮没有关闭 R-030/R-032：固定时域身份不能校准恢复阈值、证明证据完整性或替代真实用户理解。R-029 与双时态历史同样保持开放。
