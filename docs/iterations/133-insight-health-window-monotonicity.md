# 第 133 轮：健康跨窗口集合单调性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有健康 7/30/90 日嵌套窗口的跨行集合关系。

验收标准固定为：来源缺失窗口继续归一为空；按 7→30→90 比较时，`recordCount` 与 `recordedDays` 非递减；较短窗口非空时，较长窗口的 minimum 不得更高、maximum 不得更低；共享响应 Schema 独立执行同样规则并提供精确错误路径；非单调 average 必须保持合法。不得补造缺失统计、自动改值或修改 SQL、响应形状、分页、客户端、历史记录、计划、AI 与医疗解释。

## 3. 实现方法

### 先归一稀疏窗口

来源窗口仍可乱序或缺失。既有构造器先验证身份和单窗口关系，再按固定 7/30/90 日生成完整输出；缺失身份得到零计数、零记录日和空统计。单调性只比较归一后的相邻窗口，因此真实空的较短窗口可被后续非空窗口包含，但已有短窗口证据不能在更长窗口中消失。

### 只约束集合必然关系

记录数和有记录日数随包含范围扩大不能减少。若较短窗口有记录，较长窗口必须包含相同样本，因此 minimum 不能升高、maximum 不能降低。相邻比较已传递覆盖 7→90，无需增加重复的跨两级规则。

### 平均值保持无序

较长窗口加入的新样本可能使平均值上升或下降，所以只保留每个窗口内部的 `minimum <= average <= maximum`。测试显式使用 70→71→69，防止未来误加错误的单调规则。

### 来源和响应双层防御

来源构造器阻止数据库替身或适配器投影错误；共享 Schema 阻止其他生产者或传输层返回不可能的公开响应。两层使用同一固定窗口语义，但不自动修复任何冲突。

## 5. 发现的问题与经验

- 单个窗口内部合法不代表多个嵌套窗口能够同时成立；跨行不变量必须单独验证。
- 稀疏回退应先归一再比较，避免把“缺少零记录窗口行”错误升级为来源故障。
- 极值具有集合包含单调性，平均值没有；统计门禁必须基于数学必然关系，不能基于直觉。
- 相邻窗口比较足以建立固定有序链的传递约束，规则更小且错误路径更明确。
- 辅助函数不能插入链式 Schema 定义中间；格式化失败是语法边界信号，应先修复结构再继续验证。

## 6. 全局状态、项目反思与下一步

本轮关闭了健康 7/30/90 日窗口之间不可能的计数、记录日与极值组合，同时保留稀疏短窗口和无序平均值。它没有验证动作洞察完整课次、有限点前缀和 `hasMore` 的精确收据。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，健康路径已经形成完整计数—181 行来源收据—180 点公开前缀—更多标志与跨窗口集合关系。动作洞察仍只有通用点上限和标志门禁，`windows[90].sessionCount` 可以与训练点来源和公开前缀矛盾。下一轮第 134 轮必须重新排序；当前最小候选是先证明动作窗口和点 SQL 共享完成状态、动作身份、参考时刻与 90 日资格，再绑定课次计数、来源行数、公开点数和 `hasMore`。不得把组数当课次数、从有限前缀臆测历史或改变动作身份与聚合。

本轮未新增或关闭风险：集合单调性不证明动作收据一致、记录真实性、设备准确、健康范围、趋势意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
