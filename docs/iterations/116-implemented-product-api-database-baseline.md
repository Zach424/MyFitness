## 1. 范围、分类与验收标准

本轮分类为 H（Research & Understanding）与 F（Consistency Checking）。范围只有把当前已实现能力整理成三份可长期维护的中文权威文档：逐功能 PRD、全部 HTTP 接口参考和当前 PostgreSQL 数据库设计。它不改变页面、API、数据库、AI、计划算法、构建产物或运行行为。

验收标准固定为：PRD 必须从客户端和服务端代码提取具体入口、字段、操作、读取阶段、空/过期/失败状态、并发与响应丢失恢复、安全和无障碍边界；接口文档必须覆盖入库 OpenAPI 的全部操作并补充共享严格契约；数据库文档必须覆盖运行实例 `public` Schema 的全部基础表、28 个迁移、关键外键/索引/触发器和数据生命周期。三份文档进入中文门禁和 Markdown 迁移清单，不得把路线图候选写成已实现功能。

工作区开始时已有四个未提交洞察一致性文件：`packages/contracts/src/insights.ts`、`packages/contracts/src/insights.test.ts`、`apps/api/src/insights/insights.service.ts` 和 `apps/api/src/insights/insights.service.test.ts`。它们属于另一轮工作，本轮不修改、不暂存、不验证为本轮成果，也不纳入本轮提交。

## 3. 实现方法

### 从多种权威来源交叉提取

先读取项目状态、第 115 轮档案和 ADR-0110，再从 Taro 页面、客户端恢复库、共享 Zod 契约、Nest 控制器、入库 OpenAPI、SQL 迁移和运行 PostgreSQL 分层提取。界面文案只证明用户看见的交互，契约证明字段和跨字段边界，运行库证明迁移实际形成的表、列、索引与触发器；任何单一来源都不被扩大成完整现状。

### 把恢复语义提升为产品要求

主要页面共同区分首次加载、首次失败、就绪、旧快照刷新和过期保留；未知状态不能显示为空。新建幂等重试、修改/删除的精确读取协调、计划/AI 原请求协调、本地草稿和媒体物理删除边界都在 PRD 与接口文档中分别记录，避免只写“失败请重试”而丢失隐私和并发语义。

### 用机器集合证明清单完整

接口核对脚本从 `docs/api/openapi.json` 枚举 GET/POST/PUT/PATCH/DELETE，再逐个确认文档包含精确 method + path；首次核对发现结果回看和反思的四条真实路径使用 `/history/{revision}`，而草稿误写为 `/revisions/{revision}`，修正后达到 87/87。

数据库核对从 `information_schema.tables` 读取 `public` 基础表，再确认每张表均在数据库文档中以代码字面量出现，达到 39/39。列型、索引和本地活动行数分别来自 `information_schema.columns`、`pg_indexes` 与执行 `ANALYZE` 后的 `pg_stat_user_tables`；本地行数明确标为演示状态，不能当作生产容量基线。

## 5. 发现的问题与经验

- 接口路径不能只凭控制器领域命名或记忆整理；精确集合核对发现了四条 `/history/{revision}` 路径错误，说明 method + path 应作为接口文档最低机器门禁。
- “页面有按钮”不能证明操作可用。读取权限、当前 revision、计划 freshness、授权和风险资格共同决定按钮是否开放，PRD 必须记录门禁条件。
- 空、Unknown、旧快照和失败是四种不同产品状态。健身和隐私产品若把它们合并，会把没有证据误写成零或没有数据。
- 数据库文档必须区分当前态表、不可变 revision、JSONB 聚合快照和持久任务；只画一个 ER 图会遗漏响应丢失、媒体删除和账户擦除的关键证据链。
- API 与数据库文档天然含大量不可翻译字面量。为它们设专用中文占比阈值比降低全部文档门禁更精确，同时仍可用纯英文叙述行检查阻止正文回退。
- 开发实例行数有助于说明“当前已有数据库”，但测试/演示数据会变化，必须与结构基线和生产容量声明分离。

## 6. 全局状态、项目反思与下一步
