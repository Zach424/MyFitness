# 第 100 轮：产品风险登记册中文权威正文迁移

日期：2026-08-06

状态：已完成

## 1. 范围与验收标准

本轮只迁移 `docs/product/RISK_REGISTER.md` 的自然语言正文，并把它从待迁移专题唯一转入受中文门禁保护的活跃权威文档；不改变任何风险的状态、等级、顺序、关闭条件或审阅时点，也不修改产品运行行为。验收要求是：27 个风险和控制完整保留；标题、表格、代码、链接与数字结构签名不漂移；17 高/10 中分布不变；审阅元数据、控制职责、关闭条件和中文风险等级进入持久门禁；迁移索引计数同步；状态、路线图、架构、ADR、Obsidian 和 Git 归档完成。

## 2. 项目结构、设计、技术与实现功能

- `docs/product/RISK_REGISTER.md`：中文发布风险表，保留从身份、数据保管、AI/照片到部署、依赖与设备兼容的 27 个风险及下一门禁。
- `scripts/docs-language-policy.mjs`：将风险登记册加入活跃文档，并新增通用必需正文标记和禁用正文标记检查。
- `scripts/docs-language-policy.test.ts`：新增缺失受控标记与包含禁用标记两项回归。
- `scripts/docs-migration-inventory.mjs`：将风险登记册从 `topic-product-design` 移入活跃分类。
- `docs/DOCUMENTATION_MIGRATION_INDEX.md`：活跃文档更新为七份，专题待办更新为 17 份，总待办更新为 191 份。
- `docs/DOCUMENTATION_LANGUAGE_POLICY.md`：登记风险表的中文标题、正文比例、审阅元数据、职责、关闭条件和等级约束。
- `docs/architecture/decisions/0095-authoritative-product-risk-register-chinese-narrative.md`：记录风险结构保真、等级分布和时效边界。

## 3. 实现方法

### 保留风险而不是润色成完成

每行继续把“不确定性”放在风险列，把已有控制和下一门禁放在控制列。翻译没有把“配置、选择、部署、审阅、演练”改成完成时态，也没有因为后续仓库已有部分新证据而越权关闭第 043 轮记录中的条目。风险时效复核留给独立轮次。

### 同时核对结构与等级分布

迁移前从提交版本提取标题层级、表格行、行内代码、链接、代码围栏和数字令牌的有序签名；完成后用同一规则比较。风险等级从英文显示迁移为中文，不进入“字面量必须相同”的签名，而是独立统计候选表格中的高/中单元格，要求继续等于 17/10。

### 为无章节表格增加正文锚点

风险登记册只有一个一级标题，单靠标题和全文比例无法证明审阅时间、控制职责或关闭原则仍存在。因此活跃文档策略新增 `requiredTokens` 与 `forbiddenTokens`：前者固定三项治理锚点，后者拒绝英文等级回退。两个分支分别由单元测试覆盖。

### 原子转移迁移状态

同一变更从专题待办移除风险登记册，将其加入活跃文档与中文策略，并把人读索引的活跃数量和待办数量同步为 7 与 191。分类、语言和索引任一侧漏改都会失败关闭。

## 4. 验证证据

- 提交前/候选结构签名一致：1/1 个标题、29/29 行表格、3/3 个行内代码、0/0 个链接、0/0 个代码围栏和 36/36 个有序数字令牌完全一致；风险等级分布为 17/17 个高、10/10 个中。
- 定向 Vitest：迁移索引与中文正文策略共 14/14 通过；完整 Vitest 为 85 个文件、438/438 项通过。
- `pnpm docs:check-language` 通过：风险登记册包含 1,594 个汉字、199 个拉丁字母，中文占比 88.9%，纯英文叙述行为零；七份活跃权威文档全部超过 72%。
- `pnpm docs:check-migration-index` 通过：221 份 Markdown 恰好归类一次；七份活跃文档、一份治理规范、十一份当前迭代、十一份当前 ADR、17 份待迁移专题和 174 份待迁移历史完整且互斥，总待办为 191。
- 六个 TypeScript 工作区严格检查、全仓 Prettier、高风险生产依赖门禁与既有客户端产物复核通过；生产依赖为 0 个 critical/high、9 个已登记 moderate，客户端体积峰值沿用第 097 轮已构建证据。
- `docs/PROJECT_STATUS.md` 与 Obsidian 镜像逐字节一致；本档案在 vault 的 `iterations` 目录保存同名副本并通过 SHA-256 核验。

## 5. 发现的问题与经验

- 风险表的语气是控制的一部分。“需要验证”不能在翻译时变成“已经安全”，否则会无证据地绕过发布门禁。
- 风险等级是受控词汇，但应与结构签名分开验证：翻译需要有意把 `High`/`Medium` 改成“高”/“中”，同时维持数量分布。
- 单标题表格不适合只用导航标题保护；审阅元数据、职责列与关闭条件是更有价值的正文锚点。
- 最近审阅停留在第 043 轮本身就是重要事实。中文化完成并不表示第 044–100 轮新增证据已经被逐项回填。
- 缺失编号 R-001 和 R-018 属于既有历史结构，迁移不能为了视觉连续而重编号或补造风险。

## 6. 全局状态、剩余风险与下一步

当前七份活跃权威文档由中文门禁保护，专题待办剩余 API 说明、设计系统、11 个架构模型和四份运行手册，共 17 份；174 份历史档案仍等待迁移。风险登记册可直接中文审阅，但其证据时效仍停留在第 043 轮，不能据此判断 27 项风险的当前状态。

下一轮第 101 轮逐项核对第 043–100 轮的提交、测试和运行证据，关闭确已满足原门禁的风险，更新已有控制，并把未解决项分成本地可执行功能任务和必须等待用户/外部系统的阻塞项。托管部署仍不占用本地迭代编号，原生设备同步继续等待 MVP 留存门禁。
