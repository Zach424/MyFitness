# 第 106 轮：用户确认的计划体验反思

日期：2026-08-10

状态：已完成

## 1. 范围与验收标准

本轮只在既有计划结果页加入一条精确采用修订绑定的用户主观体验；不新增路由、自由文本、AI 调用、效果判断或自动适应。验收要求是：四个有界选项可首次保存和按预期修订纠正；删除真正移除内容；外部所有者、非采用和不存在修订不可探测；系统结果与反思读取权限分开，反思失败不能伪装成未填写；记录进入隐私清单、便携导出和账号擦除；H5/WeApp 包体预算不提高；文档、Obsidian 与 Git 完整归档。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/plan.constants.ts`、`plan.ts` 与测试：定义四项 `PlanExperienceChoice`、固定 `user_confirmed` 来源、读取信封和带 `expectedRevision` 的写入契约；周计划列表不再兼容携带完整结果投影。
- `infra/postgres/migrations/0028_plan_experience_reflections.sql`：新增所有者/计划/采用修订唯一记录、枚举检查、复合所有者外键、修订和时间戳索引边界。
- `apps/api/src/plans/`：新增所有者作用域 GET/PUT/DELETE；PUT 在事务和行锁中完成首次写入/纠正，DELETE 以精确修订硬删除，读取用对象信封表达“已确认不存在”。
- `apps/api/src/privacy/`：计划清单计数与最近时间包含反思；v4 导出把当前反思放入对应计划；账号擦除由所有者级联覆盖。
- `apps/client/src/pages/plan-outcome/`：系统证据和本人确认分别读取；四个语义按钮点选即保存，可显式纠正/删除；失败隐藏原始服务文案并聚焦重试。结果证据轨压缩为三行账本，以保留版本、来源、撤销和非因果边界。
- `apps/client/src/lib/api.ts`、`tests/e2e/plans.spec.ts` 与 OpenAPI：客户端适配器、真实 Chromium 新建/纠正/删除/503 重试、精确历史回看、刷新后返回降级和契约文档同步。
- `output/playwright/iteration-106-plan-reflection-mobile.png`：390 × 844 的本人确认体验证据。
- 项目状态、架构、计划模型、路线图、风险登记、ADR-0101 与本档案：同步本轮事实和第 107 轮包体前置门禁。

## 3. 实现方法

### 只接受用户能明确确认的有界事实

反思只允许“比预期轻松、安排合适、不适合我、还不能判断”。API 不接收备注，也不根据训练、恢复或缺失记录生成选择；来源始终由服务端固定为 `user_confirmed`。因此它能作为本人确认事实进入导出，又不会冒充模型结论或医学判断。

### 用精确采用修订和乐观修订保护纠正

每次读取/写入先验证同一所有者下的目标计划修订确实为 `accepted`。首次 PUT 要求 `expectedRevision=0`；纠正必须提交当前修订，数据库行锁后递增。冲突返回 409，不覆盖并发更新。DELETE 同样要求当前修订并硬删除反思内容；计划、训练和系统结果证据不受影响。

### 把“没读到”和“没有填写”分开

系统结果与反思使用独立请求代次和阶段。反思 GET 返回 `{ planId, planRevision, reflection }`，成功后的 `null` 才表示当前没有记录；传输失败只显示产品自有重试，不渲染选项为未填状态。卸载、重试和后续写入都会使旧响应失效。

### 以包体门禁约束表现复杂度

首版实现使 WeApp 超预算 7,039 字节。通过移除列表内联结果投影、把异步状态机改成 Promise 链、收敛重复文案与样式、把三段轨道改成紧凑证据账本，并保留共享键盘激活语义，最终在不提高预算的情况下通过。刷新后的独立页面若没有 Taro 返回栈，会定向返回计划页；正常进入仍使用原栈，避免重复计划页。

## 5. 发现的问题与经验

- Nest/H5 对顶层 `null` 的响应处理不稳定；显式对象信封能把“成功且不存在”和空响应可靠分开，也给未来 Schema 演进留出位置。
- Taro H5 的自定义 Button 不能只依赖裸点击属性。压包时一度移除共享激活封装，真实浏览器立即发现角色/焦点回归；最终恢复 `role`、`tabIndex`、Enter/Space 和 `aria-disabled` 语义，再从展示层减重。
- 204 DELETE 在 Chromium/Taro 组合中可能同时产生已收到 204 与 `net::ERR_ABORTED` 诊断；测试只隔离这一精确已验证的 DELETE 现象，仍要求 UI 删除、服务端复读和其他错误保持干净。
- `redirectTo` 会在已有计划栈中留下重复计划页；只在刷新导致当前页无返回栈时降级定向返回，普通路径必须保留 `navigateBack`。
- 有界枚举比自由文本更适合本阶段：它降低敏感内容与安全审阅面，但仍需用户研究验证四个选项是否足够且不诱导效果解读。

## 6. 全局状态、剩余风险与下一步

项目现在同时拥有系统观察结果和用户确认体验，两者在持久化、读取权限与 UI 中清楚分开。R-031 仍然成立：主动填写本身也有选择偏差，四档体验不能证明计划效果。反思纠正只保留当前内容，不是不可变审计历史；真实保留与用户理解仍需封闭测试审阅。

R-009 已成为下一轮的硬阻塞：WeApp 总包只余 5 字节，任何代码哈希或微小改动都可能触发门禁。第 107 轮只做客户端包体结构治理，优先测量重复页面样式、共享 API/无障碍代码与分包边界，至少恢复可解释的安全余量后再开发功能；不得直接提高预算或删减隐私、安全、无障碍语义。
