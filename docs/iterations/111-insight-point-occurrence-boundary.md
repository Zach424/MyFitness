# 第 111 轮：洞察点序列发生时间上界

日期：2026-08-10

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有健康与动作长期洞察的公开点序列：任何点的 `occurredAt` 都不得晚于响应 `generatedAt`。现有 PostgreSQL 窗口/点查询已经正确使用 `<= at`，本轮只补纯构造器与共享契约的独立防御。

验收标准固定为：纯构造器在 180 点截断及首点身份、规范单位、`hasMore` 推导前过滤未来行；共享健康/动作 Schema 在精确点路径拒绝未来时间；同一输入在推进参考时刻后必须重新接纳该点。窗口聚合不携带逐点时间，保持 SQL 权威，不从有限序列反推。不得新增 SQL、迁移、路由、客户端、AI、医疗、因果、营养目标或自动计划变化。

## 3. 实现方法

### 在截断和首点派生前过滤

两个构造器都从 `pointRows` 建立 `occurred_at.getTime() <= at.getTime()` 的合格集合。`series` 只映射该集合前 180 条；动作 `identity` 与健康 `canonicalUnit` 继续来自最终首点；`hasMore` 改为检查合格集合是否超过 180 条。未来行因此既不显示，也不占用配额或改变派生元数据。

### 用一个契约校验器守住两种响应

共用校验器读取顶层 `generatedAt`，遍历 `series` 并比较绝对时间。每个未来点都在 `series[index].occurredAt` 路径产生 `insight point cannot occur after generatedAt`，便于调用方和测试定位具体污染点。基础 datetime Schema 先保证两个时间可解析，跨字段校验只负责相对顺序。

### 用参考时间推进验证资格而非删除

动作测试给未来点使用独立训练 UUID 和不同名称；健康测试使用独立记录 UUID 与不同规范单位。原参考时刻下，两类投影仍以当前合法点开头并保留原身份/单位；参考时刻推进两小时后，未来点成为首点。这证明过滤依据是时间资格，而不是永久丢弃、输入排序或 ID 偶然碰撞。

### 保留窗口与点序列的职责边界

7/30/90 日窗口可能覆盖超过 180 条事实，且当前契约只携带聚合值，不能由有限点序列完整重算。因此本轮不伪造窗口一致性证明，也不重复修改已正确 SQL。后续若要求响应自身可审计窗口来源，应另行设计有界证据引用或完整聚合凭据。

## 5. 发现的问题与经验

- SQL 正确不能成为公共纯函数放弃边界校验的理由。纯函数也是测试、替代适配器和以后模块抽取的正式入口。
- 时间过滤必须早于上限截断。先截断会让未来点消耗有限配额，并可能把真实合格点挤出响应。
- `identity`、`canonicalUnit` 和 `hasMore` 都是点集合的派生事实；只过滤最终 `series` 而保留原始首点或原始长度仍会产生隐蔽不一致。
- 推进参考时刻比只断言“未来点不存在”更强，因为它证明同一输入会在资格满足后恢复，而不是被错误删除。
- 有限点序列不能证明完整窗口聚合。缺少逐点来源时应明确保留 SQL 权威，而不是构造看似完整的交叉校验。
- 绝对时间上界仍不证明 `localDate` 与响应 IANA 时区一致；R-029 和真实设备时区门禁继续开放。

## 6. 全局状态、项目反思与下一步

本轮把第 110 轮的发生时间原则扩展到两个独立长期观察表面，消除了替代数据路径让未来健康或动作点提前改变身份、单位和证据序列的可能。它提高了纵向状态的一致性、来源可审计性和参考时间可解释性，没有扩大产品功能范围。

全局复查显示，营养洞察 SQL 已正确生成截至 `at` 的 90 个本地日期，但 `buildNutritionInsight` 直接接受任意 90 行，共享 Schema 只检查长度和单日营养一致性；错序、重复、未来或与 `generatedAt`/timezone 不匹配的日期仍可能被测试夹具或替代适配器接受并改变 7/30/90 日窗口。下一轮第 112 轮应重新按全局缺口排序；当前最高价值候选是继续归类 F（Consistency Checking），为营养序列补参考本地日期、连续升序与窗口来源一致性，不重复已正确 SQL，也不把缺失摄入写成零。

本轮没有关闭 R-029：绝对 UTC 顺序不验证平台时区数据库或 `localDate` 映射。R-030/R-032 与双时态历史同样保持开放；点序列防御不会校准恢复模型，也不证明个人状态账本完整。
