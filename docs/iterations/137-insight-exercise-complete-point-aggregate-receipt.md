# 第 137 轮：动作未截断窗口与点聚合收据

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有动作 90 日未截断窗口的五项聚合与完整训练点集合之间的收据。

验收标准固定为：`sessionCount <= 180` 且点数完整时，来源/响应完成组与次数精确等于逐点总和，负荷、活动时间和距离只允许由来源数值表示或公开逐点舍入推导的有界误差；`sessionCount > 180` 时必须跳过完整聚合对账；真实 PostgreSQL 响应直接逐项证明窗口等于完整点集合。不得使用任意宽松容差、从截断前缀重算窗口、自动改值、解释训练效果或修改 SQL、响应形状、分页、客户端、历史记录、计划和 AI。

## 3. 实现方法

### 完整性先于聚合

第 134 轮已证明 `sessionCount <= 180` 时点数精确等于完整课次计数。聚合收据在该门禁之后运行；一旦课次超过 180，立即退出，不把最近前缀冒充完整训练集合。

### 来源整数精确、十进制有界

完成组和次数来源字符串已通过安全整数格式门禁，使用 `BigInt` 可以避免多点求和越过 JavaScript 安全整数时丢失精度。数据库十进制在进入构造器时转为 `Number`；全部值非负，没有抵消误差，因此容差只由机器精度、数值幅度和加法次数计算，并乘四保留运算余量，明显业务错配仍失败。

### 响应量化上界

窗口与每个点分别舍入。一个点最多贡献半个显示单位误差，窗口整体再贡献半个单位，因此 N 点差值上界为 `(N+1)×单位/2`。负荷和距离单位为 0.01，活动分钟为 0.1；再叠加同形式浮点加法误差。测试用两个点证明 480.26 对 480.25、10.2 对 10.1、1.02 对 1.01 都在合法边界内。

### 精确诊断而不修复

来源冲突使用领域级聚合收据错误；共享 Schema 分别定位 90 日窗口的完成组、次数、负荷、活动分钟或距离。两层都不重写窗口或点。

## 5. 发现的问题与经验

- 点数完整性必须先于聚合一致性；没有完整集合就没有总计收据。
- 整数与已舍入测量需要不同策略，统一浮点相等或统一宽松容差都不可靠。
- 量化误差上界应从点数和公开精度推导，而不是凭经验选择。
- `BigInt` 适合对来源十进制整数字符串和响应整数做精确累加。
- 直接 PostgreSQL 求和断言让 Schema 成功之外的关系证据更清晰。

## 6. 全局状态、项目反思与下一步

本轮关闭了未截断动作窗口与完整点集合之间的五项总计矛盾，同时保持截断边界诚实。它没有核对健康完整点集合与窗口统计。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，健康路径也已经用 `recordCount` 证明未截断集合完整；90 日 minimum、maximum 和 average 理应由完整规范值集合支持。下一轮第 138 轮必须重新排序；当前最小候选是先审计 `NUMERIC(14,4)` 点值、PostgreSQL AVG 精度和公开两位窗口统计，再定义来源与响应的精确或有界收据。必须保留合法负值，并在 `recordCount > 180` 时跳过完整统计对账，不引入范围、趋势或医疗解释。

本轮未新增或关闭风险：动作聚合收据不证明健康统计一致、训练记录真实性、动作执行安全、趋势意义、训练效果或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
