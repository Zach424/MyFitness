# 第 126 轮：洞察来源聚合 UUID 有效性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 D（Data Quality）与 F（Consistency Checking）。范围只有动作/健康洞察原始点的聚合 ID 运行时格式。

验收标准固定为：两个生产构造器必须在发生顺序和唯一性检查前拒绝任一无效 `workout_id`/`record_id`；检查覆盖完整来源数组，包括未来位置和隐藏第 181 点。无效格式必须与重复身份保持独立错误，合法 PostgreSQL UUID 与共享公开 Schema 保持兼容。不得生成、纠正或回查 ID，也不得修改 SQL、响应形状、分页、客户端、持久化、计划、AI 或健康结论。

## 2. 项目结构、设计、技术与实现功能

- `apps/api/src/insights/insights.service.ts`：新增共用 UUID 格式谓词和完整来源点扫描，动作/健康构造器在顺序/唯一性前调用。
- `apps/api/src/insights/insights.service.test.ts`：既有动作与健康投影用例分别让隐藏第 181 点携带无效 ID，并断言独立失败。
- `packages/contracts/src/insights.ts`：不修改；公开 `workoutId`/`recordId` 已有 `uuid()`，本轮保护被过滤/截断前的来源集合。
- `docs/product/IMPLEMENTED_PRD.md` 与 `docs/api/API_REFERENCE.md`：补充来源 UUID、全量扫描及与唯一性分离的契约。
- ADR-0120、架构、路线图、风险登记册、项目状态和本档案：同步门禁顺序、限制、无新增/关闭风险及第 127 轮候选。

本轮没有改变合法响应或错误 HTTP 映射；正常 PostgreSQL UUID 保持兼容。

## 3. 实现方法

### 与公开契约对齐的 UUID 格式

来源谓词验证八-四-四-四-十二十六进制分组、版本 1–8 和 RFC 标准变体，并允许大小写。它不接受任意连字符字符串、nil 标识或非标准变体。

### 全部来源点扫描

检查直接遍历构造器收到的原始数组，不以未来过滤或 180 点公开前缀为边界。隐藏第 181 点和当前未来点在参考时刻移动后都不会突然成为无效公开身份。

### 格式与唯一性分层

UUID 格式先于顺序和唯一性，因此重复集合只由已证明可比较的身份组成。无效格式不会被误报为重复，也不会生成替代身份；共享 Schema 继续在传输表示上独立验证。

### 不把格式冒充所有权

UUID 只证明表示结构。记录存在性、用户所有权和聚合类型仍由所有者作用域 SQL 保证；本轮没有增加数据库读取或跨聚合查询。

## 5. 发现的问题与经验

- 唯一性只对有效身份有意义；任意字符串集合无重复不代表可作为聚合引用。
- 公开 UUID Schema 看不到被截断的来源行，不能替代构造边界全量扫描。
- 格式错误、重复身份和所有权错误属于不同故障，应保留可诊断的分层语义。
- UUID 格式不证明存在性、所有权、聚合类型或记录真实性。
- 非数值来源字段仍有相同的静态类型信任缺口，需要继续按领域拆分。

## 6. 全局状态、项目反思与下一步

本轮关闭了无效来源聚合 ID 参与顺序/唯一性并进入公开投影的路径，同时保护隐藏截断行。它没有查询、替换或推断任何 ID。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处候选缺口位于动作来源快照。名称、类别、追踪模式、器械与备注主要由静态类型/公开 Schema 保护；替代适配器仍可能在纯构造阶段返回空白/超长文本、未知或重复枚举及 `other` 备注错配。下一轮第 127 轮必须重新排序，当前最小候选是复用共享语义验证完整来源点，同时保留历史快照，不回查当前目录。

本轮未新增或关闭风险：UUID 格式门禁不证明记录存在、所有权、真实性、来源字段有效、跨窗口完整性或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
