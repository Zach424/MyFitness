# 第 114 轮：Dashboard 参考本地日一致性

日期：2026-08-10

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有 Dashboard 最终响应中的 `generatedAt`、`timezone` 与 `today.date`。生产构造器已正确计算日期，本轮只要求共享契约独立证明响应时区可解析、日期精确等于参考时刻在该时区的本地日。

验收标准固定为失败关闭：无效时区在 `timezone` 路径失败，格式正确但偏移的日期在 `today.date` 路径失败；跨 UTC 日界的上海次日本地日必须通过纯构造器和契约。不得修改 SQL、服务构造器、端点、客户端、周计划选择规则、持久化、时区探测、AI 或健康结论。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/insights.ts`：把已由历史/营养使用的本地日期辅助函数提升到 Dashboard Schema 之前；Dashboard 时区收紧为非空有界值，顶层 refinement 新增时区解析与参考本地日校验。
- `apps/api/src/insights/insights.service.test.ts`：现有 Dashboard 聚合用例新增错误 `today.date` 与无效时区的精确 Issue 路径；无证据用例改用跨 UTC 日界参考时刻并证明上海本地日进入次日。
- ADR-0109、架构、路线图、风险登记册、项目状态和本档案：同步日期权威、R-029 限制、验证范围和下一轮固定窗口身份候选。

本轮没有视觉、接口形状或正常响应变化。生产构造器继续返回相同本地日期；新增边界只阻止内部不一致响应发布。

## 3. 实现方法

### 复用唯一 IANA 本地日期映射

`localDateInTimezone`、自然日移动与预期序列辅助函数从历史 Schema 前移到 Dashboard Schema 前。Dashboard 只调用本地日期映射；历史和营养继续复用完整序列函数。这样三个响应不会各自实现不同的时区格式化规则。

### 在最终响应边界精确定位错误

顶层 Dashboard refinement 先尝试把 `generatedAt` 映射到响应时区。IANA 时区无效时添加 `timezone` Issue；解析成功但 `today.date` 不相等时添加 `today.date` Issue。现有未来发生事实和个人状态账本一致性检查仍继续执行，避免一个日期错误掩盖其他独立缺陷。

### 证明 UTC 日界不等于请求本地日界

测试把无证据 Dashboard 的参考时刻设为 `2026-07-17T16:30:00Z`。该时刻在上海已是 `2026-07-18`，构造器返回次日本地日且共享契约接受；同一完整响应若把日期改回 `2026-07-17` 则失败。该证明不依赖固定偏移计算，而是执行真实 IANA 格式化。

## 5. 发现的问题与经验

- 日期格式正确不代表日期权威正确；任何会驱动计划选择的本地日期都必须绑定到同一响应的参考时刻和时区。
- UTC 日期不能代替请求本地日期。靠近 UTC 日界的测试比中午时刻更能证明时区映射真实执行。
- 查询参数校验不替代响应校验；替代实现、夹具或内部模块仍可能在已验证输入之后构造错误输出。
- 错误路径应指向用户可定位的字段。时区与日期分别报告，避免用一个顶层错误掩盖来源。
- 正常生产构造器已经正确时，不应为强化契约重复修改 SQL 或客户端；失败关闭边界本身就是最小可逆修复。
- 纯服务端契约变化不需要制造新的视觉基线；完整单元/集成与最近浏览器基线应明确区分，而不是把未重跑写成已运行。

## 6. 全局状态、项目反思与下一步

本轮把 Dashboard 的“今日”从格式正确的字符串提升为可由响应自身证明的参考本地日，保护首页与周计划选择免受日期偏移。它没有新增时间推断、健康判断或客户端默认时区。

全局复查显示，Dashboard 趋势、动作洞察和健康洞察的生产构造器都按 `[7, 30, 90]` 生成窗口，但共享 Schema 只要求三个元素且每项 `days` 属于允许枚举；重复、缺失或错序窗口仍可通过。营养窗口已在第 112 轮逐字段绑定到 90 日序列。下一轮第 115 轮应重新按全局缺口排序；当前最高价值候选是继续归类 F（Consistency Checking），只为三个非营养响应补固定窗口身份与精确路径证明，不改统计 SQL、客户端或产品语义。

本轮没有关闭 R-029：服务器契约的 IANA 映射不能证明真实 H5/微信平台时区数据或客户端探测一致。R-030/R-032 与双时态历史同样保持开放。
