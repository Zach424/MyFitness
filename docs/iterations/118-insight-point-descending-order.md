# 第 118 轮：洞察点发生时刻非递增

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 E（Temporal Modeling）与 F（Consistency Checking）。范围只有动作与健康洞察点的最新优先时间顺序。

验收标准固定为：两个生产构造器必须在未来点过滤、180 点截断、首点身份/规范单位和 `hasMore` 派生前，验证全部输入行的 `occurred_at` 非递增；第 181 行的升序断点也必须失败。两个共享 Schema 必须逐点验证公开 `series.occurredAt` 非递增，并把错误定位到首个较新的后项。相同时刻必须允许，因为公开响应没有 `createdAt`，不能证明数据库内部完整排序。不得静默排序，也不得修改 SQL、窗口统计、客户端、响应形状、持久化、计划算法、AI 或健康结论。

- `packages/contracts/src/insights.ts`：新增共享 `validateInsightPointOrder`，对两个公开序列给出 `series[index].occurredAt` 精确错误，同时继续执行固定窗口、响应本地日和未来点门禁。
- `apps/api/src/insights/insights.service.test.ts`：两个现有投影用例都把最新点放到第 181 行，证明它不会被截断掩盖。

- ADR-0112、架构、路线图、风险登记册、项目状态和本档案：同步时间顺序、验证范围、无新增/关闭风险和第 119 轮候选。

本轮没有在构造器内排序，也没有把数据库的 `created_at/id` 次序伪装成公开契约。正常生产查询结果与响应字节形状不变。

## 3. 实现方法

### 在最早会影响证据选择的位置失败关闭

如果只验证已截断的 180 点，第 181 行可以是更近事实却被 `hasMore` 隐藏。构造器因此在未来过滤和切片之前扫描全部输入，相邻后一项绝对时刻大于前一项即失败。最多 181 行的线性扫描不复制、不排序，也不改变点对象。

### 契约只声明公开字段可证明的顺序

公开响应包含 `occurredAt`，不含 `createdAt`。契约因此只要求非递增：后项不得更晚；相等合法。数据库仍使用创建时刻和 UUID 为相同发生时刻提供稳定内部顺序，但消费者不能从响应中验证或依赖该细节。

### 不用“修复排序”掩盖上游错误

构造器排序可以产出表面正确响应，却会掩盖数据库查询、替代适配器或夹具退化，并可能在截断前选错点。本轮选择抛错，让问题在服务边界暴露；共享 Schema 则为替代响应提供精确位置。

### 时间边界保持正交

非递增只证明相邻点顺序；响应时区、本地日期与参考时刻资格仍由既有独立门禁验证。相同自然日可包含多个绝对时刻，日期一致不能替代顺序；顺序正确也不能证明点不在未来。

## 5. 发现的问题与经验

- “SQL 已排序”不能证明纯构造器或替代适配器保持顺序；派生首点和截断之前需要独立门禁。
- 截断边界外的一行仍会影响 `hasMore` 和证据选择，验证不能只覆盖最终公开数组。
- 最新优先是非递增，而不是严格递减。用户可在同一时刻形成不同聚合，公开字段不足时不能强加虚假次序。
- 静默排序让响应看起来正确，却降低故障可观察性；证据系统应优先暴露错误来源。
- 时间资格、自然日和序列顺序是三个不同不变量，应该分别校验并保留各自路径。
- 权威 PRD/API 不应只列接口和点数，还要记录消费者可以安全依赖的时间语义。

## 6. 全局状态、项目反思与下一步

本轮保护动作与健康纵向观察的时间方向，避免旧事实覆盖最新身份、更新事实落入隐藏第 181 行或图表出现逆序。它没有从顺序生成趋势、变化点、异常或因果判断。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处 Foundation Value 较高的缺口位于证据身份。生产 SQL 为每个训练/健康聚合返回唯一 UUID，但纯构造器和共享契约都允许重复 `workoutId`/`recordId`。重复点会把一条事实伪装成多条纵向证据并污染 `hasMore`。下一轮第 119 轮必须重新排序；当前候选是在全部最多 181 行输入中失败关闭首个重复聚合 ID，再由契约定位公开重复项，绝不静默去重。

本轮未新增或关闭风险：顺序一致性不能证明趋势、因果、模型校准、证据完整性或用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
