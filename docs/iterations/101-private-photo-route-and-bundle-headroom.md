# 第 101 轮：私有照片路由与客户端包体余量

日期：2026-08-10

状态：已完成

## 1. 范围与验收标准

本轮只处理照片识餐与进度照片共享条件路由造成的客户端包体临界风险，不改变照片 API、存储、同意、保留、确认、删除或 AI 提供方行为。验收要求是：两个用途成为独立注册页面；饮食页确认返回语义不变；H5 和 WeApp 都能重建并通过既有预算；真实浏览器能分别进入两个工作台；新增回归、全量门禁、风险状态、架构决策、Obsidian 与 Git 归档完成。

## 2. 项目结构、设计、技术与实现功能

- `apps/client/src/pages/food-photo-workflow/index.config.ts`：为照片识餐增加专用 Taro 页面配置。
- `apps/client/src/pages/progress-photos/index.tsx`：移除食物照片静态导入和 `kind=food` 条件分派，只保留进度照片页面。
- `apps/client/src/pages/nutrition/index.tsx`：导航到 `pages/food-photo-workflow/index`，仍通过单次 `EventChannel` 接受服务器已确认的目录键与整数克数。
- `apps/client/config/index.ts`：增加只面向异步块、且至少被两个块复用的 `client-async-shared` 缓存组；发生时间字段专用块保持更高优先级。
- `apps/client/src/lib/detected-time-zone.ts`：把启动所需的轻量时区探测从完整发生时间解析器中分离；原模块重新导出函数，调用兼容不变。
- 七个页面配置删除重复 `navigationStyle: 'custom'`，继续由 `app.config.ts` 统一拥有导航样式。
- `apps/client/src/private-photo-routes.test.ts`：锁定两个独立路由、专用营养入口、无旧条件分派、异步公共块和应用级导航配置权威。
- `pnpm-workspace.yaml` 与 `pnpm-lock.yaml`：移除未使用的 Less `image-size` 可选解析器，并把受影响的 `nanoid` 3.3.16 提升到 3.3.17，关闭提交时新出现的三项 high 公告。
- `docs/architecture/FOOD_PHOTO_MODEL.md`、架构基线、风险登记册、路线图与 ADR-0096：同步新的页面边界、包体策略与仍未关闭的发布门禁。

## 3. 实现方法

### 先建立真实基线

本轮开始时，H5 总量/入口/最大异步块为 2,838,465/319,238/205,756 字节，WeApp 总量/vendor/最大页面为 1,093,598/19,338/55,697 字节。最大 H5 异步块对应进度照片路由，因为它静态携带完整照片识餐工作台。

### 把业务用途边界变成构建边界

先注册专用照片识餐页面并删除条件路由。饮食页仍拥有返回通道，因此确认后的非敏感草稿输入语义不变；直接访问、敏感媒体和保留状态边界也不变。这样页面责任与代码分块一致，不再依赖查询参数决定加载另一整套工作台。

### 用实测纠正直接拆分造成的重复

直接路由拆分使相同运行时、组件和工具被多个延迟块复制，H5 总量上升到 3,006,449 字节并触发失败关闭。随后使用 `minChunks: 2` 的异步公共块抽取真实复用模块，并保留发生时间字段的高优先级专用块。该规则不把页面自有代码合并，也不改变数据权限，只消除交付重复。

### 缩小启动依赖表面

应用初始化只需要一次当前时区字符串。把 `detectedTimeZone` 拆到独立模块后，入口不再为了一个小函数加载完整的本地时间、偏移、DST 与校验实现；原导出位置保留，避免无关调用方迁移。

### 对提交时变化的依赖公告失败关闭

最终审计发现锁文件基线之后新出现的两个 `image-size` high 公告和一个 `nanoid` high 公告。仓库没有 Less 文件，也不使用其图像尺寸函数，因此从 Less 3.13.1/4.6.7 的可选依赖边移除 `image-size`；`nanoid` 使用同主版本补丁 3.3.17。冻结重装后 `image-size` 不再出现在依赖图，`nanoid` 只有 3.3.17，随后重新执行双端生产构建与完整门禁。

- 客户端 TypeScript 严格检查通过。
- H5 生产构建通过：总量 1,193,322 字节、入口 315,096 字节、最大异步块 200,006 字节，预算分别为 2,842,000/320,000/206,000 字节。
- WeApp 生产构建通过：总量 1,094,282 字节、vendor 19,338 字节、最大页面 55,672 字节，预算分别为 1,098,000/25,000/56,100 字节。
- WeApp `app.json` 同时注册 `pages/food-photo-workflow/index` 与 `pages/progress-photos/index`，页面脚本分别为 20,867/26,332 字节。
- Playwright 定向真实浏览器回归 2/2 通过：照片识餐初始传输中断保持未知；进度照片刷新被拒绝后保留一项已接受私有证据。
- 生产依赖审计从临时发现的 3 个 high/9 个 moderate 恢复为 0 个 critical/high、9 个已登记 moderate；完整格式、文档语言、迁移索引和 Obsidian 门禁在提交前执行并记录最终结果。

## 5. 发现的问题与经验

- 把一个条件路由拆成两个页面不等于自然减少总包；在 Taro/webpack 中，相同异步依赖可能复制到每个页面，必须同时观察总量、入口和最大异步块。
- 公共块应该由真实复用次数触发，并低于领域专用块优先级；按目录无条件抽取会把只被一个页面使用的代码错误提升为全局成本。
- 页面用途边界与隐私边界应一致。照片识餐和进度照片共用基础设施，不代表它们应该共用页面、同意、文案或保留权限。
- 启动路径上的小导入可能拖入完整工具模块。对只需一次的时区探测建立轻量模块，比提高入口预算更能保留后续余量。
- 删除重复页面配置能建立单一权威，但 Taro 会在产物中物化继承配置，因此该清理改善维护性，不应被声称为本轮入口体积下降来源。
- 依赖审计结论具有时间性。即使本轮开始时是零 high，也必须在最终锁文件和构建产物确定后再次审计；对于未使用的可选解析器，删除依赖边比强行跨主版本覆盖更可验证。

## 6. 全局状态、剩余风险与下一步

客户端两个私有照片用途现在拥有独立页面边界，H5 总量相比本轮基线下降 1,645,143 字节，入口减少 4,142 字节，最大异步块减少 5,750 字节；WeApp 仍在严格预算内。R-009 只获得了新的本地构建和 Chromium 证据：H5 入口仍超过 webpack 通用建议警告，微信真机、代表性浏览器、弱网首载与正式分包行为仍未验证，所以风险保持中等级。

下一轮第 102 轮恢复风险登记册证据时效复核，逐项核对第 043–101 轮可复现证据，只关闭满足原门禁的项目，并把剩余项目分成本地可执行任务和必须等待账号、域名、预算、凭据、责任人、政策或外部系统的阻塞项。
