# 第 136 轮：动作窗口零证据语义

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有单个动作窗口中课次、完成组和四项测量总计的零证据关系。

验收标准固定为：零课次不得携带非零完成组；零完成组时次数、负荷、活动时间和距离必须全零；来源构造器与共享响应 Schema 双层失败关闭并提供可定位错误；有课次和完成组但四项测量全零必须保持合法。不得反向要求训练量为正、补造数据、判断动作质量或修改 SQL、响应形状、分页、客户端、历史记录、计划和 AI。

## 2. 项目结构、设计、技术与实现功能

- `apps/api/src/insights/insights.service.ts`：扩展来源动作窗口关系门禁，绑定零课次、零完成组和原始测量总计。
- `apps/api/src/insights/insights.service.test.ts`：覆盖零课次携带完成组、零完成组携带次数/负荷/时间/距离，并增加有完成组但测量全零的合法投影。
- `packages/contracts/src/insights.ts`：共享动作窗口 Schema 增加完成组与四项测量的精确零证据问题路径。
- `packages/contracts/src/insights.test.ts`：覆盖五类响应失败，并证明三个有课次窗口都可保持零测量。
- ADR-0130、架构、已实现 PRD、接口参考、路线图、风险登记册、项目状态和本档案：同步 SQL 空集合语义、非阈值边界与第 137 轮候选。

本轮没有改变合法响应形状、查询、集成夹具或客户端行为。

## 3. 实现方法

### 从 SQL 资格推导存在性

窗口查询只对已完成组连接结果计数。任一已完成组都会使其训练 ID 进入 `sessionCount`，所以零课次不能伴随非零完成组。次数、负荷、活动秒数和距离也都只在同一已完成组集合上求和，并在空集合上 `COALESCE` 为零。

### 单向约束而非正值阈值

规则只从“没有完成组”推出“四项总计为零”。它不从“有完成组”推出任何测量为正，因为一次合法完成可以没有次数、负荷、时长或距离覆盖。正向反例同时在来源构造器和响应 Schema 中保持通过。

### 来源与响应双层防御

来源层在数值合法后统一拒绝不可能的行关系；响应窗口在解析数字后分别对完成组和每项测量添加精确问题路径。两层都不修正、清零或补造冲突字段。

## 5. 发现的问题与经验

- `sessionCount <= completedSetCount` 只提供上界，不能完整表达空集合的存在性语义。
- 零证据关系必须保持单向：无完成组要求总计为零，有完成组不意味着任一测量必须为正。
- 将四项字段逐一定位比统一根级错误更利于发现替代生产者的具体漂移。
- 来源失败可以复用领域级关系错误，而公开契约仍应保留字段级诊断。
- 一致性门禁不能借机引入训练强度或动作质量阈值。

## 6. 全局状态、项目反思与下一步

本轮关闭了单个动作窗口中的幽灵完成组和幽灵测量总计。它没有核对完整训练点集合的聚合和窗口总计。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，当 90 日 `sessionCount <= 180` 时，公开点已经由收据证明是完整集合，理论上可以把完成组与次数精确求和，并在明确逐点舍入误差内核对负荷、活动时间和距离。下一轮第 137 轮必须重新排序；当前最小候选是先定义来源十进制精度、整数精确比较和响应有界容差，再只对未截断窗口建立收据。`sessionCount > 180` 时必须跳过完整聚合对账，不得从有限前缀推断窗口。

本轮未新增或关闭风险：零证据语义不证明窗口与完整点聚合一致、训练记录真实性、动作执行安全、趋势意义、训练效果或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
