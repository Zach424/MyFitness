# 第 104 轮：所有者作用域的历史计划结果回看

日期：2026-08-10

状态：已完成

## 1. 范围与验收标准

本轮只补齐旧 `accepted` 计划修订的只读结果回看，不接入云服务、真实 AI、设备数据，也不生成效果方向或自适应建议。验收要求是：认证所有者能按计划 UUID 与正整数修订读取真实采用快照；当前计划推进后旧采用版本仍可读取；跨所有者、非采用或不存在修订统一隐藏；结果基于当前确认事实重算；解除关联和已删除恢复记录不再成为 Observed 证据并有明确撤销计数；客户端初始失败不伪装为空，提供可聚焦重试且拒绝迟到响应；契约、领域、API、H5/WeApp、文档、Obsidian 与 Git 都有可复现证据。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/plan.ts`：为结果回看增加严格的 `withdrawnEvidence` 计数，并增加正整数计划修订解析器；OpenAPI 继续从同一 Zod 契约生成。
- `packages/domain/src/plan-outcome.ts`：结果投影接受撤销证据，保持 Unknown/Observed 原语义，并在存在撤销项时增加明确限制说明。
- `apps/api/src/plans/plans.service.ts`：把当前与历史结果计算收敛到同一个投影器；恢复记录按计划 ID/修订窗口分组，同时查询已解除/训练已删除关联和窗口内已删除恢复记录。
- `apps/api/src/plans/plans.controller.ts`：新增所有者作用域的精确历史结果路由，限制正整数修订，统一隐藏非采用/外部目标，并设置 `Cache-Control: private, no-store`。
- `apps/client/src/lib/api.ts` 与 `apps/client/src/pages/plans/`：采用历史行新增独立回看入口，复用证据链组件；加载、失败、重试、成功状态互斥，页面代次拒绝切换计划、选择其他修订或卸载后的迟到响应。
- `apps/api/src/plans/plans.integration.spec.ts` 与 `tests/e2e/plans.spec.ts`：用真实 PostgreSQL 与 Chromium 证明当前计划推进到 v11 后仍可读取历史采用 v3，已删除恢复记录只进入撤销计数，非采用/外部访问失败关闭，第一次服务中断不会发布空结果或原始消息。
- `docs/api/openapi.json`、计划模型、架构基线、路线图、风险登记、ADR-0099、本档案与项目状态：同步接口、边界、包体余量和下一轮方向。

## 3. 实现方法

### 以不可变采用快照选定历史时域

精确路由先在 `weekly_plan_revisions` 中限定所有者、计划 ID、修订与 `accepted` 动作，再从同一计划向前选择最近的 `generated` 快照。采用时刻来自目标快照的 `changed_at`，观察结束仍固定为七天，因此当前周计划的状态或修订不会改变旧回看的时间边界。

### 复用实时投影而不保存过期结果

当前列表和历史精确读取都把采用上下文交给同一个投影器。训练证据必须保留同计划修订的活动关联；恢复证据必须仍是当前未删除、已确认且非 AI 的主观记录。结果不落新表，因此解除关联、训练删除或恢复删除会立即撤回证据权限，避免旧缓存继续显示用户已经撤销的敏感事实。

### 把撤销与“从未观察到”分开

投影额外计算时间窗内已解除/训练已删除关联数和已删除恢复记录数。它们不进入证据列表和 Observed 总数，只作为“已排除”计数显示。这样 Unknown 仍表示当前没有合格证据，同时用户能看见部分证据曾被撤销；计数不恢复内容、不解释原因，也不推断计划效果。

### 为历史读取建立独立客户端权限

历史回看只在用户明确点击采用修订后读取。读取中的修订、失败标记或成功投影保存在 React 页面内存；失败只显示产品自有文案和同修订重试，H5 延迟聚焦重试按钮。每次选择与卸载都会推进代次，只有仍匹配的响应可以提交，因而迟到结果不能覆盖后来选中的修订。

## 5. 发现的问题与经验

- 历史结果不是保存一次就永远正确的报告。用户删除或解除关联是在撤回证据的当前可见权限，历史回看必须实时重算或清楚记录快照保留语义。
- Unknown 单独出现时无法区分“从未有记录”和“记录后来被撤销”。只公开有界计数可以改善解释，同时避免恢复敏感内容或夸大审计能力。
- 当前与历史路径若各写一套查询，很容易在时间窗、状态筛选或限制文案上漂移。共享投影器让同一修订在两个入口保持同一结论。
- 独立历史按钮需要自己的读取权限和代次；沿用整个历史列表的加载状态会让一个小请求错误冻结无关的历史浏览。
- 严格包体门禁揭示计划页已到拆分点。靠缩短文案只适合本轮最小交付，下一项计划功能应优先延迟加载或迁移到独立页面。

## 6. 全局状态、剩余风险与下一步

项目现在能从当前计划进入结果回看，也能在同周计划被重新生成、修改或跳过后按所有者和精确采用修订重新读取旧证据链。旧回看描述当前仍被确认的事实，并明确显示已排除的解除关联/删除计数；它仍不判断效果、依从性或因果。固定七天窗口、主动记录偏差、删除原因不可见和更正移出时间窗未被单独计数继续属于 R-031。

下一轮第 105 轮优先把“系统观察到的记录”与“用户自己确认的计划体验”分开：为精确采用修订增加一条可更正、可删除、来源明确的主观反思，例如更容易、合适、不适合或尚未判断。该事实必须由用户主动填写，不由证据计数推断，不自动修改计划，也不得宣称效果或医学结论；实现前先设计保留、导出、删除和包体拆分边界。
