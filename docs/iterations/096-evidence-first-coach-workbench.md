# 第 096 轮：证据优先教练工作台

日期：2026-08-06

状态：已完成

## 1. 范围与验收标准

本轮只把首页“教练”占位入口补成一个本地可运行、只读且证据优先的周工作台；不接真实模型、云服务、设备平台或外部账号。验收要求是：复用同一次可信读取，不创建第二份数据权威；先展示 7 天已确认记录，再展示当前周计划与显式训练关联，最后展示 AI 边界；未读取、确认无计划、过期快照和服务失败不混淆；没有计划时不出现 AI 档案入口；320 px 与桌面 H5 无水平溢出且控件不重叠；H5/WeApp 构建和包体门禁通过；状态、路线图、架构、ADR、Obsidian 与 Git 同步完成。

## 2. 项目结构、设计、技术与实现功能

- `apps/client/src/pages/index/coach.model.ts`：纯 TypeScript 展示模型，选择包含当前日期的周计划，计算计划课次数/分钟数，并只统计当前计划修订的显式关联。
- `apps/client/src/pages/index/coach-workbench.tsx`：Taro 4 + React 只读工作台，按“记录 → 计划 → AI”顺序呈现，复用首页刷新、失败和旧快照权限。
- `apps/client/src/pages/index/coach-workbench.scss`：沿用现有设计令牌，以训练记录夹“证据脊柱”为唯一视觉签名；手机单列、桌面 980 px 有界布局，提供可见焦点和减少动态效果规则。
- `apps/client/src/pages/index/index.tsx`：底部“教练”从占位反馈改为同路由标签；“今日”和“教练”共享同一仪表板/计划状态与刷新操作。
- `tests/e2e/today.spec.ts`：新增 320 px/1280 px 浏览器回归，检查信息顺序、空计划权限、AI 入口、当前导航、水平溢出和桌面顶栏重叠。
- `apps/client/client-quality-budget.json`：仅把 H5/WeApp 总文件树预算各增加 20,000 字节；入口、最大异步块、vendor 和最大页面预算不变。
- `output/playwright/iteration-096-coach-mobile.png`：保留本轮 320 × 844 真实构建截图。

## 3. 实现方法

### 使用一个原子读取权威

“今日”原本会并发读取仪表板与周计划，并且只有两者都成功时才接受新快照。本轮直接从这两个已接受值计算教练展示，没有增加第二次 GET、持久缓存或后台轮询。刷新失败时，教练与今日同时保留上一份完整快照，因此不会出现“新记录配旧计划”。

### 把事实、计划和 AI 分层

第一段只显示 7 天窗口内的有记录天数、身体/恢复条数、训练次数/分钟/训练量和餐次，并明确它们不是达标率。第二段只选择日期范围包含今天的周计划；显式关联必须同时匹配当前计划修订和计划课次日期。第三段只解释 AI 档案的权限和来源；没有计划时不渲染入口，有计划时也只进入既有只读档案，不自动调用模型。

### 用包体门禁推动架构收敛

首版创建独立教练路由，H5 总量达到 2,945,446 字节并被 2,815,000 字节门禁拒绝。分析确认独立块包含 121,683 字节 JavaScript 与 7,255 字节 CSS；随后改为首页同路由标签，消除完整路由运行时和重复读取。最终 H5/WeApp 相对第 095 轮只增加 18,887/17,264 字节。总量预算各增加 20,000 字节并保留约 3 KiB 余量，关键加载峰值预算完全不变。

### 视觉复核后修正桌面冲突

320 × 844 实测宽度为 320/320，无水平溢出。1280 × 900 首次截图发现既有桌面主导航遮住右侧更新按钮；最终把教练桌面顶栏收敛到左侧，更新按钮范围为 x=293–357，主导航为 x=901–1200，明确不重叠。设计没有加入额外图表或动画，避免稀释证据顺序。

## 4. 验证证据

## 5. 发现的问题与经验

- 导航里已有一个名字不等于用户已经拥有入口。底层功能齐全但缺少信息架构连接时，用户仍会认为 AI 和计划不存在。
- 周总结最危险的误导不是计算错误，而是把“有记录”写成“达标”、把相似训练写成“已完成”。展示模型必须继续依赖明确事实和显式关联。
- 新路由在 Taro 中有固定运行时成本。总包体门禁让首版在提交前暴露该成本；同路由标签既更小，也使读取权限更一致。
- 总量预算不是永远不能变化，但只能随已测量的真实功能小幅调整。入口、最大异步块、vendor 和单页峰值未增长，是本次接受总量增量的关键条件。
- 视觉自动检查需要同时看手机和桌面；单看 320 px 无法发现固定桌面导航与页面顶栏的重叠。

## 6. 全局状态、剩余风险与下一步

首页五个主要导航现在都有真实去向；“教练”可在本地展示可信空状态、记录摘要和计划/AI 权限边界。计划存在与显式关联的完整展示由纯模型测试覆盖，真实计划生成、模型调用、微信/OIDC 和共享环境仍沿用既有门禁，本轮没有扩大其证明范围。

下一轮继续审计不依赖外部输入的用户闭环，优先候选是把“我的”从隐私页直达改为资料、目标与数据控制的统一入口，或先建立剩余中文专题/历史档案索引。托管共享环境部署顺延至第 097 轮，等待云账号、域名、凭据、责任人和政策材料；原生设备同步顺延至第 098 轮。
