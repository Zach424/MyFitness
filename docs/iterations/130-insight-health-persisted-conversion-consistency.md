# 第 130 轮：健康洞察持久化换算一致性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 D（Data Quality）与 F（Consistency Checking）。范围只有健康点展示值/单位与规范值/单位的确定性换算关系，以及该关系依赖的持久化精度防漂移。

验收标准固定为：单位换算因子和 `NUMERIC(14,4)` 精度必须只有一份 contracts/domain 共用权威；领域写入复用该换算且既有范围、整数与四位规范值行为不变；生产构造器必须在排序、未来过滤和 180 点截断前拒绝任一换算错配，覆盖未来点与隐藏第 181 点；公开响应 Schema 必须逐点独立拒绝同类错配并报告精确路径；主表和修订表的两组值列必须由测试锁定为相同四位精度。不得用百分比容差、自动修复历史值、重新执行健康范围，或修改 SQL、响应形状、分页、客户端、持久化、计划、AI 与医疗解释。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/health-record.constants.ts`：新增九单位规范换算表、四位持久化精度、按单位推导的舍入容差及纯一致性判断。
- `packages/contracts/src/health-record.test.ts`：验证每个指标允许单位都映射到正确规范单位，并覆盖磅、小时、错误规范单位和容差外错配。
- `packages/domain/src/measurements.ts`：移除私有重复换算分支，归一化改用共享换算函数；范围、整数和四位舍入仍留在领域层。
- `apps/api/src/insights/insights.service.ts`：在单位关系之后、排序与未来过滤之前扫描全部来源点的持久化换算一致性。
- `apps/api/src/insights/insights.service.test.ts`：把合法磅夹具校准到四位持久化值，并证明未来错配与隐藏第 181 点错配均失败关闭。
- `packages/contracts/src/insights.ts` 与测试：公开响应在单位身份有效时逐点验证换算，并把错误定位到 `series[0].canonicalValue`。
- `apps/api/src/database/schema-drift.test.ts`：锁定主表和修订表的 `canonical_value/display_value` 都使用共享四位精度。

## 3. 实现方法

### 最小跨层换算权威

每个 `UnitCode` 只声明规范单位与线性因子。领域仍先按精确指标检查允许单位，再调用纯换算并执行既有四位舍入、范围与整数规则；传输层不获得产品范围阈值。

### 从持久化精度推导容差

令 `q = 10^-4`。规范列最多贡献 `q / 2` 舍入误差；非规范展示列最多贡献 `abs(factor) * q / 2`。同单位两列来自同一原值，因此不重复计算展示误差。最终仅追加与数值规模成比例的 IEEE-754 运算余量。由此 `lb → kg`、`in → cm` 与 `hour → minute` 得到不同但可解释的上界，不使用宽泛百分比。

### 来源与响应双层失败关闭

API 在全部原始行仍可见时检查换算，避免未来过滤或 180 点截断隐藏错误。公开 Schema 在指标—单位关系成立后再次检查，防止无效单位同时产生无意义的级联换算问题。两层都只拒绝，不覆盖、删除或修正原展示值。

### 持久化精度防漂移

代码常量本身不能证明数据库结构。现有迁移漂移测试读取主表和修订表迁移，要求两组值列都出现 `NUMERIC(14,4)`；未来若更改精度，迁移和容差必须在同一受测变更中更新。

## 5. 发现的问题与经验

- 单位身份正确仍不足以证明两个值属于同一测量；关系约束必须同时覆盖单位和数值。
- 持久化展示值已经舍入，不能简单重新换算后要求逐位相等；小时换算会把半个展示量化单位放大 60 倍。
- 可解释容差应由存储精度与确定性因子推导，不应使用固定百分比或经验常数。
- 跨层常量需要数据库迁移测试支撑；代码中的 `4` 不能单独证明两张表仍为四位小数。
- 失败关闭与自动修复是不同产品行为；只读洞察应拒绝矛盾证据，不应重写用户历史。

## 6. 全局状态、项目反思与下一步

本轮关闭了合法单位携带明显错误配对数值进入健康洞察的路径，并保持写入归一化行为不变。它没有判断值是否健康、正确或来自准确设备。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处同类缺口位于来源行自身的指标身份。真实 SQL 按路径指标过滤，但纯构造器的 `HealthPointRow` 不携带 `metric`；同为 `score_1_5` 的精力、压力和酸痛记录可能被替代适配器混入而保持单位与换算全部合法。下一轮第 131 轮必须重新排序，当前最小候选是让来源查询与纯构造器显式携带并核对精确指标，再评估公开点是否需要重复指标供 Schema 独立验证；不得从单位或数值反推指标。

本轮未新增或关闭风险：换算门禁不证明来源指标身份、记录真实性、设备准确、健康范围、趋势意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
