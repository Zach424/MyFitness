# 第 127 轮：动作洞察来源快照有效性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 D（Data Quality）与 F（Consistency Checking）。范围只有动作洞察原始点的身份快照运行时有效性。

验收标准固定为：生产构造器必须复用共享动作身份 Schema，在未来过滤、排序和 180 点截断前拒绝任一空白/超长名称、未知类别/追踪/器械、重复器械及 `other` 缺备注；检查覆盖完整来源数组，包括未来点与隐藏第 181 点。公开 Schema 必须独立执行相同器械关系。合法历史快照不得被修整、回查或替换；旧记录的可空追踪模式与空器械仍兼容。不得修改 SQL、响应形状、分页、客户端、目录、持久化、计划、AI 或健康结论。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/insights.ts`：为公开动作身份 Schema 增加器械唯一性和 `other`/备注关系门禁，保留既有文本、枚举和长度语义。
- `packages/contracts/src/insights.test.ts`：证明顶层身份与首点同时携带重复器械或 `other` 缺备注时，公开契约按精确字段路径失败。
- `apps/api/src/insights/insights.service.ts`：抽取唯一的来源身份映射，并让纯构造器用共享 Schema 扫描全部原始动作点后再处理 UUID、顺序、未来与截断。
- `apps/api/src/insights/insights.service.test.ts`：在隐藏第 181 点逐项注入空白/超长名称、未知类别/追踪/器械、重复器械和缺备注的 `other`。
- ADR-0121、架构、已实现 PRD、接口参考、路线图、风险登记册、项目状态和本档案：同步快照边界、兼容性、限制、经验与第 128 轮候选。

本轮没有改变合法响应或错误 HTTP 映射；公开形状不变。

## 3. 实现方法

### 复用一份共享身份语义

构造器不复制枚举或长度常量，而是把蛇形来源字段映射为既有公开身份对象，再调用 `exerciseInsightIdentitySchema.safeParse`。同一对象映射随后用于公开点，减少校验对象与返回对象漂移。

### 完整来源扫描

身份校验直接遍历构造器收到的原始数组，发生在未来过滤和 180 点公开截断之前。因此未来点在参考时刻前移后、或隐藏第 181 点进入公开前缀时，不会突然暴露无效身份。

### 验证而不改写历史

共享 Schema 的解析结果只用于判断成功或失败，构造器继续返回原始历史快照，不用解析结果修整名称或备注。它不查询当前目录，也不为旧记录补追踪模式或器械。

### 保留旧记录兼容边界

旧训练可能没有显式追踪模式或器械；公开身份继续允许 `trackingMode: null` 与空器械数组。只有现有共享语义明确无效的表示和关系失败。

## 5. 发现的问题与经验

- 公开 Schema 看不到被未来过滤或截断的来源行，不能替代构造边界的完整扫描。
- 共享 Schema 只有被生产构造器直接复用时，才真正消除静态类型与运行时来源之间的语义副本。
- 校验使用解析结果不等于应该用它改写历史；本轮刻意把“可接受”与“标准化后存储”分开。
- 可空追踪模式与空器械是已登记的旧记录兼容边界，不能因新目录规则而追溯拒绝。
- 快照格式正确不代表动作安全、定义准确或趋势可用于进阶处方。

## 6. 全局状态、项目反思与下一步

本轮关闭了无效动作身份快照在纯构造阶段参与排序、未来过滤与截断的路径，并让公开契约独立执行相同器械关系。它没有查询或重写动作目录，也没有扩大训练建议边界。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处同类缺口位于健康点来源凭据。规范/展示单位、来源类型与元数据、记录时区仍主要由静态类型和公开 Schema 保护；替代适配器可在纯构造阶段返回未知或越界值。下一轮第 128 轮必须重新排序，当前最小候选是复用健康记录契约扫描完整来源点，同时保持记录时区与响应时区语义分离，不引入医疗范围判断。

本轮未新增或关闭风险：快照门禁不证明记录真实性、动作适用性、定义安全性、来源可信度、趋势意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
