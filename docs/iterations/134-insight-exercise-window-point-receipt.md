# 第 134 轮：动作 90 日窗口与点截断收据

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只有动作 90 日完整课次计数、最多 181 行来源训练点、180 点公开前缀和 `hasMore` 的收据关系。

验收标准固定为：先证明窗口与点 SQL 使用同一训练资格并采用同一课次基数；`sessionCount <= 180` 时来源行数必须精确相等，`sessionCount > 180` 时来源必须恰有 181 行；公开响应必须满足 `series.length = min(sessionCount,180)` 与 `hasMore = (sessionCount > 180)`；缺失 90 日来源行只有在零合格点时可继续回退为空；真实 PostgreSQL 响应必须证明窗口课次等于未截断点数。不得把完成组数当课次数，不得从有限前缀臆测更多训练或重算聚合，也不得修改 SQL、响应形状、分页、客户端、历史记录、计划和 AI。

## 3. 实现方法

### 先证明同一训练资格与基数

窗口与点 SQL 都限定同一用户、精确动作键、未删除训练、参考时刻上界和 90 日下界。窗口只在存在已完成组时按训练 ID 去重计数；点查询按训练 ID 分组并以已完成组大于零为 `HAVING` 条件。一个训练因此在两侧都只贡献一个课次，不受组数影响。

### 来源层精确收据

来源点先完成时刻、数值、快照、UUID、顺序、唯一性和未来过滤。随后 181 行上界先阻止过取，再根据 90 日 `sessionCount` 计算期望行数：不超过 180 取全部，超过 180 必须取到第 181 条收据。缺失 90 日窗口视为零，因此只有零点可通过。

### 响应层可观察关系

公开 Schema 已能看到完整 `sessionCount`、最多 180 点和 `hasMore`，因此点数必须等于课次计数与 180 的较小者，更多标志必须精确等于课次是否超过 180。错误分别落在窗口课次和标志路径，替代生产者不能绕过来源层语义。

### 不从有限前缀重算聚合

超过 180 个训练时，公开点只是最近前缀，不能重算完整窗口的完成组、次数、负荷、活动时间或距离。本轮只核对课次基数，不改变数据库聚合权威。

## 5. 发现的问题与经验

- 建立计数收据前必须先证明两条查询使用同一资格集合和同一基数；字段名称相似不足以支持比较。
- `sessionCount` 是训练课次数，不是完成组数；稳定训练 ID 是窗口与点之间的对账身份。
- 181 行不是任意上限，而是 180 点公开边界的一条可验证更多收据。
- 稀疏回退不能无条件生成空窗口；一旦同资格训练点存在，缺失 90 日窗口就是证据矛盾。
- 合法空响应和合法截断响应也必须更新为关系完整的测试夹具，否则旧夹具会掩盖契约缺失。

## 6. 全局状态、项目反思与下一步

本轮关闭了动作 90 日课次宣称、点查询收据、公开前缀和更多标志彼此矛盾的路径。它没有验证三个嵌套动作窗口之间的聚合关系。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，动作窗口的课次、完成组、次数、负荷、活动时间和距离都来自同一非负已完成组资格，较长窗口不应小于较短窗口。下一轮第 135 轮必须重新排序；当前最小候选是在保留稀疏来源回退的前提下，让来源和公开响应分别验证 7→30→90 日这些字段非递减。实施前仍需逐字段复核 SQL 的非负和同资格前提；不得从有限点前缀重算聚合、补造活动或解释训练效果。

本轮未新增或关闭风险：动作课次收据一致不证明跨窗口聚合单调、训练记录真实性、动作执行安全、趋势意义、训练效果或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
