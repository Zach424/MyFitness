# 第 123 轮：洞察来源窗口身份集合

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 C（Evidence Modeling）与 F（Consistency Checking）。范围只有动作/健康洞察纯构造器接收的窗口聚合行身份。

验收标准固定为：两个生产构造器都只接受 `days` 为 7、30、90 且各自唯一的已提供窗口行；重复和未知身份必须在窗口选择及点序列派生前失败。来源数组可以稀疏和乱序，缺失身份仍回退为空窗口，公开输出继续固定为 7/30/90。参考时间和时区的既有错误优先级不得回退。不得修改 SQL、公开 Schema、窗口数值、分页、客户端、持久化、计划算法、AI 或健康结论。

## 2. 项目结构、设计、技术与实现功能

- `apps/api/src/insights/insights.service.ts`：增加两个构造器共用的窗口身份集合扫描，并在点序列校验前调用。
- `apps/api/src/insights/insights.service.test.ts`：既有动作投影用例覆盖乱序/稀疏输入、重复身份和未知身份；健康投影用例独立覆盖重复与未知身份。
- `packages/contracts/src/insights.ts`：不修改；公开 Schema 已验证最终 7/30/90 窗口，本轮保护的是构造前来源集合。
- `docs/product/IMPLEMENTED_PRD.md` 与 `docs/api/API_REFERENCE.md`：补充来源窗口身份、稀疏回退和输入顺序契约。
- ADR-0117、架构、路线图、风险登记册、项目状态和本档案：同步门禁顺序、限制、无新增/关闭风险及第 124 轮候选。

本轮没有改变正常响应或错误 HTTP 映射；正常 PostgreSQL 三行聚合保持兼容。

## 3. 实现方法

### 小型来源集合门禁

共用校验器用允许集合 `{7, 30, 90}` 和一个请求内 `Set<number>` 一次扫描窗口行。任一未知值或第二次出现的身份立即失败；集合最多三项，不引入请求外状态。

### 稀疏与乱序是有意兼容

公开窗口仍遍历固定 `[7, 30, 90]` 并按身份查找来源。未提供身份沿用既有零计数/空统计语义，来源数组顺序不参与语义。测试以 90 日行先于 7 日行证明输出仍固定有序，并保留缺失 30 日空窗口。

### 分层门禁与错误优先级

参考 `Date` 和响应时区保持最高优先级，以延续第 122 轮的可区分配置错误；来源窗口身份随后检查，再验证点时刻、顺序、UUID、截断和摘要。共享 Schema 继续保护已经生成的公开表示。

### 不推断缺失聚合

缺失窗口行只有“适配器未提供该聚合”的证据，构造器没有逐点数据可重算窗口，因此继续生成显式空窗口。本轮不把缺失升级为错误，也不从其他窗口推断数值。

## 5. 发现的问题与经验

- 固定公开 Schema 不能证明来源集合无重复或未知行；未被选择的行必须在构造边界显式审计。
- `.find` 在唯一性未经证明时会把数组顺序变成隐藏业务规则，适合取值但不适合承担一致性校验。
- 缺失、重复和未知是三种不同语义：本产品有意允许缺失回退，但对冲突和错配失败关闭。
- 共用结构门禁能让动作与健康适配器保持同一错误语义，避免两个相似投影逐渐分叉。
- 窗口身份正确不等于数值正确；字符串数值的有限性、整数性和非负语义仍需单独验证。

## 6. 全局状态、项目反思与下一步

本轮关闭了重复来源窗口由数组顺序决定结果、未知来源窗口静默消失的路径，同时保留了既有稀疏适配器和空窗口语义。它没有重算、纠正或解释任何健康/训练数值。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处候选缺口位于原始数值。窗口和点的 PostgreSQL 数值字符串会直接经过 `Number(...)`；非有限值可在 JSON 中退化为 `null`，非整数计数或负值也可能穿透。下一轮第 124 轮必须先盘点字段语义并重新排序；当前最小候选是拒绝非有限、非整数计数和明确不可能的负值，同时保留可空统计和测量精度，不扩展为医疗正常范围判断。

本轮未新增或关闭风险：来源身份门禁不证明查询完整、聚合数值有效、统计意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
