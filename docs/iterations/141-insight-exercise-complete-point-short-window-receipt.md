# 第 141 轮：动作完整点集与短窗口子集收据

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只包含未截断动作 90 日点集与 7 日、30 日短窗口之间的子集聚合收据，以及证明该规则所需的闭区间、空集、零测量、舍入和真实数据库测试。

验收标准固定为：90 日 `sessionCount <= 180` 且点集完整时，来源与响应必须按 `startedAt >= generatedAt - days×24h` 闭区间筛出 7/30 日子集；每个短窗口的课次、完成组、次数、负荷、活动时间与距离必须与子集一致。课次和整数聚合精确比较，来源十进制测量只容纳有界 IEEE 误差，公开测量只容纳按子集点数和显示精度推导的舍入上界。恰好下界包含，下界前 1 ms 排除；空短窗口全零，有完成组但零测量仍合法；`sessionCount > 180` 时全部跳过。不得从截断前缀推断、使用固定宽松容差、自动改值、评价动作质量或训练效果，也不得修改 SQL、响应形状、客户端、历史记录、计划或 AI。

## 3. 实现方法

### 先证明完整，再重建短窗口

既有 90 日点数收据先证明 `sessionCount <= 180` 时一课次一条点且没有遗漏，既有聚合收据再证明 90 日总计。新收据随后用同一参考时刻从完整集合构造 7/30 日子集；超过 180 课次立即退出，不让最新前缀冒充完整证据。动作与健康共用一个只按绝对时刻筛选的内部函数，避免两类洞察逐渐采用不同边界。

### 闭区间与未来点门禁分工

短窗口下界使用 `referenceTime - days×86_400_000`，比较符为 `>=`。恰好 7/30 日前的训练进入对应窗口，早 1 ms 则退出；点的上界继续由构造器未来过滤和公开 Schema 的 `occurredAt <= generatedAt` 门禁负责。响应时区不参与动作课次是否属于绝对窗口。

### 整数精确、来源测量有界

课次直接比较子集长度；完成组和次数以 `BigInt` 求和，避免安全整数边界内仍因错误浮点路径丢失离散语义。来源负荷、秒数和米数来自 PostgreSQL 十进制文本，复用 90 日收据的 `Number.EPSILON`、值幅度和子集点数上界，不接受显示舍入容差。

### 响应容差绑定子集规模

公开点和窗口分别舍入。负荷、分钟、公里的末位单位为 0.01、0.1、0.01，每个短窗口只允许 `(子集点数+1)×半个末位单位`，再叠加有界浮点求和误差。7 日两点不能借用 90 日五点的更宽上界；空子集仍通过既有关系门禁保持全零。

### 真实夹具而非局部规则样例

初次定向运行发现既有“合法量化差异”夹具把两点放在相同近期时刻，却只更新 90 日窗口；旧聚合收据看不到短窗口矛盾。实现保持失败关闭，夹具改为一条近期点和一条 30 日外但 90 日内的点，并分别给出可由短窗口与长窗口解释的舍入值。修正后同一测试仍证明量化差异合法，同时不再依赖矛盾证据。

### 精确诊断而不修复

来源分别报告短窗口课次或聚合冲突；共享 Schema 定位具体短窗口的 `sessionCount`、整数聚合或测量字段。系统不重写窗口或点、不放宽精度、不补造活动，也不把一致性解释为训练质量。

## 5. 发现的问题与经验

- 嵌套窗口非递减只是必要条件；每个短窗口仍需绑定其真实时间子集。
- 测试夹具也是证据模型，不能用时间上互相矛盾的窗口证明某个局部舍入规则。
- 离散计数与连续测量必须分开处理：前者精确，后者容差由表示路径、精度和点数推导。
- 逐点公开舍入误差应按实际短窗口子集大小计算，不能复用长窗口的更宽误差预算。
- 零测量不等于零证据；有已完成组的训练可以合法记录零次数、负荷、时间或距离。
- 截断限制了能够声称的知识范围，即使公开前缀在时间上看似足够新，也不能假设隐藏点不在短窗口。
- 当前 UTC 数据库会话让日间隔等于绝对 24 小时；这不能替代非 UTC、跨夏令时会话的明确 SQL 语义证明。

## 6. 全局状态、项目反思与下一步

本轮关闭了动作 7/30 日窗口可能与完整 90 日训练点集矛盾的缺口。动作洞察现在从课次资格、完整性、90 日聚合到短窗口子集形成来源/响应双层收据；这些收据只说明记录内部一致，不证明动作执行正确、负荷适宜、设备准确或训练有效。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，第 142 轮应重新排序；当前最小关键候选是洞察 SQL 绝对窗口跨会话时区稳定性。动作/健康收据都按固定 24 小时重建子集，但 PostgreSQL `make_interval(days => ...)` 与 `INTERVAL '90 days'` 在非 UTC、跨夏令时会话中可能表现为日历日。下一轮应先用独立 PostgreSQL 会话复现或排除差异，再把动作/健康窗口与点查询统一为显式小时区间，并覆盖春季跳时、秋季回拨和 7/30/90 日精确边界。

本轮未新增或关闭产品风险：短窗口收据仍不证明非 UTC 生产会话的时间语义、训练记录真实性、动作安全、趋势意义、效果或用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
