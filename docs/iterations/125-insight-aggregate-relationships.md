# 第 125 轮：洞察聚合关系一致性

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 C（Evidence Modeling）与 F（Consistency Checking）。范围只有动作窗口/点与健康窗口的同一行聚合字段关系。

验收标准固定为：来源和公开 Schema 都必须拒绝动作窗口课次多于完成组、动作点没有完成组或完成组多于总组；健康窗口必须满足记录日不多于记录数，零记录只能有零日/空统计，有记录必须有记录日/完整统计，且统计满足最小值不大于平均值、平均值不大于最大值。来源检查必须在数值有效性之后、映射之前执行并覆盖隐藏第 181 点。不得验证跨窗口单调性、纠正数值、判断健康正常范围，或修改 SQL、精度、分页、客户端、持久化、计划、AI。

## 3. 实现方法

### 先证明单字段，再比较关系

来源关系检查器只在第 124 轮的十进制、安全整数和有限值门禁通过后调用，因此比较使用已证明可安全转换的值，不会让 `NaN` 或精度损失影响关系结论。

### 动作组数来自集合包含关系

窗口课次只统计至少有一条已完成组的训练，所以课次数不会超过完成组数。点查询的 `HAVING` 要求至少一个完成组，而完成组是所有组的子集，因此 `0 < completed <= total`。隐藏第 181 点同样扫描，不能因截断逃逸。

### 健康统计来自同一非空集合

每条健康记录都有发生时间和规范值。正记录集合至少产生一个记录日及完整 MIN/MAX/AVG；空集合只产生零计数和空统计。任意非空有限集合的平均值位于最小/最大值之间，该数学关系不依赖医学范围。

### 来源与公开契约双层防御

来源检查防止构造器映射错误聚合；共享 Schema 防止替代 API 或传输边界发布同类冲突。错误保持字段路径，不修正、重排或补齐数值。

## 5. 发现的问题与经验

- 单字段类型正确不代表聚合状态可能存在；集合包含关系需要显式建模。
- 关系门禁会发现测试数据的陈旧矛盾。应修正夹具，使其继续证明原意，而不是放宽生产规则。
- 来源校验和公开 Schema 解决不同信任边界；一个保护映射前集合，一个保护传输后的表示。
- `MIN <= AVG <= MAX` 是有限非空集合的数学性质，不是健康正常范围或趋势判断。
- 隐藏截断行仍属于来源收据，关系错误不能因为不公开而被忽略。
- 跨窗口关系与稀疏回退存在设计张力，必须另行决策，不能顺手加入本轮。

## 6. 全局状态、项目反思与下一步

本轮关闭了单字段合法但聚合组合不可能的发布路径，同时使纯构造器与共享契约保持同一关系语义。它没有推断跨窗口变化、纠正数据或增加健康结论。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，下一处候选缺口位于来源非数值字段。UUID、动作快照文本/枚举、健康单位、来源类型/元数据和记录时区主要由静态类型与公开 Schema 保护；替代适配器运行时仍可能越界。下一轮第 126 轮必须先盘点可复用共享 Schema 与来源字段并重新排序，优先建立最小运行时门禁，不重复目录业务规则。跨窗口单调性因稀疏回退决策存在张力，继续单独保留。

本轮未新增或关闭风险：同一行关系门禁不证明跨窗口完整性、记录真实性、健康正常范围、趋势意义或真实用户理解。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
