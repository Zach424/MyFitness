# 第 140 轮：健康完整点集与短窗口子集收据

日期：2026-08-11

状态：已完成

## 1. 范围、分类与验收标准

本轮分类为 F（Consistency Checking）。范围只包含未截断健康 90 日点集与 7 日、30 日短窗口之间的子集收据，以及证明该规则所需的边界、空集和真实数据库测试。

验收标准固定为：90 日 `recordCount <= 180` 且点集完整时，来源与响应都必须按和 PostgreSQL 一致的 `at - days` 绝对时刻闭区间筛出 7/30 日子集；每个短窗口的 `recordCount`、响应时区去重 `recordedDays`、minimum、maximum 和 average 必须与子集一致。恰好位于下界的点必须包含，下界前 1 ms 必须排除；空短窗口保持零计数和 `null` 统计；`recordCount > 180` 时全部跳过。不得从截断前缀推断、自动改值、增加跨窗口 average 单调性、趋势或医疗规则，也不得修改 SQL、响应形状、客户端、历史记录、计划或 AI。

## 3. 实现方法

### 由完整集合证明短窗口

既有收据先证明 `recordCount <= 180` 时 90 日来源行与公开点没有遗漏。新收据随后用相同参考时刻从该完整集合构造短窗口；超过 180 条立即退出，不让最新前缀冒充完整证据。每个请求最多处理 180 点，7 日和 30 日各执行一次线性筛选。

### 绝对时刻闭区间与日期投影分工

SQL 的资格边界是 `occurred_at >= at - days`。TypeScript 用 `at.getTime() - days * 86_400_000` 重建相同绝对下界，并依赖既有未来点收据保证上界。响应时区只用于 `recordedDays` 的本地自然日投影，不参与点是否落入时间窗口的判断。

本地 PostgreSQL 会话实测 `TimeZone = UTC`。以纽约 2026 年夏令时回拨附近的参考时刻审计时，数据库 `timestamptz - 7 days` 与 JavaScript 毫秒边界得到相同 UTC 时刻；若未来部署改变该语义，来源收据会失败关闭。

### 整数精确、统计有界

点数和本地日去重数量是离散事实，必须精确比较。来源规范值可能经历 PostgreSQL 十进制字符串到 JavaScript `Number` 的转换，继续沿用按数值幅度、绝对值和点数计算的有界 IEEE 误差；公开统计保留四位小数，额外只允许 0.00005 半单位。该容差不允许把不同点集解释成相同统计。

### 空集和截断边界保持诚实

只有较早的 90 日点、但 7/30 日没有点时，子集收据要求短窗口为零计数、零记录日、三个 `null` 统计。90 日窗口超过 180 条时，即使公开 180 点都很新，也不能证明短窗口完整，因此来源与响应全部跳过子集聚合对账。

### 平均值不跨窗口单调

旧测试曾用相同时间集合承载不同 7/30/90 日 average，只为证明 average 无需单调；完整点收据加入后该夹具不再是真实证据。本轮把三组点放入真正不同的时间子集：7 日平均 70、30 日平均 65、90 日平均 70。结果仍证明 average 可升可降，同时每个窗口都能由自己的点集复算。

### 精确诊断而不修复

来源对计数、记录日和统计分别使用领域错误，响应 Schema 定位具体短窗口的 `recordCount`、`recordedDays` 或统计字段。两层都不重写窗口或点，不补造证据，也不解释数值是否健康。

## 5. 发现的问题与经验

- 跨窗口单调性只能约束方向，不能证明短窗口来自正确的时间子集。
- average 天生不要求跨窗口单调；真实测试数据必须同时满足各窗口证据，而不能用彼此矛盾的夹具证明一个局部规则。
- 时间窗口资格使用绝对时刻，记录日使用响应时区的自然日；把两种语义混在一起会在夏令时附近制造错误。
- 闭区间边界必须同时测试恰好命中与前 1 ms，才能防止比较符号或参考时刻偏移。
- 完整长窗口可以复用为短窗口证据，避免额外查询和快照分裂，但前提必须由独立点数收据证明。
- 截断是认识边界，不是性能细节；无法看到完整集合时必须明确放弃聚合结论。

## 6. 全局状态、项目反思与下一步

本轮关闭了健康 7/30 日窗口可能与完整 90 日点集矛盾的缺口。健康洞察现在从点资格、完整性、统计、记录日到短窗口子集形成来源/响应双层收据；这些收据只说明记录一致，不证明来源真实、设备准确、趋势意义或医疗结论。

按 Personal Cognitive Mirror 的 Inspect → Rank → Improve → Validate 反思，第 141 轮应重新排序；当前最小关键候选是动作完整 90 日点集与短窗口子集收据。需要先核对训练窗口与点查询按 `started_at` 使用的资格和闭区间，再由未截断点集筛出 7/30 日子集，核对课次、完成组、次数、负荷、活动时间和距离。必须区分整数精确聚合与逐点公开舍入的测量上界，并覆盖边界时刻、空短窗口、零测量训练和 90 日截断跳过。

本轮未新增或关闭产品风险：短窗口收据仍不证明目标平台时区数据、来源真实性、设备准确性、用户理解、因果趋势或医疗意义。风险登记册全表时效复核、真实身份/设备/保留/备份与 AI 专家语料仍保持开放。
