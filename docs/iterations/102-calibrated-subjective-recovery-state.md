# 第 102 轮：校准主观恢复状态

日期：2026-08-10

状态：已完成

## 1. 范围与验收标准

本轮只修复主观恢复证据被过早提升成确定状态并直接影响计划的问题，不接入设备、云服务、真实 AI 或医学模型。验收要求是：单次自评保持 Unknown；状态估计公开时间窗、个人基线、逐条来源、覆盖、方向一致性、置信度和限制；只有满足纵向覆盖且方向一致的中等置信估计可影响计划；今日页能解释差异；契约、领域、API、计划、双端客户端、项目状态、Obsidian 和 Git 归档都有可复现证据。

## 2. 项目结构、设计、技术与实现功能

- `packages/contracts/src/recovery-state.constants.ts` 与 `recovery-state.ts`：新增版本化状态、置信度、方向一致性、7/28 天覆盖、因素和逐条证据引用契约；用严格 Zod 交叉校验 Unknown、当前摘要与基线比较的不变量。
- `packages/domain/src/recovery-state.ts`：实现按本地日期/指标去重、1–5 方向规范化、近期/基线分窗、覆盖门槛、个人基线差、方向冲突和计划影响投影。
- `apps/api/src/insights/insights.service.ts`：仪表板查询增加来源类型，把当前已确认恢复记录映射到状态估计器；不持久化重复汇总。
- `packages/domain/src/plan.ts` 与 `apps/api/src/plans/plans.service.ts`：生成、新鲜度、决策和关联都只消费通过中等置信且方向一致门槛的计划分数。
- `apps/client/src/pages/index/index.tsx`：今日页显示 Unknown 覆盖、低/中置信、个人基线变化或方向冲突，并明确用户陈述不等于已确认状态。
- `packages/contracts/src/recovery-state.test.ts`、`packages/domain/src/recovery-state.test.ts`、API/计划单元与集成测试、`tests/e2e/today.spec.ts` 和 `plans.spec.ts`：锁定稀疏证据、纵向证据与真实界面行为。
- `docs/architecture/decisions/0097-calibrated-subjective-recovery-state.md`、健康记录模型、架构基线、路线图、风险登记册与本档案：记录模型、限制、R-030 和下一轮结果回看方向。

## 3. 实现方法

### 先保留证据，再估计状态

领域输入不是匿名数字数组，而是带记录 UUID、修订、指标、发生时间和来源的观察。输出再次保留这些引用及其窗口和规范化值，使用户界面、计划与未来审计能回到具体证据。AI 候选、未来值、无效 1–5 值和同日重复不会进入估计。

### 用个人纵向基线替代人群评分

近期窗口取参考时刻之前 7 天，基线取更早的 28 天。精力和睡眠质量按高值正向规范化，压力和酸痛按高值反向规范化。比较只发生在近期和基线都存在的指标中，不定义人群正常范围，也不声称生理恢复、原因或诊断。

### 用 Unknown 和置信度限制结论

近期不足 2 天或 2 类指标时没有分数；达到最低覆盖但没有 7 个基线记录日和 2 类可比指标时只给低置信近期摘要。至少 3 个近期日、3 类可比指标、7 个基线日且指标方向一致，才达到中等置信。因素跨度达到 50 分即标记冲突并降为低置信。

### 把计划影响设为更窄的投影

状态估计可以帮助用户理解，但计划不直接消费所有状态。独立 `planningReadinessScore` 只为中等置信且方向一致的估计返回分数；Unknown、当前摘要、低置信和冲突全部返回空。因此单次陈述不会使计划过期，充分的纵向一致证据仍可通过既有指纹和新鲜度机制安全重排。

## 5. 发现的问题与经验

- “用户确认”只证明这条陈述由用户提交，不证明陈述描述的是稳定身体状态；确认状态和估计置信度必须是两条独立轴。
- 证据数量不能只按行数计算。同一天重复记录若都进入平均，会让频繁输入被误当成更强证据；按本地日和指标去重更接近纵向覆盖。
- 用户没有个人历史时，提供近期摘要比制造基线更诚实，但摘要不能因此获得提升计划强度的权限。
- 指标冲突本身是有用信息。把精力、睡眠、压力和酸痛强压成一个平均值会掩盖不一致；显式 `mixed` 能保留多种解释并阻止过度行动。
- 同一状态契约供界面理解，计划只消费更窄的安全投影，能避免展示能力自动扩大为执行权限。

## 6. 全局状态、剩余风险与下一步

项目现在拥有第一个带纵向个人基线和校准不确定性的跨记录状态估计。它仍然只建模主观恢复陈述，不包含睡眠设备、静息心率、训练负荷或医学数据，也没有证明窗口和阈值能预测训练结果。R-030 因此保持高等级；当前测试只证明实现一致、安全失败和界面可解释，不证明有效性、因果性或临床价值。

下一轮第 103 轮建立最小结果回看链，把生成时真正影响计划的状态证据、用户采用的计划调整和随后确认的训练/恢复记录连成可解释时间线。它先帮助用户回答“当时为什么这样安排，后来发生了什么”，不自动归因、不自动加量，也不把结果反馈写成新的身体事实。
